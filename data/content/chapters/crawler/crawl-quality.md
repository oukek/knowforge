## 从具体问题认识数据质量、样本回放与变版检测

采集成功不等于数据正确。HTTP 返回 200、解析器没有抛异常，仍可能提取到空标题、广告价格或登录提示。数据质量需要从字段完整性、类型范围、重复与分布变化等方面持续检查。

页面改版后选择器仍命中一个节点，但含义已经改变，这类静默错误比直接报错更难发现，因为流水线看起来全部成功。

## 样本回放与分布变化检测

建立允许保存的代表性原始样本，包含正常、缺字段、不同版式和异常页面。解析器修改后回放样本，比较结构化输出，能快速发现回归。样本需要版本与来源时间，不能永远只测试最早的一种页面。

线上质量指标包括必填字段覆盖率、解析失败率、重复率、值域和记录数量。突然从每页二十条变成一条，或价格全部为零，都值得检查。阈值应结合历史与业务，不宜把所有波动都当错误；节假日或来源真实变化也可能改变分布。

可疑批次进入隔离区，保留错误类别与有限样本，避免直接污染正式 API 和 RAG 索引。修复后通过回放重新处理，并记录修复版本。若只修改解析器但不修复已入库错误，下游仍会持续展示旧问题。

## 把机制放到一条完整路径中

```flow
采集质量闭环
样本基线｜保存允许的代表性页面与预期
解析回放｜比较新旧解析器输出
线上检测｜观察完整性范围与分布变化
隔离修复｜阻止污染并重处理受影响数据
```

## 配套代码：数据质量、样本回放与变版检测：最小可验证示例

下面代码在课内Python运行区执行；浏览器环境与本机CPython的网络、文件和原生扩展能力不同。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

records=[{'title':'A','price':10},{'title':'B','price':None},{'title':'C','price':None}]
valid=sum(r['price'] is not None for r in records)
show({'valid':valid,'total':len(records),'quarantine':valid/len(records)<0.8})
```

阈值 0.8 是教学设定，并非所有业务通用。统计保留了全部三条作为分母，避免先丢失败记录再计算。真实门禁应结合历史基线、关键字段和影响程度，并能从异常批次追溯到响应样本。

## 从示例走向实际使用

给每个关键字段至少准备一个失败样本，并验证失败能被观察，而不是被默认值掩盖。将质量检查放在发布到下游之前，形成真正的门槛。

课内 0.8 阈值只是演示，不是普适标准。实际阈值应由字段重要性、历史分布与人工检查成本决定。
