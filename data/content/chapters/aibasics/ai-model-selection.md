## 从具体问题认识模型与部署选型

选择模型要从任务要求出发，而不是先挑品牌。信息抽取、代码生成、长文阅读和图像理解对能力的要求不同；同一个模型在某个公开榜单领先，也未必在你的输入格式、语言和延迟预算下最合适。

部署方式也属于选择：托管 API 减少模型运维，自部署增加硬件、容量、升级与安全责任。两者应按完整成本比较。

## 硬约束、质量与运行代价

先筛硬约束，包括数据能否出域、输入模态、上下文、工具协议、结构化输出和许可。无法满足硬约束的模型，即使平均分高也不适用。随后用相同任务集比较正确性、失败类型、首响应与总延迟，以及实际使用量成本。

API 兼容不代表能力等价。相同 messages 字段可能有不同角色支持、工具语义、流事件、缓存计费与错误格式。切换提供商需要适配层与契约测试，不能只换 base URL 就假定所有功能保持不变。

自部署成本包括权重、KV 缓存、并发调度、空闲容量和人员维护；托管成本包括调用、重试、限额与外部依赖风险。评估应包含高峰与故障情形，不只比较一次短请求的单价。质量差导致反复重试，也会改变实际单位任务成本。

## 从任务约束开始，而不是品牌开始

**选模型先写出具体任务和约束，再做可比实验。** 例如客服意图分类需要较短响应和稳定格式，而复杂合同分析可能更重视长文理解和证据核对；两者不一定选择同一个模型。

从真实样本构建测试集，固定输入、提示、模型版本和评判标准，比较任务成功率、常见错误、延迟和总体成本。公开榜单可以提供候选，但不能代替自己业务中对隐私、部署和错误代价的验证。

例如测试集应包含缺失字段、长输入和越权请求，不能只挑选模型最擅长的几个演示。

先定义输入模态、语言、长度、结构化输出、工具使用和错误代价，再列数据驻留、响应时间、并发和费用约束。某排行榜领先不能直接推断在自家工单抽取或代码检索任务最好。先有代表性样本与验收，才有可比选择。

不在课程中固定“当前最强型号”和价格，避免随版本失效。实际选型应核对具体模型卡、服务版本、许可和使用数据政策，并记录评估时点。

## 托管 API 与自部署的责任

托管服务减少权重部署与容量管理工作，但仍需考虑网络、限流、地域、版本和数据边界；自部署增加硬件、推理服务、扩缩容、更新和安全责任。开源权重不意味着零成本，也不意味着可忽略许可。

| 维度 | 托管服务要查 | 自部署要查 |
|---|---|---|
| 容量 | 配额、限流与排队 | 显存、批次与调度 |
| 质量 | 实际服务版本与配置 | 权重、模板及量化 |
| 数据 | 传输、保留和驻留 | 存储、网络与权限 |
| 运维 | 故障回退与依赖 | 升级、回滚与监控 |

本地浏览器运行课程 Python 不等于本地运行了大模型；Pyodide 是执行 Python 的环境，与模型权重推理是两类能力。

## 兼容接口不代表相同契约

某服务支持类似的路径和 JSON 字段，不保证消息角色、工具调用、schema、流式事件、拒绝和费用字段完全相同。用模型适配层将响应转为应用自己的联合类型，保留 request_id、模型版本和终态。

不要把失败统一兜成空字符串；区分传输失败、拒绝、不完整、格式不符与业务不满足。降级模型也要保持隐私和工具契约，不能为成功率展示而悄悄放宽安全。

## 切换与验收

先使用 fake 建立接口测试，再对真实候选做质量实验；托管模型版本更新时跑同一套回归。把模型、提示、索引、工具 schema 作为兼容组合管理，回滚也需要兼容持久状态。

保留明确未知项：没测过的语言、长输入或高并发不能宣称支持。选型结论应附条件，说明为何满足当前任务，而不是宣称一个模型适合一切。

## 把机制放到一条完整路径中

```flow
模型选择
明确硬约束｜数据模态协议许可与预算
统一任务集｜覆盖真实输入和失败切片
比较运行｜质量时延使用量与稳定性
受控上线｜版本记录灰度与回退验证
```

## 配套代码：模型与部署选型：API、本地推理和可比实验

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
const candidates = [
  { id: "cheap", schema: false, private: true, cost: 1 },
  { id: "fit", schema: true, private: true, cost: 3 },
  { id: "outside", schema: true, private: false, cost: 2 },
];
function select(rows) {
  return rows
    .filter((x) => x.schema && x.private)
    .sort((a, b) => a.cost - b.cost)
    .map((x) => x.id);
}
console.log(select(candidates));
console.log(candidates.length);
```

先满足本题结构和数据边界，再比较构造成本。代码没有调用模型，不能作为真实产品或价格推荐。

## 从示例走向实际使用

建立代表性任务集与必须通过的切片，先选最小可行方案，再评估复杂路由或多模型组合。保留版本与参数，升级时重跑同一评估。

课内先筛条件再比较代价，表达选择过程而非推荐某个固定型号。具体型号与价格会变化，应按实际账号与当前官方文档确认。
