## 从具体问题认识AI 中转高并发

AI 中转的高并发压力不仅是每秒多少 HTTP 请求，还包括同时占用多久连接、多少上下文 token、多少工具并发和多少待结算额度。一个生成三分钟的请求，与一个普通毫秒级查询占用资源的方式不同。

当入口速度超过处理能力，若无限排队，用户等待变长、超时重试增多，反过来继续放大负载。容量治理首先要让系统知道何时拒绝和何时等待。

## 有限资源与故障放大链

入口按用户、租户和服务商做公平准入，同时限制活动任务、队列长度与 token 预算。排队也计入总截止时间，已经等到无法完成的任务应尽早失败。只限并发不限制长输入，仍可能被少量超大任务占满资源。

背压让下游忙时上游减速；熔断避免持续调用明显异常依赖；重试处理可能恢复的短暂错误。三者目的不同。重试需要退避、抖动和次数预算，多个层级同时重试会乘法放大请求量，应统一负责边界。

并发槽位释放不等于计费预留已结算。任务可能结束但 usage 未知，账务要进入待核对状态；取消也可能无法立即停止上游计算。调度状态、供应商健康状态和额度账本分别维护并通过任务 ID 关联。

## 先列资源账而不是先加机器

AI 请求常持续数秒到数分钟，并发连接数约等于到达速率乘平均驻留时间。入口 QPS 相同，输出变长也会撑满并发；RPM、TPM、供应商并发、账号额度、出口连接池、文件描述符和本机内存是不同约束。均值不能替代 P95/P99，还要看请求排队与首 token 时间 TTFT。

## 入口公平与有限排队

认证后按租户、用户、任务设置并发与 token 预算，先估算并预占，超额明确拒绝。队列设长度与最长等待，按租户公平调度防止一个大客户吃满全局。多副本需要共享原子计数或可证明的租约，进程内计数只能约束单实例。取消请求要释放排队位、连接与预占资源，后台是否继续计算需有明确产品约定。

流输出需要背压与缓冲上限，慢客户端不能让所有输出永久驻留内存；心跳只说明链路活着，不说明模型有业务进展。反向代理超时、缓冲与压缩也会影响 SSE，必须串联观察客户端、代理和上游时间线。

## 重试、切换与熔断的区别

瞬时网络故障和临时限流可在统一 deadline 内指数退避并加抖动，遵守 Retry-After。余额不足、无效密钥、参数错误应隔离配置或告警，不能无限重试。熔断按端点/模型的失败窗口打开并半开探测；选择备用只在能力、权限与数据驻留满足要求时发生。

已经向用户输出 token，或工具副作用状态不明时，不应无缝换模型重放整次请求。否则会拼接两份答案、重复扣款或重复执行。可在首输出前有限切换；中途失败返回可诊断状态，恢复需要幂等任务协议。可用性是受约束的目标，不可能保证任何供应商全挂时仍正常服务。

## 账务和审计如何闭环

资源预占、实际消费、释放与账单对账使用 requestId/attemptId，区分一次业务任务和多次上游尝试。超时不等于供应商没有计费；记录未知结果而非自动全部退款。日志包含排队、连接、首字、总耗时、token、端点、错误类型，敏感正文按最小必要保留。

## 示例与容量实验

示例为纯本地容量判断器，演示并发已满和预占 token 超限两个独立拒绝原因。真实实现应原子化检查和更新，并对进程崩溃的租约设置恢复策略。压测使用假上游模拟长输出、慢消费者、429、断流与所有备用失效，验证队列上限和取消后资源回收。

## 把机制放到一条完整路径中

```flow
高并发准入
估算请求需求｜时间连接 token 与工具预算
公平排队｜有限队列和明确等待期限
有界执行｜背压重试熔断与健康路由
分别结算｜释放资源并核对任务账本
```

## 配套代码：AI 中转高并发：排队、背压、熔断与账务

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

使用本地 JavaScript 模型验证关键不变量；不调用真实数据库、模型或生产服务。实验简化之处与真实系统步骤见正文。

```javascript
function admit(state, task) {
  if (state.active >= state.maxActive) return 'concurrency_full';
  if (state.reserved + task.tokens > state.tokenBudget) return 'token_budget';
  state.active++; state.reserved += task.tokens;
  return 'accepted';
}
const state = {active:0,maxActive:1,reserved:0,tokenBudget:100};
console.log(admit(state,{tokens:80}));
console.log(admit(state,{tokens:1}));
state.active--;
console.log(admit(state,{tokens:30}));
```

本段程序用于把状态、条件和数据之间的关系写清；真实实现仍需上文介绍的资源、权限与失败协议。

## 从示例走向实际使用

做阶梯负载实验，记录排队时间、活动量、拒绝率、尾延迟和成功任务成本。明确系统在超载时怎样保持已有任务，而不是只追求峰值吞吐。

课内 active 与 reserved 分开，正是为了说明连接资源和 token 预算不能混用；示例手动释放槽位后预留仍然存在。
