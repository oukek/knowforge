## 从具体问题认识Worklet、SharedValue 与手势动画

拖拽卡片时，手指每移动一点，卡片都要更新位置。如果每一帧都把坐标交给业务逻辑、再通过数据更新送回视图，跨环境往返就可能成为延迟来源。Worklet 用于让合适的轻量交互计算在靠近渲染的执行环境中运行。

SharedValue 一类共享值机制承载动画所需的少量状态，例如当前横坐标。它不是把整个页面对象变成线程间可以任意读写的共享内存，也不是浏览器 Web Worker 的另一个名字。

## 高频动画状态与低频业务状态如何协作

一次拖拽通常有开始、移动、结束和取消。移动阶段需要及时把手势位移映射成视觉位置；结束阶段才需要确定最终业务值，例如卡片属于哪个列表。把这两类状态分开后，可以让移动过程主要更新动画值，松手时再把结果通知业务层。

Worklet 的执行环境有自己的可用 API 和闭包捕获规则。捕获一个大型业务对象可能增加传递成本，直接调用普通网络函数也未必被支持。设计时应把输入压缩成位置、速度、边界等必要数字，把计算限制为可预测的短任务；昂贵计算放到渲染附近，同样会阻塞渲染。

共享值只解决状态传递的一部分问题，不能自动决定谁拥有最终状态。业务端若在拖动中收到远端更新，需要约定是暂存、取消本次拖拽还是重新对齐。页面隐藏、组件销毁、手势取消时，也要清理绑定并阻止旧回调把已经失效的位置写回。

## 把机制放到一条完整路径中

```flow
拖拽状态分工
开始手势｜记录起始位置与边界
连续移动｜共享值驱动视觉位置
结束或取消｜确定有效的最终结果
业务提交｜低频保存并同步状态
```

## 配套代码：高频动画与低频业务提交分层

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

普通 JS 数值模拟 UI 连续坐标与业务最终状态，不是真实 Worklet 线程。

```javascript
let sharedX = 0;
const businessUpdates = [];
for (const x of [10, 20, 30, 40]) sharedX = x;
businessUpdates.push({finalX: sharedX});
console.log(sharedX);
console.log(businessUpdates.length);
console.log(businessUpdates[0]);
```

四次高频更新只向业务提交一次最终值，体现动画与业务的频率边界。真实 Worklet 有独立上下文和可调用 API 限制，不能直接搬运任意 JS 对象或函数。

## 从示例走向实际使用

先用普通页面实现正确的拖拽状态机，再把确实频繁且独立的坐标计算迁入受支持的 Worklet。以手指到画面的延迟、掉帧和取消恢复为验证目标，不能只看跨层消息数量变少。

示例中的 sharedX 是单线程教学变量，只展示“多次动画更新、一次业务提交”的组织方式。真实共享值与跨环境调用必须使用目标基础库提供的 API，不能直接复制普通变量写法作为平台实现。
