## LLM 的完整名称与基本任务
LLM 是 Large Language Model，大语言模型。它通常使用大量语言数据训练，学习在上下文条件下预测后续 token 的分布，并能通过适配完成问答、摘要、代码和信息抽取等任务。“大”没有适用于所有年代和架构的固定参数门槛，不能只凭某个 B 数断定质量。

对自回归生成，可将一段序列概率写为各位置条件概率的连乘。每生成一个 token 就把它接回上下文，再进行下一步。这里的概率描述模型对序列的偏好，不直接等于答案事实正确率或用户任务完成率。
## 从模型到聊天产品
基座模型主要学习一般语言和数据规律，指令适配让其更容易按任务要求回答；推理型能力可能通过不同训练和推理时策略形成。聊天产品还包含消息组织、工具、文件处理、搜索、风控和用户界面。产品能联网查天气，不意味着模型参数在每次聊天后自动更新天气。

| 名称 | 讨论对象 | 需要核实 |
|---|---|---|
| 基座模型 | 结构与参数 | 训练目标及使用许可 |
| 指令模型 | 对任务的适配行为 | 输入模板和评估表现 |
| 模型 API | 托管推理接口 | 版本、协议和限制 |
| 聊天应用 | 端到端产品 | 工具、权限和数据策略 |

同名系列的不同版本、量化和部署设置也会有差异，应记录实际版本，避免只说“用了某大模型”。
## 为什么能做很多任务，又为什么会错
文本、代码和任务示例共享许多可学习模式，较丰富的预训练加任务适配可支持广泛能力。但模型仍可能缺少知识、误用条件、对输入歧义作错误补全，或在检索证据错误时生成看似可信的解释。表达自然不是事实担保。

要处理实时或私有知识，通常通过上下文、检索或工具提供事实；精确金额由程序计算；高风险动作由规则和权限服务检查。不能把“提示模型不要编造”当成完整方案，也不能把所有错误简单归为随机采样。
## 可运行实验：序列概率不等于事实分数
实验给两条假想 token 路径，每一步概率固定，计算连乘和负对数和。长序列即使每步概率都较高，连乘也可能很小，因此不同长度序列不宜直接拿原始乘积当答案评分。对数表示更稳定，但仍只描述这个教学分布。

修改路径长度，观察乘积下降；再想象其中一个词把“可以”改成“不可以”，局部概率变化并不直接告诉你哪条业务政策正确。本例不训练模型，不声称模拟真实 LLM 的全部行为。
## 如何验证理解
用自己的话解释 token、参数、上下文与工具的区别：参数来自训练；上下文是本次推理提供的信息；工具由宿主执行；输出是候选内容或行动。随后给一个例子说明模型为何不能凭自身回答当前库存。

学习 LLM 不需要先记住所有模型品牌。先掌握生成机制、输入契约和失败边界，再用自己的任务集比较能力、费用和时延。研究某个具体模型时阅读其模型卡、许可及实际版本文档。
