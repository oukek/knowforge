## 智能体的核心不是角色名字
在 LLM 应用中，Agent 通常指利用模型根据目标和当前状态选择行动，调用工具获取观察，再继续决策直到满足停止条件的系统。简化循环是 state → decision → action → observation → state。并非每次都需要工具，也并非所有多轮聊天都构成有意义的业务 Agent。

模型提出行动，宿主程序验证并执行。模型不能直接获得数据库、文件和支付系统的任意权限。提示里写“你是经理”不代表拥有审批权，名字叫 Researcher 也不证明有独立研究能力。
## 与聊天、Copilot 和工作流怎么区分
普通聊天主要返回内容；Copilot 通常辅助用户并保留明确人为控制；固定工作流明确安排节点和路径；Agent 在允许范围内根据观察选择下一步。真实产品可以混合：外层固定认证和审批，中间研究节点动态选择工具。

| 系统 | 谁选择下一步 | 适用判断 |
|---|---|---|
| 单次生成 | 调用者固定 | 摘要、草稿、抽取 |
| 固定工作流 | 代码明确路由 | 步骤已知且强约束 |
| Agent | 模型加宿主策略 | 下一步依赖不确定信息 |
| 多 Agent | 多个受约束子任务 | 分工收益需测量 |

自主性越高，需要的预算、状态、观测与恢复设计通常越多，不是只加一个循环。
## Harness 为什么重要
Harness 可以理解为围绕模型的运行支撑：工具注册与执行、上下文装配、状态持久化、权限、预算、取消、日志和验收。框架可以提供部分能力，应用仍需定义业务契约。MCP 是连接协议的一部分，不等于完整 Harness。

每个行动有工具名、参数、调用 ID，结果有结构化值和明确错误。停止包括业务完成、需要用户输入、资源预算耗尽、失败和无进展；不能只依赖模型说“我完成了”。
## 可运行实验：两次行动后结束
实验用确定性策略替代模型：缺事实时调用 lookup，已有事实时生成 final。宿主检查已注册工具和最大步数，将工具观察写回状态。这个小循环不调用真实模型，但展示行动与执行分层。

把策略改成一直查询，最大轮数应终止；返回未知工具应拒绝；把工具结果改成错误，策略应明确恢复或停止。接 SDK 时保留相同不变量，而不把框架默认值当业务保证。
## 什么时候不该上 Agent
固定公式、权限校验、单步格式化或路径完全已知的流程，普通函数与工作流通常更易测试。先与单次模型加规则基线比较，只有动态决策带来可测收益才增加自由度。

学习验收是能画出目标、状态、策略、工具与停止条件，说明每一层失败如何处理，再给一个不能交给模型决定的权限例子。Agent 是完整系统问题，不能只回答某个 SDK 类名。
