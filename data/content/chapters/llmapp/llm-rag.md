## 从具体问题认识RAG 全链路、证据预算与无答案行为

完整 RAG 系统要回答三个连续问题：资料中有没有答案、检索有没有把必要证据找出来、模型有没有根据证据正确回答。任何一项失败，最终都可能看起来像“生成不准确”，但修复位置完全不同。

例如报销政策写明正式员工上限 500 元，检索只拿到金额却丢了身份条件，模型即使忠实复述也会给出不完整建议。

## 证据预算与无答案行为

在线流程先保留查询中的实体、时间与约束，再检索、过滤、重排并组装上下文。预算分配不仅看片段分数，还要保证回答所需条件共同出现。多跳问题可能需要多个来源，单个 top-1 片段不足以支持完整结论。

生成提示区分资料事实与用户假设，要求引用来自实际证据集合。后处理检查引用资格、主张支持和冲突。若资料不足，返回可回答部分与明确缺口；若工具失败，说明查询未完成，不能把失败当成资料不存在。

评估拆成检索与回答两部分。检索看必要证据是否进入候选和上下文，回答看正确性、完整性、引用与拒答行为。提高 top-k 可能增加噪音与成本，换大模型可能掩盖部分检索缺陷但不解决权限与过期数据。

## 检索与生成的错误不能合成一个分数

先定义目标文档是否进入候选集，再评价重排、上下文截断和生成是否忠于证据。召回不足、证据过期、权限过滤错误和模型幻觉需要不同修复。提高 top-k 可能引入噪声或挤掉关键上下文，不能作为默认万能优化；保留版本、来源 ID 与租户信息以追踪证据。

## 端到端验收与拒答

建立有答案、无答案、冲突证据、跨租户和恶意文档样本。检索评估看覆盖与排序，生成评估看事实支持和引用一致性，业务评估看任务完成与审核成本。没有足够证据时应明确缺口，不能用流畅语言填补。索引更新、删除和权限变化同样需要测试，向量相似度不是授权依据。

## 把机制放到一条完整路径中

```flow
RAG 质量链
确认语料｜答案是否存在且当前可访问
召回选择｜必要证据进入候选与上下文
生成回答｜保留条件并关联具体来源
验证缺口｜检查支持完整性与无答案行为
```

## 配套代码：RAG 全链路、证据预算与无答案行为：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

docs=[{'id':'a','text':'python crawler'},{'id':'b','text':'vue renderer'}]
query={'python'}
hits=[d for d in docs if query & set(d['text'].split())]
show([d['id'] for d in hits])
show('evidence available' if hits else 'insufficient evidence')
```

这是确定性的词项召回与证据存在性示例，没有调用生成模型，也不能证明候选足以回答具体问题。完整 RAG 应把命中、证据支持与最终回答正确性分开评估，失败时保留来源和版本。

## 从示例走向实际使用

为每个失败样本保存问题、标注证据、候选、最终上下文和答案，沿链路定位最早偏差。一次只调整一个主要环节，形成可解释对照。

课内词项匹配只是端到端教学基线，真实质量结论需要授权语料与代表性问题集。能返回文本不等于 RAG 已通过验收。
