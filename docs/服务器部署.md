# GitHub Actions 打包、OSS 与 SSH 部署

## 两条独立手动工作流

| Actions 名称 | 文件 | 作用 |
| --- | --- | --- |
| **Deploy frontend (OSS)** | `.github/workflows/deploy-frontend.yml` | 构建并测试后，只上传前端到 OSS |
| **Deploy backend (SSH)** | `.github/workflows/build-package.yml` | 构建、测试并打包后，只上传服务器运行文件到 `/www/wwwroot/knowforge` |

直接使用仓库现有的 Secrets 和 Variables，名称不变，不需要重新配置、不需要创建 Environment、不需要复制两份配置。前端工作流只读取 OSS 凭据，后端工作流只读取 SSH 凭据，MySQL 仍使用服务器现有 `.env`。

1. 将两个工作流及相关代码提交到 GitHub 默认分支。
2. 打开 **Actions**，选择 **Deploy frontend (OSS)** 或 **Deploy backend (SSH)**。
3. 点击 **Run workflow**，选择分支并运行。`deploy` 默认开启；取消则前端只构建、后端只打包。
4. 可从该次运行的 **Artifacts** 下载产物：前端为 `knowforge-frontend-运行编号-重试编号`，后端为 `knowforge-deploy-运行编号-重试编号`，均保留 30 天。

两条工作流均只声明 `workflow_dispatch`，不会因推送、PR、标签、定时或另一工作流完成而自动运行。它们分别使用前端和后端部署并发组，防止同一目标被两个部署同时覆盖。

只改页面时运行前端工作流；接口、题库资料、判题或运行器有改动时运行后端工作流。两端都改时，选择同一个 commit 对应的分支，先运行后端、通过后再运行前端；期间不要继续向该分支推送新 commit，避免两次手动运行选中不同版本。

前端执行安装依赖、构建、数据校验和常规测试，保存 dist 产物后上传 OSS。后端只生成学习数据并执行测试，再通过 esbuild 编译 `backend-dist/`、检查独立生产包，最后上传 SSH 并按 `SSH_RESTART_COMMAND` 重启。后端不执行 Vite 构建，不上传前端 dist、client/shared 源码目录或整份 docs。16666 仅保留 API 与实验资源代理，兼容已有 Nginx 回源地址。

构建或测试失败不会进入对应上传步骤。后端 Artifact 为独立后端运行包及 SHA-256 校验文件；部署阶段失败时已生成的 Artifact 仍可下载。

## Actions 配置：Secrets 与 Variables

在仓库 **Settings → Secrets and variables → Actions** 配置以下名称。凭据只能放在 Secrets，不要写进仓库、Vite 环境变量或前端代码。

### Secrets

| 名称 | 必填 | 内容 |
| --- | --- | --- |
| `SSH_HOST` | 是 | 服务器公网 IPv4 或主机名，不带协议与路径 |
| `SSH_USERNAME` | 是 | SSH 账号，例如 root 或有部署权限的账号 |
| `SSH_PASSWORD` | 是 | SSH 登录密码 |
| `SSH_PORT` | 否 | SSH 端口，默认 22 |
| `OSS_ACCESS_KEY_ID` | 是 | 阿里云 AccessKey ID |
| `OSS_ACCESS_KEY_SECRET` | 是 | 阿里云 AccessKey Secret |

无需配置主机公钥 Secret。每次运行使用临时 known_hosts 文件，首次连接自动接受主机密钥，并在同一次运行的后续 SSH/SCP 连接中复用；密码通过环境变量交给 sshpass，不写入命令行或产物。

### Variables

| 名称 | 必填 | 内容 |
| --- | --- | --- |
| `OSS_BUCKET` | 是 | Bucket 名称，不带 oss:// |
| `OSS_ENDPOINT` | 是 | Bucket 公网 Endpoint，例如 https://oss-cn-hangzhou.aliyuncs.com |
| `OSS_REGION` | 是 | Region，例如 cn-hangzhou；V4 签名使用 |
| `OSS_PREFIX` | 否 | 前端对象目录，例如 knowforge；默认空，即 Bucket 根目录 |
| `SSH_RESTART_COMMAND` | 否 | 上传后的服务重启命令，例如 systemctl restart knowforge |

`OSS_REGION` 必须填写通用 Region ID，例如广州为 `cn-guangzhou`（短横线），不能写成 `cn_guangzhou` 或 `oss-cn-guangzhou`。广州对应的 `OSS_ENDPOINT` 为 `https://oss-cn-guangzhou.aliyuncs.com`。出现 `Invalid signing region in Authorization header` 时，先检查这两个值是否与 Bucket 地域一致；修改现有仓库 Variable 即可，无需重新创建其他凭据。

SDK 使用阿里云 V4 签名。AccessKey 所属 RAM 身份需有目标前缀的上传权限，Bucket/CDN 的读权限与鉴权按你的站点配置；流水线不会修改 Bucket ACL、CDN、DNS 或服务器 Nginx 配置。

服务器需预先安装 Node.js 24+、npm、tar、sha256sum，SSH 账号需能写入 `/www/wwwroot/knowforge`。配置重启命令时还需 curl，且账号要有执行该命令的权限。

## SSH 目录与重启

后端直接部署到 **`/www/wwwroot/knowforge`**：

```text
/www/wwwroot/knowforge/
├── server/index.mjs         编译后的后端入口
├── server/chunks/           编译后的动态存储模块
├── data/catalog.json        课程、题库与标准答案
├── resources/               Worker、学习手册与 Python 下载示例
├── node_modules/            仅后端生产依赖
├── package.json             后端专用依赖清单
├── package-lock.json        从源码锁文件提取的精确运行依赖
├── build-info.json          构建元数据
├── .env                     服务器原有配置，部署保留
└── runtime/                 学习数据库，部署保留
```

上传包只在 `.incoming/` 中临时解压、校验 SHA-256 和安装生产依赖，准备成功后将应用文件更新到项目根目录，最后清理临时上传目录。不创建或使用 releases、current 版本目录。数据库、WAL 文件、根目录 .env 与其他本地文件保留。server/data/resources/node_modules 为构建产物目录，每次更新替换，避免残留旧模块；同时清理旧版完整包管理的 dist/client/shared/docs/examples 目录及 README.md。这些目录不用于保存个人数据。

`SSH_RESTART_COMMAND` 默认不设置，表示只更新文件，不改变现有服务。首次部署必须启动服务；需要每次自动重启时设置此变量。命令以 SSH 账号身份、在 `/www/wwwroot/knowforge` 工作目录执行。重启后检查本机 6666 端口的 `/api/health`，失败会令部署任务报错。

这是直接覆盖部署，不再提供版本链接切换或自动回退。依赖安装失败不会修改原应用；文件更新后的重启失败需修复服务或重新部署，已有学习数据仍保留。部署前可通过应用导出学习备份。

如果采用 systemd，可预先创建 `/etc/systemd/system/knowforge.service`，按服务器实际路径与运行用户修改：

```ini
[Unit]
Description=KnowForge
After=network.target

[Service]
Type=simple
User=www
WorkingDirectory=/www/wwwroot/knowforge
Environment=NODE_ENV=production
ExecStart=/usr/bin/node /www/wwwroot/knowforge/server/index.mjs
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

确认运行用户有 runtime 的写权限、Node 的绝对路径正确，然后执行 `systemctl daemon-reload` 和 `systemctl enable knowforge`；将 Variable `SSH_RESTART_COMMAND` 设为 `systemctl restart knowforge`。SSH 账号需要对应的服务管理权限。若已有服务使用其他 DB_PATH，继续沿用原配置，不要复制正在打开的 SQLite 文件。

## SSH 部署失败定位

`Permanently added ... to the list of known hosts` 是首次连接的提示，本身不是失败。脚本依次打印 `[SSH 1/3]` 创建上传目录、`[SSH 2/3]` 上传文件、`[SSH 3/3]` 执行远端部署；远端会继续打印工具检查、校验、解压、依赖安装、更新文件、重启与健康检查阶段。失败信息只包含阶段、行号和退出码，不输出密码或完整命令。

若提示 `Missing server command: node` 或 `npm`，说明该命令不在非交互 SSH 的 PATH 中，即使交互终端能运行也可能出现此问题。需在部署账号的非交互环境中提供 Node.js 24+ 和 npm，或配置其可执行目录。`SSH_RESTART_COMMAND` 留空只上传文件，不会启动服务，也不是工具检查阶段失败的原因。

## MySQL 数据库配置

服务器可以完全使用已有 MySQL，建议 MySQL 8.x。SQLite 仅作为未配置时的本地默认选项；选择 MySQL 后不会读写 `runtime/study.sqlite`。

先在数据库管理面板中创建数据库及账号（或使用已有库），给账号授予目标库的 `CREATE`、`SELECT`、`INSERT`、`UPDATE`、`DELETE` 权限。应用不会自动创建数据库，也不需要 root 账号。然后在服务器 `/www/wwwroot/knowforge/.env` 填写：

```dotenv
DB_DRIVER=mysql
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_DATABASE=knowforge
MYSQL_USER=knowforge
MYSQL_PASSWORD="替换为你的数据库密码"
MYSQL_TABLE_PREFIX=knowforge_
MYSQL_SSL=false
FRONTEND_PORT=16666
PORT=6666
```

远程 MySQL 如果要求 TLS，设置 `MYSQL_SSL=true`；使用私有 CA 时再配置 `MYSQL_SSL_CA=/absolute/path/to/ca.pem`。TLS 会验证服务端证书，主机名需要与证书匹配。只使用项目后端连接 MySQL，数据库账号密码不放入前端或 OSS。

`.env` 不上传 GitHub、不进入部署包，SSH 更新保留服务器现有文件。由服务运行用户持有，建议限制为仅该用户可读。无需为 Actions 增加 MySQL 生产密码：部署任务只更新应用，应用启动时从服务器 `.env` 读取配置。若 systemd 或 PM2 已设置同名变量，需要同步修改或移除旧值。

重启服务后，`curl http://127.0.0.1:6666/api/health` 应返回 `"database":"mysql"`；页面底部也显示 MySQL。首次启动自动创建 `knowforge_` 前缀的账号、会话和个人学习表，重复启动保留数据。修改前缀会切换到另一组表，原表不会删除。连接或建表失败会令启动失败，检查地址、权限、密码及服务日志。

在两个账号/数据库间迁移个人备份（可选）：

1. 登录来源账号，在“资料来源与数据”导出个人 JSON 备份。
2. 配置 MySQL 并重启服务，确认健康接口显示 MySQL。
3. 在目标库注册并登录账号，再选择备份、预览并合并导入，核对个人记录。
4. 保留原 SQLite 与 JSON 备份。浏览器未提交草稿仍在对应站点的 localStorage 中，需单独保存。

应用已支持账号隔离。账号、会话及 `user_*` 个人表与旧共享表分开；所有新账号从空白学习状态开始，首位注册者也不会获得旧共享记录。浏览器代码草稿按账号 ID 分开保存，不读取旧共享草稿。应用请求仍在单个 Node 进程内串行处理数据库操作，事务绑定同一连接；部署保持一个应用进程，不开启多进程 cluster 或多副本。

工作流另外启动独立 MySQL 测试服务验证存储和 API，不会连接你的生产数据库。开发验证命令为 `npm run test:mysql`，需要单独测试库的 `MYSQL_*` 变量及建表、删表权限；测试仅清理每次随机前缀下创建的表。

## 正式域名与跨域登录

| 用途 | 正式地址 | 回源 |
| --- | --- | --- |
| 前端 | `https://knowforge.ookew.com` | OSS 静态资源 |
| API 与实验运行资源 | `https://knowforge-api.ookew.com` | 服务器 Nginx → `127.0.0.1:6666`（也兼容原 16666 网关） |

域名已在 `shared/deployment.mjs` 配置，正常生产构建无需新增 Actions 变量。开发模式继续使用本地同源代理。前端所有 API、个人备份和资料下载均指向 API 域名；OSS 前端域名不再需要为 `/api/*` 配置条件回源。

前端域名配置 HTTPS、首页 index.html，以及 Vue history 页面路由回退 index.html；HTML 不缓存，带哈希的 assets 长缓存。API 域名配置 DNS、HTTPS 证书及服务器站点，接口禁止缓存，保留 GET/POST/PUT/OPTIONS 和请求体。

API 站点 Nginx 中使用：

```nginx
location / {
    proxy_pass http://127.0.0.1:6666;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header Connection "";
    client_max_body_size 12m;
}
```

该配置放在 `knowforge-api.ookew.com` 的 HTTPS server 中。已有 16666 代理入口可以继续使用。API 源站 Host 应保留 API 域名，不再固定为前端域名。

后端仅允许 `https://knowforge.ookew.com` 的跨域访问（以及 API 自身来源）；精确返回 Allow-Origin、Allow-Credentials 和 Vary: Origin，处理不带登录态的 OPTIONS 预检。保留 Cookie、Set-Cookie、Origin、X-CSRF-Token、X-KnowForge-User 请求头，不要在 Nginx 再添加通配 CORS 头。前端 fetch 使用 credentials: include。生产会话 Cookie 为 API 域名的 host-only、Secure、HttpOnly、SameSite=Lax；两个 HTTPS 子域属于同站点，无需把 Cookie 扩大到整个 ookew.com。

代码实验通过 API 域名的 `/runner-frame` 隔离页启动同源 Worker，并校验跨域消息的来源、窗口及请求 ID。`/runner.js`、`/python-runner.js`、`/python-runtime/*` 继续由 API 提供并保留 Worker CSP 网络限制。`/runner-frame` 的 CSP 仅允许正式前端嵌入；不要用 Nginx 的 X-Frame-Options: DENY/SAMEORIGIN 覆盖这个路径，避免阻止合法跨域嵌入。前端若配置页面 CSP，应允许 frame-src https://knowforge-api.ookew.com 和 connect-src https://knowforge-api.ookew.com。

OSS 上传仍先上传资源，最后发布 index.html，不删除旧哈希资源。若 CDN 曾缓存旧 HTML，发布后刷新前端 HTML 缓存。公网端口只需 HTTPS，Node 端口仍保持本机监听。

## 部署包内容

Artifact 外层为 GitHub 下载的 ZIP，解压后包含：

- `knowforge-2.0.0-deploy.tar.gz`：独立后端运行包，版本号取自 package.json。
- `knowforge-2.0.0-deploy.tar.gz.sha256`：SHA-256 校验文件。

tar.gz 内的目录为 `knowforge/`，包括：

| 路径 | 用途 |
| --- | --- |
| `server/index.mjs`、`server/chunks/` | esbuild 编译结果，不包含原始 server/shared 源码树或 sourcemap |
| `data/catalog.json` | 完整课程、题目和标准答案，API 运行必需 |
| `resources/runner.js`、`python-runner.js` | 后端提供带 CSP 的浏览器执行脚本 |
| `resources/handbook.md`、`workbench.py` | 手册和配套项目下载接口所需文件 |
| `package.json`、`package-lock.json` | 仅 Express、mysql2、Zod、Pyodide 及其锁定的传递依赖 |
| `build-info.json` | 版本、源码 commit、锁文件摘要与构建信息 |
| `runtime/` | 空目录，不携带个人数据 |

`npm run build:backend` 生成独立 `backend-dist/`，`npm run package:deploy` 先构建该目录，再打成原有命名的 tar.gz。后端包不包含前端页面、Vue/CodeMirror/Vite/esbuild/nodemon、整个 docs、测试、源码配置、已有数据库或 node_modules。服务器只需安装生成清单中的后端依赖，版本和 integrity 来自项目原锁文件，不重新解析依赖版本。

Pyodide 是 Python 实验实际运行所需资源，仍通过后端依赖安装并由 `/python-runtime/*` 提供；Worker、题库和下载资源也是现有接口的一部分，不能一并删除。

## 服务器启动

以下命令以 Linux、Node.js 24 和 npm 为例。服务器安装生产依赖时需要访问 npm registry，运行学习示例不需要模型 API Key。

先解压 GitHub 下载的 Artifact ZIP，在包含 tar.gz 的目录执行：

```bash
sha256sum -c knowforge-2.0.0-deploy.tar.gz.sha256
tar -xzf knowforge-2.0.0-deploy.tar.gz
cd knowforge
npm ci --omit=dev
NODE_ENV=production npm start
```

独立后端 API 监听 `127.0.0.1:6666`，兼容网关监听 `127.0.0.1:16666`，仅转发 API 和运行资源，不提供 `/`、`/login` 等前端页面。浏览器访问 OSS/CDN 的 HTTPS 域名。Python 3.12 用于 CI 测试，普通服务器运行无需安装本机 Python，只有执行独立 Python 配套项目时才需要 Python 3.11+。

包已包含编译后的后端，无需在服务器构建。`npm start` 与既有 `server/index.mjs` 服务入口保持不变，服务必须以解压后的 `knowforge/` 为工作目录运行。原有 SSH/OSS 配置、服务器 .env、重启命令、Node 环境及 Nginx 回源端口都可继续使用。

## 数据目录与升级

建议固定学习数据库路径，并由运行服务的用户持有写权限。例如先创建 `/var/lib/knowforge`，再启动：

```bash
NODE_ENV=production DB_PATH=/var/lib/knowforge/study.sqlite npm start
```

用 systemd 或现有进程管理器保持服务运行，并配置相同的工作目录和环境变量。启动入口自动加载工作目录中的 `.env`；终端或进程管理器已有的同名环境变量优先。MySQL 模式按下面的配置运行。

自动部署直接更新 `/www/wwwroot/knowforge` 的应用文件并保留 runtime。手动升级也应保留已有数据库和外部 DB_PATH，先导出备份，再在维护时段更新文件与重启服务；空 runtime 目录不是个人数据备份。

## 整站服务器模式的 HTTPS（不使用 OSS 时）

本节仅用于从源码运行完整前后端的方式。独立后端部署包不再提供前端页面；OSS 部署使用前文独立前端/API 域名配置；原有 16666 API 网关仍可使用。

两个 Node 端口均只监听回环地址。服务器通过 Nginx 等反向代理暴露域名，将请求转发到前端 `127.0.0.1:16666`，API 和 Python 资源会由前端继续转发到后端，无需把 6666 暴露到公网。

在已有 HTTPS server 配置中，可使用下面的 location；域名和证书沿用服务器自己的配置：

```nginx
location / {
    proxy_pass http://127.0.0.1:16666;
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header Connection "";
    client_max_body_size 12m;
}
```

后端仅信任来自本机回环代理的转发信息，生成 Python Worker CSP 时会识别外部 HTTPS 协议。请保留 Host 与 X-Forwarded-Proto 配置。

当前应用开放账号密码注册，无验证码。登录后访问个人记录接口；资料与标准答案全站共享，进度、笔记、作答、设置、试卷和备份均按账号隔离。

密码用带随机盐的 scrypt 哈希保存；数据库只保存会话令牌的 SHA-256 摘要，会话有效期 7 天。Cookie 使用 HttpOnly、SameSite=Lax，经 HTTPS 访问时带 Secure；写入接口校验 CSRF Token 和请求来源。请保留 Nginx 的 `Host`、`X-Forwarded-Proto`、Cookie 和 Set-Cookie 头，CDN 的 `/api/*` 禁止缓存，不能过滤 `X-CSRF-Token` 或 `X-KnowForge-User` 请求头。

限流按后端识别的访客 IP 计算，Nginx 应覆盖传入的 `X-Forwarded-For`，传入自身确认的 `$remote_addr`。若经过 CDN，需使用云厂商提供的真实访客 IP 配置，并只信任 CDN 的来源地址；否则多个访客可能共用一个 CDN 节点的限流额度。

注册按 IP 限制为每小时 10 次；登录按 IP 每 15 分钟 40 次，并限制账号连续尝试。限流在单实例内存中维护，重启清零。当前没有自助找回密码或管理员控制台；注册页已提示用户保管密码。

## 本地复现打包

在源码根目录、依赖已安装的 Linux 或 macOS 环境执行：

```bash
npm run build:data
npm run check:data
npm test
# 先配置独立测试库的 MYSQL_* 变量
npm run test:mysql
python3 -m unittest discover -s tests -p test_deploy.py
npm run package:deploy
node scripts/check-deploy.mjs release/knowforge-2.0.0-deploy.tar.gz
```

本地输出同样位于 release/；最后一步会解压到临时目录、安装生产依赖并使用独立数据库和临时端口检查，不会读写已有学习数据库。
