## 从具体问题认识算法起步

算法题要求你把一份输入按照明确规则变成输出。故事背景只是包装，真正需要提取的是对象、允许操作、目标和限制。例如“选最多场不冲突会议”中的对象是时间区间，允许操作是选择其中若干个，目标是数量最多，限制是所选区间不能重叠。

读题后先用自己的话解释一个样例，再决定数据结构。若还不能说明某个输出为什么是 3，就直接套模板，往往只是把不理解藏进代码。

## 题意、规模与验证怎样连起来

输入格式规定数据如何排列。第一行 n 可能表示数组长度，也可能表示接下来有 n 个测试用例，必须逐项确认。输出要求也要精确：返回最优值、方案数量和某个具体方案是三类不同问题。下标从零还是一开始、是否允许空解、重复元素是否视为不同对象，都影响实现。

约束给出算法必须承受的范围，不意味着题面会列出所有测试。n 为十万时，两层完整枚举可能需要约百亿次比较，通常不合适；但复杂度不是绝对秒数承诺，常数、语言和数据结构也有影响。空间约束、整数范围和递归深度应一起检查。

先写小规模暴力解作为正确性基线，再设计高效算法，用随机小输入对照两者。样例帮助理解题意，边界测试帮助找错误，对拍帮助发现未预想组合；这些都不能代替正确性论证。证明循环不变量或状态转移，才能解释为什么未列出的输入也应正确。

## 先把问题翻译成自己的话

遇到题目先写清四件事：给了什么、允许做什么、要输出什么、哪些细节不能改变。比如“从数组选连续非空子数组求最大和”，连续表示不能跳过中间元素，非空表示全负数组也不能输出 0。不要看到“最大”就套动态规划，先用三五个数手算合法与非法答案。给自己写一句输入输出契约，比一开始写循环更能减少方向错误。

## 一组输入和多组测试不是同一概念

n≤200000 表示单个实例最多二十万个元素，不表示需要二十万组例子。一个测试实例可以很大，多个测试则覆盖不同情况。本项目题面样例用于理解，提交验证另有边界、小规模随机对照和接近约束上限的数据。有限测试不能证明所有输入正确，学习者仍需解释算法依据。数据规模检查也受设备速度影响，浏览器执行时间不能作为跨设备的统一性能排名。

ACM 程序读完整标准输入，按格式解析后只输出答案。多余的“请输入”“答案为”都会使输出不匹配；调试信息用 console.error。数组下标 0-based 与题目位置 1-based 要在入口转换，闭区间 [l,r] 与半开区间 [l,r) 要先画图确认。

## 从约束反推能承担的工作量

O(n) 不是“一次循环”这个语法，而是总工作量随 n 线性增长；两根只向前的指针即使有嵌套 while，总推进也可为线性。O(n²) 在 n=10 时不显眼，在 n=200000 时约有四百亿对候选。先估算状态数、每状态转移数和空间，再选算法；常数、输入解析、字符串复制也可能影响表现。

JS 默认 sort 按字符串比较，数值排序需比较器。位运算只处理 32 位整数，不能用它截断账单总和或大区间中点。Number 的整数精度有上界，题目允许 10^18 时应从原始字符串进入 BigInt，不能先 Number 再转回来补精度。

## 先写一个小规模正确基线

例如最大子数组和，可以枚举起点、终点并累加；它慢，但容易核对，适合长度 8 的随机数据。再把优化程序与这个基线用相同输入比较，保存第一个不一致的实例。基线不能照抄优化递推，否则同一错误会同时出现在两边。随机种子固定，才能在同伴电脑和下一次修改后重现失败。

## 设计边界而不是机械增加数量

至少考虑单元素、全相同、递增、递减、全负或零、重复边界、无解、刚好等于阈值、超过 32 位但仍安全的数值。测试要能对应一个错误假设，例如背包正序会重复使用同一物品，可用“一项重量 2、预算 4”暴露。大数据则针对可能的平方扫描、递归爆栈和输出膨胀；不是随便把同一个小样例复制一万遍。

## 推荐练习顺序与复盘

先做合并有序名单、数值排序、分饼干、爬楼梯；再做会议选择、打家劫舍、最大子数组；最后再进背包、区间 DP 与选择算法。每题记录：一句话题意、暴力方法、优化依赖的不变量、边界反例和复杂度。通过后关掉答案重写一次，改变条件再判断原方法是否仍成立，例如把每船最多两人改成三人，旧贪心证明就不能直接沿用。

## 把机制放到一条完整路径中

```flow
读题到验证
翻译题意｜明确输入目标与允许操作
估算规模｜筛选时间空间可行的方法
推导算法｜写出状态或不变量
验证实现｜样例边界与小规模对拍
```

## 配套代码：算法起步：读懂题意、输入规模和验证边界 · 手推后运行

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

先预测输出，再修改一处输入，检查你的状态与不变量解释是否成立。

```javascript
const input="3 2\n10 -1 4\n1 2\n2 3";
const tokens=input.trim().split(/\s+/).map(Number);
const n=tokens[0],q=tokens[1],values=tokens.slice(2,2+n);
console.log({n,q,values});
console.log(values.reduce((sum,value)=>sum+value,0));
```

输入首先按空白拆分，再把首项作为数量并读取后续数据。ACM 格式由题目约定，不能把这个解析器原样用于所有题；若题目有多组或允许空行，需要按相应协议推进读取位置。

这段示例还展示题目约束与测试实例数不同：上限约束决定算法的复杂度选择，样例只负责解释输入输出。提交前另外构造边界和小规模暴力对照，才能检查样例之外的正确性。

## 从示例走向实际使用

练习时固定四步：翻译题意、手算样例、写清算法依据、验证边界。ACM 模式还要把输入解析与求解分开，避免算法正确却因读取多组数据或输出多余日志而失败。

后续练习提供输入输出示例与测试，但不要把通过样例当成完成。每题至少主动构造一个最小输入、一个重复值输入和一个能推翻直觉的反例。
