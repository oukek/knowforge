## 从具体问题认识Workflow、ReAct 与 Plan-and-Execute

工作流把步骤和分支显式写在程序中；ReAct 风格让模型结合观察逐步选择行动；Plan-and-Execute 先形成计划，再执行并根据结果调整。它们描述控制流组织方式，不是质量高低排行榜。

例如发票处理的固定校验与审批适合明确工作流，开放式资料调查可能需要边查边决定下一步，而复杂任务计划有助于记录依赖和进展。

## 计划不是事实，观察可以改变下一步

显式工作流的优势是路径可检查、权限与失败处理明确，但面对未预见任务可能需要增加分支。动态 Agent 更灵活，却增加循环、成本与不可预测路径。实际系统常混合两者：外围工作流控制授权与提交，内部模型处理有限开放问题。

计划应包含可验证步骤、依赖、输入输出与完成条件。模型写出的计划可能遗漏前置条件，执行器不能把它当成已证明可行。工具失败或新证据出现时，需要更新计划并保留已完成事实，避免每次重规划都重复有副作用操作。

所谓推理与行动交替，应关注可观察决策摘要、工具调用与结果，不要求暴露模型内部不可见推理。评估看任务是否完成、行动是否合法和资源是否受控，而不是计划文本看起来多么细致。

## 先分清控制流由谁决定

固定工作流由代码指定路径和条件；ReAct 式组织将推理决策与行动观察交替；Plan-and-Execute 先形成计划再执行步骤，并可能根据新证据重规划。它们是设计模式，不是互斥品牌，也没有一种始终最优。

固定路径适合稳定规则和强约束流程；动态行动适合下一步依赖未知观察；显式计划适合可分解长任务，但计划也可能过时。真实系统常把确定性外壳与动态节点组合。

## 三种模式的代价

ReAct 可能更频繁调用模型来决定下一步，计划模式可能减少某些决策轮次但增加计划维护与重规划成本。延迟与成功率取决于任务，不应仅凭名称断言谁更快。并行也只能加速真正独立的部分。

| 模式 | 优点方向 | 失败风险 |
|---|---|---|
| Workflow | 路径清晰可检查 | 无法处理未覆盖情况 |
| ReAct | 能根据观察调整 | 工具循环、重复行动 |
| Plan/Execute | 长任务结构明确 | 计划过时、假进度 |

Reflection 或 Critic 可检查候选结果，但同模型的自评可能重复原错误，仍需外部标准与证据。

## 计划必须可验证

每步包含目标、输入、完成判据、依赖和预算。发现事实冲突时改变后续计划，已提交操作不能被文本计划简单“撤销”。人工介入绑定具体动作和版本，不能只问“是否继续”却隐藏金额或对象变化。

不要要求把私有思维过程当成系统审计。可靠轨迹记录可观察的决策摘要、工具请求、结果、状态和验证证据；这些事实比一段流畅的推理文本更可复现。

## 如何选型和验收

对相同任务集比较三种模式，固定工具事实、模型和预算，记录任务成功、模型轮次、关键路径、总成本与人工接管。加入工具失败、计划中途失效、重复动作和长期无进展。

面试回答要说明为什么当前任务适合此模式，哪些边界交给固定规则，以及重规划后的旧副作用如何查账。没有真实对照时用“设计假设”，不要声称必然降低百分之多少延迟。

## 把机制放到一条完整路径中

```flow
行动组织
选择控制方式｜固定流程逐步决策或先计划
定义步骤契约｜输入输出依赖与权限
执行观察｜用真实结果更新任务事实
调整收敛｜必要时重规划并验证终点
```

## 配套代码：Workflow、ReAct 与 Plan-and-Execute：行动组织方式

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
function plan(stock) {
  return stock > 0
    ? ["check_stock", "create_draft", "review"]
    : ["check_stock", "report_unavailable"];
}
const initial = plan(3);
const observedStock = 0;
const revised = plan(observedStock);
console.log(initial);
console.log(revised);
console.log(revised.includes("create_draft"));
```

计划随权威观察更新；本例只替换未执行的后续步骤，不撤销真实副作用，也不模拟完整 ReAct 或模型思维。

## 从示例走向实际使用

用同一个任务比较固定工作流、逐步行动与计划执行，记录成功率、工具次数和恢复难度。任务变化小且风险高时，更多显式控制通常更容易管理。

课内计划变化实验展示观察如何触发调整；真实系统还需版本化计划与幂等步骤，保证恢复后不把已完成工作再做一遍。
