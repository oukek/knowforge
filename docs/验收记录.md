## 已解决的验证发现

- 开发代理下 Origin 与后端 Host 不一致导致写请求 403：开发模式显式允许输出的 127.0.0.1:5173 来源，正式模式同源校验。
- Vue 响应式 Proxy 不能直接 postMessage/structuredClone：给 Worker 传纯数据，在试卷恢复时复制可序列化记录。
- SSE 实验的跨行测试字符串转义：修复并加入实际 Worker 脚本协议测试。
- 计划超出周期时全部堆在最后一天：改为有界日程与下一周期待排队列。
- 动态导入整套图标使入口变大：改用显式图标映射，入口约从 631KB 降至 127KB（构建原始体积）。
- 运行器加入实时 console 后，单条日志不能视为执行完成：用 console/clear/done 消息类型分开处理，并兼容原实验协议。
- DOM、微信和 Node 宿主能力不能直接在 Worker 执行：提供明确标记的纯 JS 教学模型，说明验证范围，避免把模拟结果当成真实平台结论。

## 开发监听循环修复

原 `node --watch` 会跟踪 Vite 动态加载的 `.vite-temp` 临时配置；每次重启生成新配置，又触发下一次重启。开发命令改用 nodemon，明确只监听 `server/`、`shared/` 和 `data/catalog.json`，通过 SIGTERM 正常关闭后重启，前端热更新仍由 Vite 负责，默认入口保持 6666。

在独立的 `output/watch-fix/qa.sqlite` 和显式测试端口执行真实开发服务检查：空闲稳定；连续写入 Vite 临时目录不重启；CSS 改动通过 WebSocket 收到 Vite HMR 消息且后端不重启；分别修改后端、共享模块和课程数据时各只重启一次，随后保持稳定。16 项 API 回归测试通过。记录位于 `output/watch-fix/verification.txt` 和 `output/watch-fix/api-tests.log`，未修改正式学习库。
