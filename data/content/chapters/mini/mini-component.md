## 从具体问题认识自定义组件、通信与状态所有权

组件把界面结构、样式和局部行为组织成可复用单元。它应有明确输入与输出：父级传入需要展示的数据，组件通过事件表达用户意图，父级再决定业务状态怎样变化。这样同一个组件才能用于不同页面。

例如数量选择器接收 count 和 disabled，用户点击加号后发出“希望增加数量”的事件。是否超过库存、是否需要登录、是否保存到服务器，是外部业务决定，不应全部隐藏在一个通用按钮内部。

## 单向数据流与状态所有权

属性是外部输入，内部状态属于组件自身。若组件把传入属性复制一份后永久独立修改，就容易出现父级值更新了、内部副本还停在旧值的双重状态。应明确受控组件由父级持有最终值，或非受控组件只把输入当初始值，不能两种模式混用。

事件应描述发生的业务意图或结果，并提供最小必要信息，例如 itemId 与 nextCount。直接暴露内部实例让父级随意调用私有字段，会使组件重构牵连所有调用方。事件是否冒泡、是否跨组件边界传播，也应显式设计，避免嵌套组件触发多次处理。

插槽用于让外部提供部分内容，样式隔离用于减少不同组件互相覆盖。隔离并不意味着无需设计尺寸与主题契约：组件应该说明宽度由谁决定、长文本怎样处理、外部可定制哪些部分。共享状态适合放在真正共同的所有者中，避免每个组件都重复维护一份登录用户。

## 把机制放到一条完整路径中

```flow
组件通信
父级输入｜传入当前值与约束
局部交互｜组件处理展示与操作
发出事件｜表达意图并携带必要标识
业务更新｜父级确认后传回新状态
```

## 配套代码：受控状态通过事件更新

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

子组件发送意图，父级持有权威值，不隐式修改共享对象。

```javascript
let parentValue = 0;
function createChild(getValue, emit) {
  return {click() { emit('change', getValue()+1); }};
}
const child = createChild(() => parentValue, (event, next) => {
  if (event === 'change') parentValue = next;
});
child.click(); child.click();
console.log(parentValue);
```

子组件读取父级当前值并发出 change 意图，由父级更新权威状态。这里使用普通函数模拟 properties/事件，真实组件还有更新调度和生命周期。
