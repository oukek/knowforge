## 从具体问题认识性能结果的口径与因果

性能结果只有在测量口径清楚时才有意义。“提升 50%”可能指耗时减半、吞吐增加一半或某个分数上涨，它们并不等价。项目表达需要把指标名称、起止点、样本和比较条件一起说清。

例如接口从 800 毫秒降到 400 毫秒，耗时下降 50%；若只是在开发机缓存命中后测得，不能直接宣称所有真实用户首屏都快了一倍。

## 从相关变化走向因果证据

先固定目标指标与采集位置，再收集改动前后的数据。设备、网络、缓存、页面路径和用户构成变化都可能影响结果。整体平均变好而慢设备变差并不矛盾，所以需要分组分布与样本量，不能只展示一张均值截图。

受控实验尽量只改变目标因素；灰度或 A/B 比较则需要稳定分组并检查两组是否可比。若同一版本同时上线资源压缩、接口改造和新 CDN，很难把全部收益归因于某一个函数优化。可以报告组合改动的效果，同时通过局部实验解释各环节贡献。

百分比之外保留绝对值与业务影响。把 2 毫秒降为 1 毫秒比例很大，但用户可能无感；把长尾十秒降为三秒即使只影响部分用户，也可能显著改善完成率。指标优化还应检查错误率、资源成本与功能完整性，避免通过跳过必要工作制造漂亮数据。

## 把机制放到一条完整路径中

```flow
指标证据
定义口径｜明确起止点单位与成功条件
控制比较｜保持环境或建立可比分组
分析分布｜同时看绝对值分位数和样本
限定结论｜区分观察结果与因果推断
```

## 配套代码：先固定测量口径再计算变化

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

仅对演示样本计算中位数和变化比例，不把输入数字当个人业绩。

```javascript
const median=values=>{const a=[...values].sort((x,y)=>x-y);return (a[Math.floor((a.length-1)/2)]+a[Math.floor(a.length/2)])/2;};
const before=median([100,110,120]);
const after=median([70,80,90]);
console.log(before,after);
console.log(Number(((before-after)/before*100).toFixed(1)));
```

相同定义下演示中位数下降 27.3%，但计算正确不证明因果。真实回答要给设备网络、采样、分位数、失败率与对照；不能套用这些示例数字。

## 从示例走向实际使用

为每个结果写一句完整表述：在哪些用户、什么时间窗口、按何种指标，从多少变到多少，样本多少，还有哪些限制。没有随机对照时，使用“观察到相关改善”比断言单一因果更准确。

复盘时保留原始测量与分析脚本，使结果可以复查。面试追问通常不是要更多数字，而是检验数字是否可信。
