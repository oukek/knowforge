## Go 程序怎样从源码变成可执行文件
Go 是静态类型的编译型语言。编译器先检查类型与语法，再生成可执行程序；运行时还提供 goroutine 调度、内存管理等能力。编译型不代表程序里没有运行时开销，也不代表内存与并发问题自动消失。

文件属于 package，相关文件共同构成包。module 则是依赖和版本管理的单位，通常由 go.mod 标识，一个 module 可以包含多个包。把包名、模块路径与目录名分清，才能理解 import 引用的到底是什么。
## 逐个认识源文件里的结构

Go源文件先声明package，再列出import，随后定义类型、变量、常量和函数。main包中的main函数是可执行程序入口，它不接收普通函数参数，也不声明返回值；命令行输入通过os.Args或flag等库读取。标准库fmt用于格式化输入输出，打印只是观察程序的一种手段，不是函数返回结果的替代品。

一个包可以由同一目录下多个源文件组成，它们共同参与编译。标识符首字母大写通常表示从包外可访问，小写则限制在包内；这是包边界上的导出规则，不等于给敏感数据加密。import使用包路径，调用时使用包名，两者相关但并非每次都只是目录最后一段的机械复制。

## go run、go build 和 go test 的关系

| 命令 | 主要用途 | 是否等于部署 |
| --- | --- | --- |
| go run . | 编译当前程序并立即运行，方便开发 | 不是固定交付产物 |
| go build . | 编译并生成适合目标平台的产物 | 还需配置、资源与启动方式 |
| go test ./... | 对当前模块下匹配包执行测试 | 通过不代表真实环境所有故障都覆盖 |
| go fmt ./... | 统一源码格式 | 不检查全部业务正确性 |

模块路径例如example.com/course用于标识依赖中的导入位置，不要求每个练习都立即上线一个同名网站。go.mod中的依赖与版本决定构建解析，go.sum提供校验信息；本机缓存只是加速手段，不应成为唯一依赖来源。学习时先让一个目录在干净环境能构建，再逐步拆包，避免一开始把每个函数都放进单独包而形成难以理解的依赖网。

## 完整运行一个小程序
安装官方 Go 工具链后检查 go version。将下列代码保存为 main.go，执行 go run main.go。go run 会编译再运行，便于学习；go build 生成可交付的二进制。浏览器内的 JavaScript 运行区不能编译这段 Go 代码。
```go
package main

import "fmt"

func main() {
	message := "Hello, Go"
	fmt.Println(message)
}
```
package main 加 main 函数表示可执行入口。import 引入标准库 fmt，未使用的导入会导致编译错误。`:=` 在函数中声明并初始化变量，类型由右侧推断；它不是任意位置都能使用的赋值替代品。
## 用 module 管理一个项目
```bash
mkdir go-course
cd go-course
go mod init example.com/go-course
# 把 main.go 放到此目录
go run .
go fmt ./...
go test ./...
go build -o course .
```
go.mod 记录模块路径、Go 版本约束与依赖；go.sum 记录用于依赖校验的信息，不等于一份应用代码备份。不要复制别人的整个本地工具链目录来发布。版本、目标平台以及 CGO 依赖会影响产物能否运行。
```flow
源码到交付
.go 文件与 go.mod｜源码、包关系、依赖声明
类型检查与编译｜发现不合法调用和类型不匹配
链接生成程序｜结合目标平台与构建配置
运行｜Go runtime 管理调度与内存
测试与发布｜同一构建产物进入可控环境
```
## 从第一天建立可维护习惯
用 gofmt 统一格式，错误处理写在调用附近，先理解值、指针与接口，再学习 goroutine。标准库文档按本机版本阅读，不能把新版本新增 API 直接复制到旧工具链。涉及模块下载时固定可复现依赖，并记录系统环境与配置来源。

练习把打印语句提取成返回字符串的函数，为它写测试，再把程序拆到独立包。这样能看到函数、包和模块各自解决的问题，而不是只记住一串安装命令。
