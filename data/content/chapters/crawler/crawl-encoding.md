## 从具体问题认识编码、压缩、响应类型与原始样本

HTTP 响应首先是字节。压缩决定这些字节怎样被还原，字符编码决定还原后的字节怎样解释为文字，Content-Type 则说明内容类型。把这三个概念混为一谈，会出现解码乱码、重复解压或把 HTML 错误页当 JSON 解析。

例如服务器返回 gzip 压缩的 UTF-8 HTML，需要先得到解压后的字节，再按编码解释文本；客户端库可能已经自动解压，因此不能再无条件手动执行一次。

## 保留证据再解释内容

先记录状态码、相关响应头和受限大小的原始样本，再按客户端行为处理正文。字符编码可能来自 Content-Type、文档声明或来源约定，检测算法只是推测。遇到乱码时应检查字节与声明是否一致，而不是不断尝试编码直到看起来像中文。

JSON、HTML、图片和下载文件有不同处理方式。请求期望 JSON 但实际返回登录页面时，应报告类型或业务状态异常，不能把解析异常当成目标数据格式永久损坏。重定向链和最终 URL 也可能解释为何拿到了错误内容。

流式读取需要限制累计大小，并正确处理跨块的多字节字符。压缩内容可能解压后远大于传输大小，因此只限制 Content-Length 不足以控制内存。保存样本时对敏感信息裁剪，并附带抓取时间与解析器版本，方便后续回放。

## 把机制放到一条完整路径中

```flow
响应解释
取得字节｜记录状态头与受限原始样本
处理压缩｜确认客户端已完成哪些转换
确定编码｜依据声明与来源规则解码
按类型解析｜校验 JSON HTML 或文件内容
```

## 配套代码：编码、压缩、响应类型与原始样本：最小可验证示例

下面代码在课内Python运行区执行；浏览器环境与本机CPython的网络、文件和原生扩展能力不同。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

raw='标题'.encode('utf-8')
show(raw.decode('utf-8'))
content_type='text/html; charset=utf-8'
show(content_type.split(';',1)[0]=='application/json')
```

解码成功来自已知 UTF-8 约定，Content-Type 检查说明不能把任意文本交给 JSON 解析器。真实站点存在错误声明和压缩等情况，需要保存样本定位，而不是盲目尝试所有编码并选一个看起来没有报错的结果。

## 从示例走向实际使用

制作 UTF-8、多字节字符切块、错误 charset、HTML 冒充 JSON 和截断响应样本。验证错误分类，而不只是让程序不抛异常。

课内示例展示正确解码与内容类型判断。真实客户端是否自动解压、如何选择编码应按使用库版本确认，避免重复处理。
