## 从具体问题认识图与堆

图用节点表示对象，用边表示关系。依赖关系通常是有向边，朋友是否连通可以用无向边；堆则是一种让最小或最大候选容易取得的数据结构。图、并查集和堆各自维护不同事实，不能因都出现“节点”就混用。

例如课程 A 是 B 的前置条件，边 A→B 表示 A 完成后 B 才可能开始；找成绩最高的 K 个学生则没有依赖关系，更适合考虑堆或排序。

## 入度、连通集合与堆顶的含义

拓扑排序的入度表示尚未解除的前置依赖数。把入度为零的节点入队，处理它后减少后继入度；若最终处理数量少于节点总数，剩余部分存在无法解除的有向环。队列里可以有多个合法节点，因此拓扑序通常不唯一。

并查集把节点划分为互不相交的集合，通过代表元素判断是否连通，合并操作连接两个集合。路径压缩与按大小或秩合并改善重复查询成本。但它不直接提供具体路径，也不适合用普通合并操作解决任意边删除后的动态连通问题。

求最大的 K 个值可维护容量 K 的最小堆，堆顶是当前入选者里最弱的一项。新值若不超过堆顶就无需入选，超过则替换并恢复堆序。堆只保证父子约束，不保证整个数组有序；最终若需要排序输出，还要额外整理 K 个结果。

## 不同图问题不能混用数据结构

拓扑排序只适用于有向无环图，结果表示依赖先后，不表示最短距离；并查集维护无向连通分量，不能判断任意有向可达性。真实依赖图应明确节点全集、边方向、重复边和自环语义，不能只收集出现在边里的节点而丢失孤立任务。

## Kahn 拓扑排序与环检测

入度为零的节点可先执行，将它从图中移除并降低后继入度；整个过程保持“已输出节点的所有前置依赖都已处理”。若最终输出数小于节点数，则有环或未解决依赖。队列用数组加头索引，避免大量 shift 的潜在线性搬移。如果需要确定性的字典序结果，可用小根堆，而不能把任意合法拓扑序判成同一序列。

## 并查集与摊还复杂度

每个节点指向集合代表，find 沿父指针查根，路径压缩把沿途节点直接挂到根；union 按秩/大小合并避免退化。初始化分量数为 n，只有合并不同根才减一。重复边和已连通节点不能反复减少计数。复杂度通常写为几乎常数的反 Ackermann 摊还界，而不是把每次 find 都声明为严格 O(1)。

## Top-K 的堆不变量

求第 k 大时维护大小不超过 k 的小根堆。堆顶是当前候选中最小的元素；新值不大于堆顶可跳过，更大的替换堆顶并下沉。堆不保证整个数组有序，只保证父节点不大于子节点。重复值按元素计数，非法 k 要明确报错；测试 k=1、k=n、重复最大值和负数。

## 和全排序比较

若只需一次返回排序后的全部元素，排序可能更简单；若是流式数据或 k 远小于 n，堆节省空间与不必要的比较。时间 O(n log k)，空间 O(k)，但最后输出 Top-K 若要求有序还需对 k 个元素排序。把完整排序冒充堆实现可能得到相同小样本答案，但不满足题目资源约束。

## 工程迁移与故障验证

构建任务图出现环时，应输出可诊断信息，而不是永久等待。动态新增节点/边时原有入度和排序可能失效，要定义增量算法或重新计算。算法题先验证不变量，工程版还需限制图规模、处理不可信输入和保留稳定节点 ID。

## 手算一次依赖释放和候选替换

任务有 A、B、C、D，边为 A→C、B→C，D 是孤立节点。初始入度 A=0、B=0、C=2、D=0，队列包含 A、B、D。弹出 A 只把 C 降到 1，不能提前执行 C；弹出 B 后 C 降到 0，才加入队列。因此 A、B、D、C 和 D、B、A、C 都合法。若再加 C→A，B、D 仍可输出，但 A、C 会互相等待，输出数小于 4；这个判据说明有环，不会自动给出完整环路径，诊断路径需要额外 DFS/颜色或强连通分量分析。

Top-K 取流 [5, 1, 8, 8, 3] 的第 3 大：前三个值形成候选集合 {1,5,8}，堆顶 1；第二个 8 替换 1，候选变成 {5,8,8}；3 小于堆顶，直接丢弃。答案是 5。若错误地去重再选第 3 大，会得到 3，改变了题目契约。下沉时需要比较两个子节点并选择更小者，不能始终只与左孩子比较。

```javascript
// 校验任何合法拓扑序，不要求和参考解排列完全一致。
function validOrder(nodes, edges, order) {
  if (order.length !== nodes.length || new Set(order).size !== nodes.length)
    return false;
  const position = new Map(order.map((id, index) => [id, index]));
  return nodes.every(id => position.has(id)) &&
    edges.every(([from, to]) => position.get(from) < position.get(to));
}
```
这说明自动验证也要对准性质：拓扑序验证依赖偏序，堆验证元素多重集与顺序统计量，并查集验证连通关系。测试“数组和参考数组逐项相等”不总是正确的判定器。

## 把机制放到一条完整路径中

```flow
图与候选结构选择
识别关系｜有向依赖还是无向连通
定义维护量｜入度代表元或堆顶候选
局部更新｜释放依赖合并集合或替换堆顶
检查结果｜验证环容量与输出顺序
```

## 配套代码：图与堆：拓扑依赖、连通性和 Top-K

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

浏览器内的确定性实验，用于验证关键不变量。真实服务/SDK 完整示例见正文；不会连接模型或外部服务。

```javascript
function topo(n, edges) {
  const next = Array.from({ length: n }, () => []),
    degree = Array(n).fill(0);
  for (const [a, b] of edges) {
    next[a].push(b);
    degree[b]++;
  }
  const q = [];
  for (let i = 0; i < n; i++) if (!degree[i]) q.push(i);
  for (let head = 0; head < q.length; head++) {
    for (const b of next[q[head]]) if (--degree[b] === 0) q.push(b);
  }
  return q.length === n ? q : null;
}
console.log(
  topo(4, [
    [0, 1],
    [0, 2],
    [2, 3],
  ]),
);
console.log(
  topo(2, [
    [0, 1],
    [1, 0],
  ]),
);
```

图中存在多条合法拓扑序，示例的顺序来自队列与边遍历规则。第二个输入有向成环，返回 null 表示不存在拓扑序；不能返回已经处理的部分节点并当作完整结果。

## 从示例走向实际使用

先问输出需要什么：依赖执行顺序、是否连通、最优候选还是完整排序。输出目标决定数据结构，而不是先选熟悉模板再改题。

测试图中孤立节点、重复边与环；Top-K 测试 K=0、K 大于数据量及大量相等值。边与重复值的处理应在题目契约中明确。
