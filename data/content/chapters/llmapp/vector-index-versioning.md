## 从具体问题认识向量更新

向量更新至少包含三种不同操作：原文内容变化、更换 embedding 模型、调整索引结构或参数。它们影响的层次不同。文本没变但模型变了，向量空间也可能完全不同，不能只更新查询侧。

把原始文档作为主数据，向量与索引作为带版本的派生数据，才能在更新失败、删除和迁移时恢复一致性。

## 异步任务如何避免旧结果覆盖新内容

文档每次修改产生版本，索引任务携带文档版本、切分版本和 embedding 版本。任务完成发布前重新检查当前版本，旧任务即使更晚完成，也不能覆盖新状态。删除还需要墓碑或等价标记，防止延迟任务把内容重新写回。

文档重新分块后，新块数量和 ID 可能变化，不能只 upsert 新块而留下旧尾块。使用文档级清单记录当前片段集合，受控替换并失效相关缓存。并发读如何看到切换，要按数据库与索引实际一致性设计。

更换 embedding 通常建立新空间、重嵌入、验证再切路由。迁移期间查询使用与索引匹配的编码版本，双写或补偿任务处理增量变更。回退不仅切别名，还需确认旧索引是否继续保持数据新鲜。

## 先区分三类更新

文档正文变化，需要重新解析受影响内容与生成向量；只改 ACL 或标签，可能只更新 payload 但要同步所有过滤缓存；embedding 模型或切块策略变化，意味着整个向量空间或块标识规则变化。即使维度相同，不同 embedding 模型也不保证可直接混查，不能把“同维度”当作兼容协议。

## 主数据与派生索引

主库保存文档版本和状态，outbox 或可靠变更日志驱动索引任务。索引记录带 tenant、docId、docVersion、chunkId、内容 hash、embedding/切块版本和可见状态。幂等键避免重复点，任务处理前后检查期望版本，防止慢的旧任务覆盖新版本。不能仅靠队列按序，因为重试、并发与跨分区可能打乱完成顺序。

## 替换旧块与删除

切块数量变化时，单纯 upsert 新块会留下旧块。可按版本写入新集合或新代际，完成校验后切文档可见版本，再异步清理旧代；读路径只接受当前有效版本。删除用 tombstone 立即影响读取，再重试物理删除，避免缓存/异步延迟泄露已撤回内容。跨主库和向量库无共同事务时要用状态机与补偿，不能假装一次调用全原子。

## 更换 embedding 如何灰度

构建新索引或命名向量，重算历史、双写增量，核对文档数、缺失和版本落后。固定评估集对照新旧召回、权限与 P95，追平增量后切读别名；保留旧索引一段回退窗口。回滚期间新增文档也要可读，双写/回放策略不能只照顾切换那一秒。价格与供应商变化也应记录转换版本。

## 可运行的陈旧任务防护

示例只有目标版本匹配才接受索引结果，旧任务完成会被丢弃；模型版本不匹配进入重建。生产里检查和发布需要原子版本比较，且“写入成功”“搜索可见”“副本同步”可能是不同阶段，要按所用向量数据库确认一致性选项并监控延迟。

## 实践任务与验收

在本地用 Map 模拟主文档库与向量点表，为一个文档生成三个块。提交版本 2 的慢任务，再提交版本 3 的快任务，手动让版本 3 先完成，验证版本 2 无法覆盖可见结果。接着把块数从三变一，检查剩余两个旧块是否仍能从检索读路径进入答案。

加入删除事件后，故意让物理清理失败一次：用户查询应立即受 tombstone 约束，后台能够重试且不会重新激活文档。最后模拟 embedding 从 e1 切到 e2，查询端只访问匹配空间；在切流窗口新写入的文档需在回滚时仍可查。验收输出不是“队列消费成功”，而是每一步的可见版本、孤儿块数、拒绝陈旧任务次数和删除传播状态，这些才是用户会感受到的一致性。

## 把机制放到一条完整路径中

```flow
索引版本更新
记录主数据版本｜文档内容与删除状态
生成派生任务｜绑定切分编码和索引版本
发布前校验｜拒绝陈旧任务并替换旧片段
迁移切换｜验证新空间且保持增量一致
```

## 配套代码：向量更新：文档版本、幂等入库和索引迁移

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

使用本地 JavaScript 模型验证关键不变量；不调用真实数据库、模型或生产服务。实验简化之处与真实系统步骤见正文。

```javascript
const doc={id:'policy',version:3,embedding:'e2'};
function publish(job) {
 if(job.version!==doc.version) return 'stale_document';
 if(job.embedding!==doc.embedding) return 'wrong_space';
 return 'published';
}
console.log(publish({version:2,embedding:'e2'}));
console.log(publish({version:3,embedding:'e1'}));
console.log(publish({version:3,embedding:'e2'}));
```

**文档从十块变成六块，你只 upsert 六个块，哪里会出错？**

四个旧块可能残留并被检索，且新旧版本混合。用文档代际/块清单发布，读路径只读当前版本，切换后按旧版本删除并检查孤儿；失败可重试，不按块序号简单覆盖就算完成。

检查点：孤儿块、版本发布、重试清理。

**更换 embedding 但维度没变，可以保留旧向量直接混用吗？**

通常不能，坐标空间和分布可能变化。需以模型版本隔离并重算文档，查询向量与目标索引匹配；除非有经过验证的兼容映射，否则维度相同不足以证明语义距离有效。

检查点：空间匹配、版本隔离、兼容验证。

**删除政策后异步索引队列延迟五分钟，怎么避免继续回答？**

读路径即时检查主库可见版本/删除标记与 ACL，缓存按版本失效；异步物理删除可后续完成。对删除传播设目标和告警，不能为了搜索延迟让撤回内容继续进入上下文。

检查点：立即可见性、缓存失效、删除监控。
