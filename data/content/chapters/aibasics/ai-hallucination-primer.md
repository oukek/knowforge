## 从具体问题认识幻觉、置信度与 Grounding

模型可能生成语法通顺、结构完整，却缺乏事实依据或违背输入材料的内容，这类现象常被称为幻觉。它不是只有“编造一个不存在的人名”才算，也可能是把正确资料中的条件遗漏、把旧版本政策当成当前政策，或给真实链接附上不受支持的结论。

因此评估答案不能只问“像不像专业回答”，还要逐项检查主张与证据的关系。

## 把事实、推断与未知分开

事实支持可以来自可信文档、数据库查询或可验证计算。Grounding 是把回答建立在这些可检查输入上，但资料存在并不保证模型正确使用。检索返回错误段落、相互矛盾版本或缺少关键条件，生成阶段仍可能得出错误结论。

模型自报“我有九成把握”通常不是经过业务校准的正确率，token 概率也不直接等于事实概率。需要用标注数据分析置信与正确性的关系，并为高风险任务设置外部验证。金额与权限交给确定性系统，引用检查主张是否被对应证据支持。

信息不足时可以回答已知部分、说明缺口并请求必要补充，或拒绝执行不确定动作。只在提示词中写“不知道就说不知道”不足以保证可靠；应用要定义缺证据、冲突和工具失败时的行为，并将这些样本纳入评估。

## 什么情况称为幻觉

**幻觉通常指模型生成看似合理、却没有事实或证据支持的内容。** 例如要求总结一篇文档，模型写出文中不存在的发布日期，甚至附上一个看似真实但无法打开的来源。

先判断错误发生在哪一层：资料本身是否过期、检索是否漏掉正确段落、模型是否误读了证据。引用检索和输出验证可以帮助降低风险，但不能保证零错误；重要事实需要回到可信来源或业务系统核对。

例如回答声称政策允许所有人退款，实际条款只适用于未使用订单；应把遗漏条件标记为事实或证据错误。

模型可能输出不存在的来源、错数字、错误关系或与材料不符的结论。实际讨论先明确错误定义：事实不真实、没被给定证据支持、违反业务规则和没有满足格式，是不同维度。生成很流畅、附有链接或说“我确定”，都不证明内容真实。

有时模型忠实复述了过期文档，业务答案仍错；有时检索结果正确但模型丢了否定条件。两类问题需要不同修复，不能统称“模型不够大”后盲目换模型。

## Grounding 把主张连到可检查事实

Grounding 指让输出依据可信输入或可核验来源。对知识回答，保存具体证据片段、版本与引用关系；对订单动作，查询权威业务系统；对数学和金额，交由确定性程序计算。检索增强能改善事实获取，但不会自动防止错误引用和权限泄漏。

| 检查 | 解决什么 | 不能单独解决 |
|---|---|---|
| 来源存在 | 防编造文档 ID | 来源是否支持主张 |
| 权限与时效 | 当前用户可用证据 | 模型是否正确理解 |
| 程序计算 | 精确公式结果 | 输入事实是否真实 |
| 人工审核 | 复杂判断与兜底 | 无限扩展和零成本 |

模型自报置信度、token 概率和向量相似度各有含义，均需独立校准后才能用于业务决策。

## 拒答不是简单返回不知道

在资料不足、事实冲突、无权限或工具失败时给不同原因，说明还缺什么可验证信息。不要把无权限描述为资源不存在的详细线索泄漏，也不要用拒答率越高越安全作为单一目标。需要同时看回答覆盖与被接受答案的错误率。

提示、检索、规则和评估分别发挥作用。高风险动作仍需授权、审批和幂等，不能因为回答有引用就直接执行。

## 如何排查与验收

保存用户问题、实际上下文、工具事实、主张和来源，定位错误首次出现的环节。建立有答案、无答案、过期、矛盾、数值、跨租户和注入样本，分别报告检索覆盖、主张支持和业务成功。

面试回答应给出一个可复现坏例、故障分层和修复后回归结果。避免宣称“用了 RAG 后完全没有幻觉”，系统只能在明确范围和测试条件下报告表现。

## 把机制放到一条完整路径中

```flow
事实支持检查
拆分主张｜识别回答中的具体事实结论
寻找证据｜关联可信来源与有效版本
检查关系｜区分支持矛盾与未覆盖
限制输出｜说明不确定并阻止无依据动作
```

## 配套代码：幻觉、置信度与 Grounding：为什么答案像真的却不对

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
function decision(verdicts) {
  if (verdicts.includes("contradicted")) return "conflict";
  if (!verdicts.length || verdicts.some((v) => v !== "supported"))
    return "insufficient";
  return "answer";
}
console.log([
  decision(["supported"]),
  decision(["supported", "unknown"]),
  decision(["supported", "contradicted"]),
  decision([]),
]);
```

证据标签是人工构造的输入，函数只执行保守决策规则。真实支持判定有误差，不能因本实验通过而声称自动事实核验可靠。

## 从示例走向实际使用

准备三个版本的材料：完整支持、缺少关键条件和互相矛盾。检查系统是否分别给出有依据回答、有限回答与冲突说明，而不是都生成同样自信的结论。

本课实验只检查已标注的支持与矛盾关系，真实证据验证需要结合来源、时间、权限和主张粒度。
