## 从具体问题认识成本、延迟、缓存与模型路由

模型成本来自实际计量与价格规则，不能仅用“调用了一次”估算。输入、缓存、输出、推理与媒体可能采用不同口径，供应商还可能有折扣或阶梯价。用户购买的额度则是产品定价单位，与上游人民币成本需要分别记账。

例如输入原价每百万 5 元、输出 30 元，上游倍率 0.15，则采购单价分别为 0.75 元和 4.5 元。输入一万、输出两千的这次成本为 0.0075+0.009=0.0165 元，前提是这些 token 没有另行计量项。

## 成本计量、预留与结算

基本公式是各类数量除以计价单位再乘对应单价，最后乘适用倍率。缓存是否包含在总输入内必须核对：若输入总量已含缓存，应先拆非缓存量再按两种价格计算，不能把缓存再次叠加。金额计算采用确定的小数或最小货币单位，避免浮点累计误差。

任务开始可按最大预算预留额度，结束按明确 usage 结算并释放差额。失败尝试可能已产生上游成本，是否向用户收费属于产品规则，需要可解释且一致；缺失 usage 表示未知，不应直接写成零。账本保存任务、尝试、价格版本与原始计量。

资源包毛利取决于用户实际消耗结构。相同额度若全用于高输出任务，采购成本可能与纯输入任务不同。用代表性比例做预测，并分别给出输入密集、输出密集与缓存命中变化的敏感性；不要把一个示例比例说成行业固定规律。

## 把机制放到一条完整路径中

```flow
任务成本核算
读取价格版本｜确认币种单位与采购倍率
预算准入｜预留用户额度并限制任务预算
核对计量｜区分输入缓存输出与未知项
结算审计｜保存实际成本扣费与释放差额
```

## 配套代码：成本、延迟、缓存与模型路由：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

def cost(input_tokens,output_tokens,input_per_million,output_per_million):
    return (input_tokens*input_per_million+output_tokens*output_per_million)/1_000_000
show(round(cost(1000,500,2,8),6))
```

2 和 8 是自行设定的每百万 token 教学价格，不对应任何真实模型，也未包含缓存、工具和税费。生产估算应使用当前配置、调用实际 usage 与供应商结算规则，并在并发调用前预留预算。

## 从示例走向实际使用

建立成本报表区分收入、已消耗额度、上游调用成本和其他运营费用。毛利率为收入减直接成本后除以收入，不能与加价率混用。

课内双价格函数仅覆盖普通输入输出，接真实供应商时补齐计量语义和失败尝试。价格版本必须随任务落账，避免日后改价导致历史重算失真。
