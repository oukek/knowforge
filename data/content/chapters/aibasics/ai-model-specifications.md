## 从具体问题认识读懂模型规格

模型规格通常包含参数量、结构、上下文窗口、模态、精度与部署要求。参数量只是其中一个维度，不能独自决定质量、速度或显存。两个都标为 7B 的模型，也可能因训练数据、结构和推理配置表现不同。

阅读规格时应先问这些数字描述什么：总参数还是每 token 激活参数，最大输入还是输入输出共同预算，权重文件大小还是完整运行内存。

## Dense、MoE 与运行资源

Dense 模型通常在每次相应计算中使用其稠密网络路径；MoE 通过路由选择部分专家参与，因此总参数与单次激活参数不同。激活较少可能降低部分计算量，但所有权重的存放、跨设备通信与路由开销仍可能很大，不能直接按激活参数估算全部显存。

上下文窗口表示可处理输入与生成相关序列的容量边界，具体计量由模型与服务约定。更长窗口不保证模型能同样可靠地利用每个位置的信息，也不代表输出上限同样长。长上下文还增加缓存与计算压力，影响并发和延迟。

模型卡应说明任务、语言、训练或评估范围、许可与使用限制。部署规格还要区分权重、KV 缓存、激活、运行时与并发余量。纸面上刚好放得下权重，不代表能够稳定服务真实请求。

## 一个模型规格包含多条轴

**模型规格表中的数字分别回答不同问题。** 参数量描述模型中可学习数值的规模；上下文窗口限制一次处理的序列预算；最大输出长度约束生成部分。大窗口并不意味着模型会长期保存聊天，也不保证它能准确使用所有输入。

例如两个模型都能接收长文，仍需在自己的抽取和问答数据上比较正确率、响应时间、价格与支持能力。MoE 等架构可能每次只激活部分参数，因此不能只看总参数量就推断每次运行成本或任务质量。

例如一次请求既要放入资料又要生成答案，两部分通常都要计入上下文预算，具体以模型接口规则为准。

参数量是可学习数值的数量，B 通常表示十亿量级；上下文窗口是输入与生成可使用序列的容量约束，具体计量与接口有关；输出上限限制生成长度。参数量不是文档容量，窗口长度不是长期记忆大小，输出上限也不等于全部预算。

架构、训练数据、目标、后训练和推理设置共同影响能力。不能因为一个模型参数多就断言在自己的抽取或代码任务上更好，也不能因为窗口大就忽略证据选择。

## Dense 与 MoE 的基本区别

稠密模型通常让输入经过相应层的大部分参数；混合专家 MoE 在某些模块用路由选择部分专家参与计算。总参数与每 token 激活参数因此可能不同。路由、共享模块、专家通信及负载均衡都会影响真实性能。

| 规格 | 能帮助估算 | 不能单独决定 |
|---|---|---|
| 总参数 | 权重存储规模方向 | 完整训练/推理内存 |
| 激活参数 | 部分计算量方向 | 真实延迟和并行效率 |
| KV 布局 | 长会话缓存开销 | 所有工作区占用 |
| 上下文长度 | 可接收长度范围 | 长文任务准确率 |

MoE 每步只用部分专家，不代表只需加载对应激活参数的全部部署内存；具体 offload、分片与服务方式要测量。

## 读模型卡要找哪些字段

先核对名称和版本、许可、预期任务、输入模态与模板，再看评估方法、长度约束、硬件与限制。开源代码、开放权重和完整公开训练数据不是同一含义，使用与商用许可需要查看具体条款，不能仅看可下载就推定所有用途都允许。

服务平台还可能改变默认采样、推理预算或工具支持。记录实际 API 版本和配置，不把同名模型在两个平台的行为当成理所当然完全一致。

## 反例与验证方法

小模型在受约束的分类任务上可能足够，较强模型在复杂推理或长工具轨迹上才显优势。使用固定任务切片、相同输入事实和预算比较质量、时延和总成本；不要跨不同测试条件引用排行榜作结论。

学习时尝试从一份规格表画出“能力、权重存储、缓存、接口限制”四栏，分别写出还缺什么证据。能指出未知项，比给出虚假的完整容量数字更专业。

## 把机制放到一条完整路径中

```flow
阅读模型规格
识别数字｜区分总参数激活参数与窗口
核对能力｜语言模态工具与输出契约
估算资源｜权重缓存激活及并发余量
实测选择｜在相同任务硬件与版本下比较
```

  return (parameters * bytesPerParameter) / 1e9;

function canFit(input, outputReserve, window) {

## 从示例走向实际使用

制作选型表时分列质量、首响应、总耗时、峰值资源、许可和协议能力，不把一个总分掩盖硬约束。用自己的输入长度与并发进行测量。

课内资源估算是数量级模型，实际内存还包含框架与格式开销。具体模型版本和硬件结果应单独记录，避免用系列名称替代可复现配置。
