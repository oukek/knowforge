## 从具体问题认识小程序长列表与虚拟滚动

长列表的困难不仅是数组里有很多数据，而是同时存在太多可见或不可见的界面节点、图片和更新任务。分页减少一次获取的数据量；虚拟列表减少同时创建的视图节点数量，两者解决不同层面的成本。

假设一万条记录中屏幕一次只能看见十条，虚拟列表只渲染视口附近的一小段，再用占位空间保持滚动区域总高度。用户看到的是连续列表，实际节点却可以保持在较小范围。

## 可见窗口怎样映射到数据索引

固定行高时，滚动距离除以行高可估算起始索引，视口高度除以行高可估算可见数量。额外渲染前后缓冲区能减少快速滚动时的空白，但缓冲越大，节点与图片成本也越高。顶部占位高度对应前面未渲染记录的总高度，底部同理。

动态行高更复杂：每条内容长度和图片加载状态都可能改变高度，需要测量缓存、累计高度与查找可见范围的策略。图片出现后若改变前方高度，会推动当前阅读位置，因此应预留尺寸或按锚点补偿滚动。不能把固定行高公式直接用于任意内容。

节点复用时，组件实例可能先显示 A 记录，再显示 B 记录。输入状态、图片请求和选中状态必须与业务 ID 关联，避免旧实例状态泄漏到新记录。数据层还要处理分页重复、删除插入和请求乱序，否则视图优化以后仍会出现内容跳动与重复。

## 把机制放到一条完整路径中

```flow
长列表窗口
滚动位置｜得到视口与当前偏移
范围计算｜确定可见索引和缓冲区
局部渲染｜复用节点并保持占位高度
尺寸校正｜按测量与锚点修正位置
```

## 配套代码：定高虚拟列表的窗口计算

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

用视口、行高和 overscan 算出需要渲染的索引范围。

```javascript
function windowRange(scrollTop, viewport, itemHeight, count, overscan) {
  return {
    start: Math.max(0, Math.floor(scrollTop/itemHeight)-overscan),
    end: Math.min(count, Math.ceil((scrollTop+viewport)/itemHeight)+overscan)
  };
}
console.log(windowRange(200, 300, 50, 1000, 2));
console.log(windowRange(0, 300, 50, 1000, 2));
```

end 是排除端点，overscan 向两侧扩展并夹到合法范围。该公式适用于定高；动态高度需要测量缓存、前缀和和滚动锚点处理。

## 从示例走向实际使用

先测节点数、图片内存和更新大小，确认瓶颈再引入虚拟化。普通短列表引入复杂窗口管理，可能增加维护成本而没有可感知收益。

测试快速滑动、回到顶部、动态插入、图片加载后高度变化和滚动中切换筛选。记录业务 ID 与可见范围，比只看“页面还能滚动”更能发现复用错误。
