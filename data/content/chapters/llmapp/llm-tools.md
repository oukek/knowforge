## 从具体问题认识工具调用、参数验证与权限执行

工具调用是模型提出一个带参数的操作请求，应用检查后执行，并把结果交回模型。模型本身没有因为生成了函数名就获得数据库、文件或支付权限。工具层相当于把概率生成连接到确定性系统的一道受控接口。

查询课程与删除课程即使参数都只有一个 ID，风险也完全不同。设计工具时必须同时说明输入输出和允许产生的效果。

## 从工具提议到受控执行

工具描述说明何时使用，输入 Schema 限制形状，业务校验确认参数含义。例如 lessonId 是字符串还不够，服务端需要检查课程存在、当前用户有权限，以及动作是否处于允许状态。身份与租户来自可信会话，不接受模型自行声明。

执行前建立调用 ID、截止时间和资源预算。读操作可按策略重试；写操作需要幂等键、冲突检测或确认流程。网络超时可能发生在对方已成功之后，不能仅凭没有收到响应就再次扣款。结果应区分成功、业务拒绝、暂时失败与状态未知。

工具返回内容也可能含有不可信指令，例如网页里要求“忽略规则”。返回值只作为数据处理，不能变成新权限。大型结果可裁剪并提供受控分页或引用，但保留判断所需事实，避免裁掉错误状态只留下看似成功的片段。

## 把机制放到一条完整路径中

```flow
工具调用生命周期
模型提议｜给出工具名参数与调用身份
服务端验证｜检查结构权限预算和确认状态
受控执行｜处理幂等取消与明确结果
返回数据｜把结果交回当前任务上下文
```

## 配套代码：工具调用、参数验证与权限执行：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

tools={'read_article'}
request={'name':'delete_article','id':'other'}
show(request['name'] in tools)
show('rejected' if request['name'] not in tools else 'validate args')
```

工具名白名单阻止未知动作，但允许的工具仍需参数和资源授权。这个模型没有执行删除或任何网络请求；真正执行器应该将检查、确认和结果审计放在受控服务端。

## 从示例走向实际使用

把工具作为独立 API 测试：非法 ID、跨用户资源、重复提交、超时后重试和恶意返回内容都要覆盖。模型选择正确工具，只是整个执行链中的一个环节。

课内白名单说明允许集合，真实实现还需要逐次授权与参数校验；仅检查函数名无法保护资源归属。
