## 从具体问题认识模型接入、SDK 适配层与确定性替身

模型适配层把业务需要的能力与不同服务商协议分开。业务代码希望得到“完成结果、增量事件、使用量和错误类别”，不应该在每个页面或任务里解析各家不同的字段。适配层提供统一入口，同时保留无法统一的能力差异。

例如某服务支持工具调用与结构化输出，另一家只支持普通文本。它们都能返回字符串，并不意味着可以在所有任务上互相替换。

## 内部契约与确定性替身

先定义内部请求：任务身份、输入消息、输出契约、工具集合、预算与取消信号；再定义结果：完成、拒绝、截断、工具提议或失败。每个适配器负责字段映射、流事件转换和错误归类，而不是把原始响应对象直接交给业务层。

能力表声明支持的模态、上下文、工具、Schema 与 usage 细节，路由先筛能力再选服务。未知字段或不支持参数应显式处理，不要静默删除后让业务误以为约束仍生效。供应商原始请求 ID 可保留用于诊断，敏感头与密钥则不进入普通日志。

FakeModel 返回固定结果，适合测试状态机、计费与错误路径；协议契约测试使用受控 HTTP 服务模拟真实格式；小规模真实调用评估质量和兼容性。这三层证据不同，不能用替身测试通过宣称真实模型效果已验证。

## 把机制放到一条完整路径中

```flow
模型适配
定义内部契约｜任务输入结果事件与预算
声明能力｜筛掉不满足任务要求的模型
协议转换｜映射请求流错误和使用量
分层验证｜替身契约与真实任务分别测试
```

## 配套代码：模型接入、SDK 适配层与确定性替身：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

class FakeModel:
    def complete(self,prompt):
        return {'text':'fixed:'+prompt,'usage':{'input':3,'output':2}}
result=FakeModel().complete('hello')
show(result['text'])
show(sum(result['usage'].values()))
```

FakeModel 是确定性测试替身，不是 AI 推理。它让状态、日志和结果转换可重复验证；真实 SDK 适配器需要凭据、网络、超时和供应商契约测试，模型质量必须由真实任务评估判断。

## 从示例走向实际使用

为每个适配器准备成功、限流、超时、拒绝、截断和异常 usage 样本。版本升级后重放这些样本，再进行必要的真实服务验证。

课内替身展示依赖接口可替换。真正接入前先固定业务契约，避免为了某家 SDK 的便利把内部数据结构全部绑定到它。
