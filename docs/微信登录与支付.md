# 微信登录与资源包购买

本实现参考 t-box 的公众号授权和微信支付 API v3 链路，使用面试项目自己的用户、会话与额度账本，不共享 t-box 数据或密钥。数据库新增普通关联字段与索引，没有外键。

## 配置与开通

在管理后台 → **微信接入** 配置，微信登录和微信支付分 Tab 管理。页面默认展示摘要，点击“编辑配置”打开弹窗，保存后即时生效，无需重启。现在不再读取 `WECHAT_*` 环境变量；之前填在环境变量中的内容需由管理员重新录入后台，确认可用后删除旧变量。

服务器只保留现有的 `AI_ENCRYPTION_KEY` 主密钥：32 字节、跨部署保持不变，与数据库分开安全备份。它复用于 AI 凭据及微信配置的 AES-256-GCM 加密。**配置整体（含 AppID、URL、商户信息、密钥与证书）均以密文存入数据库**，主密钥不存入数据库。缺少主密钥时不能保存，密文无法解密时不允许覆盖原值。

- 微信登录弹窗：填写具有网页授权权限的公众号 AppID、AppSecret，以及前端／API HTTPS 源地址；域名不带路径、尾部斜杠。在公众号后台配置网页授权域名为 API 域名（默认 `knowforge-api.ookew.com`）。
- 微信支付弹窗：复用同一公众号 AppID，填写商户号、商户证书序列号、商户私钥 PEM、微信支付公钥／平台证书 PEM、对应公钥 ID／平台证书序列号，以及 32 字节 API v3 密钥。
- 商户平台需开通 JSAPI 支付，并绑定上述公众号 AppID；JSAPI 支付授权目录为前端购买页所在目录，默认 `https://knowforge.ookew.com/`。
- AppSecret、商户私钥、微信支付公钥／证书、API v3 密钥不回显；编辑时留空保留。更换公众号须重新填写 AppSecret，更换商户须重新填写对应商户私钥及 API v3 密钥。开启微信支付时校验 RSA 密钥、商户标识与密钥长度。
- 后台展示授权回调和支付通知地址。反向代理保留通知原始正文与 `Wechatpay-*` 请求头，不对通知要求用户登录。
- 管理接口要求管理员、有效会话与 CSRF，并使用版本号防止并发编辑覆盖。审计只记录操作人、版本号和开关状态，不记录配置正文、密钥或密文。

未配置登录或支付时，对应按钮明确显示不可用，不模拟成功。没有真实商户凭据的本地测试仅使用注入的测试网关，不能代替生产小额实付验收。

## 登录行为

公开 `/api/auth/register` 返回 410；新用户通过微信授权自动创建账号，不赠送可消费额度。后端只返回授权链接和登录流程凭据，前端本地绘制五分钟有效的二维码，微信内直接进入授权。授权完成后手机显示确认页，用户点击确认后，持有独立轮询密钥的原设备才能获取 HttpOnly 会话。state、授权票据和轮询票据一次性使用；OAuth token 不返回前端。

旧账号仍通过“已有账号登录”访问原有学习记录；同一微信 AppID + openid 对应同一学习账号。当前不会根据昵称、用户名或 UnionID 自动合并旧账号，防止误合并学习与付费数据。微信账号不显示改密码表单。

微信内打开未登录页面时自动发起 OAuth，无需点击本站登录按钮；授权后用仅发起浏览器持有的 HttpOnly 临时凭据核对原流程，核对成功自动完成本站确认，返回后以原标签页保存的流程密钥领取会话并回到原页面。首次微信授权仍遵循微信自己的授权界面。临时凭据五分钟有效且绑定流程，不匹配或未携带时仍显示确认登录页。桌面扫码登录保留手机确认，不会因访问同一授权链接而自动批准其他设备。手机端确认页和成功页使用与项目一致的独立页面，无需加载前端应用。确认页使用 `Referrer-Policy: strict-origin`，避免普通表单 POST 在 `no-referrer` 下发送 `Origin: null` 而被来源校验拦截；不放开全局 `null` 或外部来源。失败时显示重试入口，不循环跳转；配置未开放时不自动发起。

出现 `redirect_uri 域名与后台配置不一致`（10003）时，检查 **当前 AppID 对应的微信公众号后台 → 公众号设置 → 功能设置 → 网页授权域名**。本项目登录回调为 `<API HTTPS 地址>/api/auth/wechat/callback`，支付授权回调为 `<API HTTPS 地址>/api/payments/wechat/oauth/callback`，因此默认网页授权域名填 `knowforge-api.ookew.com`，不带协议或路径；如已更换 API 域名，以项目后台“微信接入 → 微信登录”中的 API 地址为准。前端默认域名 `knowforge.ookew.com` 配在“JS 接口安全域名”，两者作用不同。项目后台登录配置摘要与编辑弹窗会显示应填的网页授权域名。配置与 AppID 必须属于同一个公众号，微信后台如要求域名校验文件，应按该页面提示完成校验。

## 支付与额度

顶栏常驻“购买资源包”按钮，可在当前学习页面打开选购弹窗；左侧“资源包与额度”（`/credits`）默认展示资源包，切换“额度与订单”查看余额、流水和订单。AI 额度栏和额度不足提示也提供购买入口。点击购买统一传 `mode: "jsapi"`。后端先创建本站支付页链接，二维码由前端本地生成。微信外展示二维码，微信内自动前往该链接。扫码页面无需学习账号登录，先使用当前微信进行 `snsapi_base` OAuth 授权，再初始化官方 JSSDK 并调用 `wx.chooseWXPay`。同一学习账号自动调起；微信身份与下单账号不一致时明确展示接收账号，点击确认后才可为对方付款。额度始终发放给下单账号，不会把扫码者登录成该账号。

扫码页入口为 `https://<前端域名>/pay/wechat#ticket=...`，票据只放在片段中，进入后移出地址栏并保存在当前标签页的 sessionStorage；数据库只保存入口票据、OAuth state 和浏览器授权密钥的 SHA-256 摘要。扫码授权绑定该订单与当前标签页密钥，OAuth state 一次性消费；付款人按订单锁定，不能由前端传入 OpenID 或通过 URL 标志跳过跨账号确认。支付链接随订单到期。更换扫码微信后不能复用另一微信已经创建的预支付。

公众号需配置：API 域名为网页授权域名、前端域名为 **JS 接口安全域名**、服务器出口 IP 加入接口 IP 白名单。商户 JSAPI 支付授权目录配置前端根目录（包含 `/pay/wechat`）。后台使用公众号 stable_token 获取并缓存 jsapi_ticket，为完整、不带片段的支付页 URL 生成 SHA-1 JSSDK 签名；只允许本站支付页签名，不返回 ticket 或 AppSecret。iOS 使用最初进入页面的 URL 签名。SDK 就绪后自动调用 `wx.chooseWXPay`，取消和加载失败可重试原订单；付款结果仍由服务端验签／查单确认。

历史已创建的 Native 订单继续使用原支付码，不切换通道；新订单不再调用 Native 下单。二维码绘制仍完全在前端，后端没有 `qrcode` 依赖。本次未接入 H5 跳转、APP 原生支付或在线退款。

下单在服务端校验发布状态和版本，价格按整数分计算。订单固定商品版本、价格、额度及赠送额度；同一用户、同一版本存在有效待付订单时复用。每次请求有幂等标识，网络失败重试不会直接生成新订单。

只有经过 RSA 验签的查单结果或已验签、AES-GCM 解密的支付通知，且商户号、AppID、金额、币种与订单一致，才会在同一数据库事务中写入支付流水、额度批次、额度事件和审计。微信交易号唯一，重复通知不会重复发放。有效期从微信确认付款时间起算；购买额度和赠送额度分别形成批次。

支付弹窗定期查单，失败后可以手动核对。“我的支付订单”展示最近 50 笔，支持重新打开继续支付或核对。前端支付成功提示本身不会发额度。订单 15 分钟有效，过期订单在查单时先核对付款结果，再调用微信关单；通知仍可补确认，避免漏账。离线时依赖微信通知重试，管理员应对照商户平台账单核查异常订单。

支付接续链接创建时只生成本地订单；扫码完成后才向微信发起 JSAPI 下单。因此查单接口返回**已验签的** HTTP 404 / `ORDER_NOT_EXIST` 时视为尚未支付，不显示网关故障、不发额度；这类订单到期后直接关闭本地订单，无需向微信关单。其他 404、签名失败、权限或网络错误仍按失败处理。支付弹窗查单失败会保留二维码并继续轮询，网络恢复后清除提示。

微信网关故障在服务端标准错误日志中以 `[wechat.pay.error]` 输出结构化记录：`errorId`、请求方法与接口路径、发生阶段（`sign` / `network` / `read` / `verify` / `response` / `parse`）、HTTP 状态、微信 `wechatCode`、参数 `field`、微信 `requestId` 以及是否验签通过。验签失败另记预期与实际公钥标识；网络异常记网络错误码。`wechatCode` 在验签失败时仅用于排障，不会用于改变订单状态。日志不输出 Authorization、签名、密钥、OpenID、票据、请求正文或微信响应正文。微信路由内其他服务错误以 `[wechat.route.error]` 记录。页面会显示同一个“错误编号”，可在后端日志中检索该编号定位。无需额外环境变量。

每次保存生成独立的加密配置版本。新登录流程和新订单绑定发起时的版本；升级前没有版本绑定的订单使用当前后台配置核对，录入时须保持原商户身份。关闭新登录／新购买后，存量流程仍可完成，存量订单仍可核对。商户或公众号变更后按绑定身份处理存量数据；同身份的最新凭据用于查单与授权，支付通知按验签公钥 ID 尝试解密配置版本。运行时查找最近 200 个版本的轮换凭据；历史密文仍保留，不可直接清理有未结订单关联的配置版本。更换主密钥需先做独立的密文重加密迁移，直接改环境变量会造成解密失败。

测试中的 `authOptions.allowRegistration` 只用于保留历史账号密码行为的回归覆盖，入口脚本和环境变量均不启用该选项。

官方协议：[查单错误码](https://pay.wechatpay.cn/doc/v3/merchant/4012791900)、[错误响应与 Request-ID](https://pay.wechatpay.cn/doc/v3/merchant/4012081709)、[公众号网页授权](https://developers.weixin.qq.com/doc/offiaccount/OA_Web_Apps/Wechat_webpage_authorization.html)、[JSAPI 开发指引](https://pay.wechatpay.cn/doc/v3/merchant/4012791870)、[API v3 签名与验签](https://pay.wechatpay.cn/doc/v3/merchant/4012365342)。

## 头像与昵称

所有账号首次建立个人资料时从 16 个内置卡通头像中随机分配一个，旧账号缺少头像时在登录／读取资料时自动补齐并持久保存。头像使用随前端发布的 SVG 资源，不依赖微信头像地址。个人中心默认显示资料摘要，点击“修改资料”在弹窗中选择头像和修改昵称；再次微信登录不会覆盖用户的头像选择或昵称。头像更新仅接受内置 ID，与昵称在同一事务中保存。

## 界面主题

全站默认使用黑白石墨，另内置石墨蓝、灰紫色、暖灰琥珀。个人中心的“界面主题 → 切换主题”与登录页的“切换主题”均通过弹窗选择；点击即时预览，保存后生效，取消或关闭弹窗恢复已保存配色。偏好保存在当前浏览器的 `knowforge.theme`，刷新、退出登录后仍沿用，同浏览器其他标签页会同步；不同设备各自选择，不写入账号数据库。缺失或不支持的偏好回退黑白石墨，不增加环境变量。

配色定义集中在 `shared/themes.mjs`，前后端共用。页面主要背景、按钮、导航、文字、边框与弹层使用 CSS 主题变量，成功、错误、警告等语义状态保留独立颜色。微信扫码登录链接仅传内置主题 ID，确认页与完成页保持该配色；主题参数不参与登录授权，仍须原有流程票据与设备密钥。
