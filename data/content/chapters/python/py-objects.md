## 变量更像名字，不是装着完整对象的小盒子
对象有身份、类型和值。赋值将名字绑定到对象，另一个名字可以指向同一对象。列表是可变对象，可以原地增删元素；整数和字符串等不可变对象的“变化”通常产生新值并重新绑定名字。理解名字与对象的分离，才能解释函数参数和浅拷贝。

is 比较对象身份，== 按类型规则比较值。两个内容相同的列表可以 == 为真而 is 为假；小整数缓存与字符串驻留是实现细节，不应依赖它们判断业务相等。
## 名字绑定、修改对象和重新赋值是三件不同的事

把 `a = [1, 2]` 想成创建一个列表对象，并让名字 a 指向它。接着执行 `b = a`，只是增加另一个指向同一列表的名字，不会复制列表。`b.append(3)` 改的是这个共享对象；`b = [9]` 则把 b 改为指向新对象，a 仍指向原来的列表。沿着引用关系画箭头，比背“传值还是传引用”更准确。

Python 的函数参数同样建立局部名字绑定。函数可以通过参数访问并修改可变对象，但仅给参数重新赋值不会把调用方的名字也改掉。不可变对象如整数和字符串不能原地改变，`n += 1` 对整数通常意味着计算新值再重新绑定 n；列表的 `+=` 则可能原地扩展，所以相似语法不能推出完全相同的共享行为。

```python
def update(items, count):
    items.append("new")
    count = count + 1
    return count

items = ["old"]
count = 1
next_count = update(items, count)
print(items, count, next_count)
```

## 相等、身份与复制分别回答什么问题

`==` 比较对象的值是否按其类型规则相等，`is` 判断是否为同一个对象。两个分别创建的列表可以内容相同但身份不同；不要拿整数或短字符串偶然复用的内存行为推导业务规则。None 是单例，`is None` 则是合适的身份判断。

浅复制只复制最外层容器，内部对象仍可能共享。深复制会递归处理对象图，但复制数据库连接、文件句柄等资源没有普遍正确的含义，类也可能自定义复制行为。数据更新优先考虑清晰的所有权：只读共享、明确原地修改，或复制需要改变的那部分。

```python
original = {"tags": ["python"]}
copy = original.copy()
copy["tags"].append("backend")
print(original["tags"])
print(original == copy, original is copy)
```

内存回收则关注对象是否仍可达。CPython 常用引用计数并辅以循环垃圾回收，但何时释放不是所有 Python 实现统一承诺。文件、锁、连接应由 with 等显式生命周期管理，而不是等待引用计数碰巧归零。

## 用代码画出共享关系
```python
original = {"tags": ["python"]}
alias = original
shallow = original.copy()
shallow["tags"].append("go")
print(original)
print(alias is original)
print(shallow is original)
shallow["tags"] = ["new"]
print(original["tags"])
```
第一次 append 修改的是两份字典仍共同引用的内部列表，原对象因此变化。随后给 shallow 的 tags 赋新列表，只改变 shallow 这个字典中的引用，不会把 original 的字段也换掉。把“修改对象”与“改变引用”分开描述，就不必把行为记成口诀。
```flow
浅拷贝之后
original 名字｜指向原字典
shallow 名字｜指向新字典
两个 tags 字段｜最初仍指向同一列表
append 修改列表｜双方都观察到新元素
替换一方字段｜只让该字段指向另一列表
```
## 参数传递仍然是绑定
函数形参在调用时绑定到传入对象。函数里 items.append(...) 修改共享列表，调用者可见；执行 items=[] 只是将局部形参重新绑定。不能笼统称为“列表按引用，整数按值”，规则始终是对象与绑定，只是不同类型支持不同操作。

可变默认参数在函数定义时创建，不会每次调用都新建。需要独立容器时用 None 哨兵再在函数内部创建。类变量、模块级配置和缓存也有共享生命周期，多个用户的数据污染常来自这些地方。
## 深拷贝也有边界
copy.deepcopy 尝试递归复制并处理循环与共享引用，但文件、连接、锁和外部资源不是复制一下就获得新资源。业务应明确哪些对象属于谁、哪些共享只读、哪些允许修改，必要时用不可变结构或只复制变更路径。

测试复制后修改嵌套字段、同一个子对象出现两次、循环引用和资源对象。对复杂配置，不要拿 JSON 序列化代替所有拷贝：它有类型与编码限制，会改变数据语义。
