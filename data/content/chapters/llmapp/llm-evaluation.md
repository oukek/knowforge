## 从具体问题认识评估集、Recall@k、答案质量与回归

评估不是问模型“你觉得自己答得好吗”，而是把应用目标转成可以反复检查的样本、标准和指标。知识问答、信息抽取与工具执行的成功条件不同：问答要有事实支持，抽取要字段正确，工具任务还要确认实际状态变化。

假设系统能回答大部分产品介绍，却经常答错退款期限，平均分可能很好看，但关键业务风险仍然很高。因此评估既需要总体指标，也需要按任务、难度和风险分组。

## 样本、评分器与统计口径

先从真实任务中选代表性样本，记录输入、可用证据、预期行为和允许变化。开放回答不必只有一句标准答案，可以列必需事实、不可接受错误与允许的表达差异。训练或提示调试用的样本与最终验收集分开，防止反复针对测试题优化造成虚高。

评分器可以是精确比较、结构校验、程序测试、人工审核或模型评审。能用程序确认的数量、权限与工具状态优先用程序；语义评审要用锚点示例校准，抽查一致性与偏差。评审模型同意答案不构成独立事实证据。

检索 Recall@k 是前 k 项中找回的相关项数除以标注相关项数。它依赖标注范围：漏标相关资料会影响解释，没有相关资料的样本不宜混入相同分母，应单列无答案行为。比较版本时保留配对样本和失败明细，小样本的一点分数差可能只是波动。

## 把机制放到一条完整路径中

```flow
可复现评估
定义成功｜拆成事实结构行为和边界
固定样本｜保留证据并隔离验收集
执行评分｜确定性检查与校准后的评审
分析切片｜比较质量成本延迟与失败类型
```

## 配套代码：评估集、Recall@k、答案质量与回归：最小可验证示例

下面代码在课内Python运行区执行；浏览器环境与本机CPython的网络、文件和原生扩展能力不同。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

def recall(retrieved,relevant):
    return len(set(retrieved)&set(relevant))/len(set(relevant)) if relevant else 0.0
show(recall(['a','b'],['a','c']))
show(recall(['a','a'],['a']))
```

集合消除重复，相关项分母固定，避免重复命中抬高召回。本课将没有相关标注的情况定义为 0，但真实评估应单独标记无答案样本或未定义指标；答案质量和权限需要其他测试。

## 从示例走向实际使用

为应用建立正常、无答案、权限不足、冲突资料、工具失败等切片，同时记录延迟和成本。一个版本质量略高但失败成本大幅增加，是否发布需要结合业务目标判断。

课内召回函数演示集合口径，其中空标注返回零是代码约定；正式报表应把这类样本单独统计，避免误解为检索失败。
