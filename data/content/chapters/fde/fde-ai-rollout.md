## 从具体问题认识AI 上线交付

AI 系统离线评估通过后，还要验证真实流量、数据分布和用户行为。影子运行与灰度发布降低一次性暴露范围，但它们不是免检通道：影子流量如果真的执行退款，仍然会造成真实业务效果。

发布设计应先隔离副作用，再决定哪些用户进入新版本以及何时扩大。

## 影子比较、灰度分桶与回退门槛

影子模式复制允许使用的输入，让新系统计算建议而不提交真实写入；工具可以使用只读权限或隔离替身。记录与当前系统结果的差异，注意复制敏感数据仍需符合访问范围。

灰度按稳定用户或租户分桶，避免同一会话反复跳版本导致状态不兼容。观察窗口要覆盖足够任务和关键场景，不能仅凭几分钟没有报错就扩大。阈值根据风险、基线和业务目标确定，不存在所有系统通用的样本数。

越权、重复扣款等严重不变量失败可立即停止，而质量与成本波动需要结合样本判断。熔断由确定性系统执行，不依赖模型自己承认出错。回退方案包括路由、兼容状态和未完成任务处理。

## Demo 通过后仍缺哪一段

FDE 的交付目标是进入真实工作流并产生可测价值，而不是把聊天界面放到客户服务器。先确认谁使用、替代哪一步、现有成本、错误损失、人工接管和验收责任人。技术指标要连到业务事件：节省处理时间是否包含审核，建议采纳后是否导致返工，自动完成是否真的完成。

上线前固定数据权限、工具契约和失败路径。客户系统的身份、审批、网络与发布流程可能比模型选择更决定落地效果，需要与业务方共同验证，不能以离线平均分替代接入验收。

## 影子流量必须避免真实副作用

Shadow 把脱敏且获准的实际请求复制给新方案，用户仍使用旧方案。新方案的写工具应换成 fake、dry-run 或受约束的只读适配器，不能因为“结果不展示”就允许真的发信退款。影子结果用于比较任务轨迹、候选动作、延迟和成本。

影子也会产生模型调用费用并可能接触敏感数据，必须遵守相同授权与保留策略。输入应尽量保持可比，但不要为复制流量而复制生产秘密或跳过访问限制。

## 灰度分桶和观测窗口

按稳定主体或任务标识分桶，使同一会话在观察窗口内保持方案一致，避免模型状态和提示版本来回切换。跨租户业务可按租户逐步开启，确保代表性和容量上限。分桶哈希用于稳定分配，不是安全随机或匿名化手段。

| 门槛 | 例子 | 决策特点 |
|---|---|---|
| 硬性安全 | 越权、重复付款 | 出现即阻断或回滚 |
| 质量 | 任务成功与返工 | 看切片、样本量和不确定性 |
| 性能成本 | P95、每成功任务成本 | 与预算及基线比较 |
| 运营 | 人工接管、报警可处理性 | 确保有人能接住失败 |

阈值和最少样本量由任务风险决定，课程代码里的数字只是练习契约。

## 熔断应独立于模型决策

后端开关可以关闭写工具、限制租户、切换只读建议或回退旧版本。不能要求故障模型自己判断是否应停止。预算、授权和重复副作用门槛在宿主强制执行。关闭新模型不一定回滚已提交业务，需要单独查账、补偿或人工处理。

发布版本应包含提示、模型、工具 schema、数据索引与配置的兼容组合。只回退 prompt 而保留不兼容 schema，可能制造第二次事故。数据库迁移与已持久状态要设计向后兼容或明确恢复策略。

## 交付与事故演练

上线前演练模型不可用、下游超时、权限撤回、索引更新错误和已提交但响应丢失。确认一线能查任务及操作 ID，知道谁批准回滚、谁核对业务影响。运行手册应写具体步骤、观察信号和恢复判据，而不是“联系研发”。

上线后对比业务基线，记录总人工时间、返工、客户满意度、风险事件和总成本。只有收益在真实流程中成立且故障可处理，交付才算完成；灰度百分比达到 100% 只是发布状态。

## 把机制放到一条完整路径中

```flow
AI 灰度发布
影子验证｜隔离副作用并比较真实输入
稳定分桶｜少量用户进入固定版本
监控门槛｜质量成本与安全分别判断
扩大或回退｜处理存量任务和状态兼容
```

## 配套代码：AI 上线交付：影子流量、灰度、熔断与业务验收

下面代码在课内Python运行区执行；浏览器环境与本机CPython的网络、文件和原生扩展能力不同。



```python
def decide(m):
    if m['unauthorized'] or m['duplicates']:
        return 'rollback'
    if m['samples'] < 100:
        return 'hold'
    if m['success_rate'] < 0.9 or m['cost_per_success'] > 3:
        return 'rollback'
    return 'expand'

base=dict(samples=120,success_rate=0.95,cost_per_success=2,unauthorized=0,duplicates=0)
print(decide({**base,'samples':20}))
print(decide({**base,'samples':1,'unauthorized':1}))
print(decide(base))
```

先检查硬性违规，再判断样本和本题质量成本门槛。少样本不能掩盖已发生的越权；代码不执行发布，100、0.9、3 都是练习约定。

## 从示例走向实际使用

在发布前演练一次撤回，确认旧版本能处理当前状态或有明确存量分流。业务验收同时看采纳、正确率、人工复核负担和用户等待。

课内 100 个样本与 0.9 成功率是演示门槛，不能作为未经测量的上线标准；安全失败优先于样本量判断。
