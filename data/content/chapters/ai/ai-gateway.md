## 从具体问题认识AI 网关、鉴权、限流与费用边界

AI 网关位于业务应用与模型服务商之间，集中处理认证、模型路由、使用量、重试与记录。它不应成为前端可任意转发请求的开放代理，而应只接受业务定义的任务，如评阅某道题或生成限定数量的变式。

用户提交的是业务意图，后端决定提示、允许模型、工具与输出限制。服务商密钥和内部计费配置不应进入客户端。

## 准入、适配与任务账本

入口校验用户、题目关联、答案长度和任务类型，再检查并发与额度。模型适配层把统一业务请求转换成提供商协议，同时保留能力差异，不能把不支持结构化输出或工具调用的模型当作完全等价替代。

失败切换需要分类：参数错误或不支持能力不应反复换供应商；暂时限流或服务故障可以在总预算内切换。已经输出部分内容或执行工具后，重试可能重复结果或副作用，应建立尝试与生成版本，必要时重新开始并明确告知。

使用量按每次上游尝试记录，再按业务规则结算用户额度，避免把失败成本与用户扣费混为一谈。缓存键包含任务、模型与提示版本、权限作用域等条件，防止不同用户共享私人答案。日志与历史同样需要访问控制与保留策略。

## 把机制放到一条完整路径中

```flow
AI 网关
业务准入｜验证身份任务关联与资源预算
能力路由｜选择满足协议的模型服务
受控调用｜总预算内重试切换并记录尝试
结果结算｜验证输出保存历史与使用量
```

## 配套代码：预算检查与权限化缓存键

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

用模型说明租户和提示版本参与隔离，不生成真实 API 密钥或费用数据。

```javascript
function cacheKey({tenant,user,query,promptVersion}) {return JSON.stringify([tenant,user,query,promptVersion]);}
console.log(cacheKey({tenant:'T',user:'A',query:'你好',promptVersion:1})===cacheKey({tenant:'T',user:'B',query:'你好',promptVersion:1}));
function withinBudget(used,estimate,limit){return used+estimate<=limit;}
console.log(withinBudget(80,15,100));
console.log(withinBudget(80,30,100));
```

同样 query 不应跨用户裸复用；预估输出也需计入预算。真实网关还要并发原子配额、身份鉴权、供应商计费和取消，前端检查不能替代服务端边界。

## 从示例走向实际使用

用受控假服务商模拟限流、超时、错误 JSON 和部分流后断开，检查切换是否保持任务状态与账本一致。模型测试应显示明确正常或失败原因。

课内缓存键与预算判断只展示边界条件，真实网关还需要原子预留、持久任务和完整尝试链。
