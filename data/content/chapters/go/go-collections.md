## 数组和切片不是同一个类型
数组长度是类型的一部分，例如 [3]int 与 [4]int 不同。数组赋值复制整个数组值。slice 是对一段底层数组的描述，包含访问起点、长度和容量等信息。复制 slice 复制的是描述，两个 slice 可能仍指向同一底层存储，所以修改元素可能互相可见。

len 表示当前可访问元素数量，cap 表示从起点到可用底层空间的容量。append 可能在原存储上扩展，也可能分配新数组，因此必须接住返回的 slice，不能假定 append 永远原地修改或永远复制。
## 切片描述符与底层数组怎样联系

数组长度是类型的一部分，`[3]int`与`[4]int`不同；数组赋值复制全部元素。slice可以看成包含底层数组位置、长度和容量的一份描述信息，赋值会复制这份描述，但多个slice仍可能访问同一底层数组。len表示当前可见元素数量，cap表示从当前起点到可用底层容量的范围，不是业务上允许的最大长度。

append返回新的slice值，因此通常要写`s = append(s, value)`。容量足够时可能复用底层数组，容量不足时分配新数组并复制已有元素；不能依赖某次append恰好分配或恰好复用来维护隔离。需要独立数据时显式分配并copy，或使用合适的克隆方法。copy只复制元素；元素本身若是指针或嵌套slice，仍可能存在更深层共享。

## map的存在性、遍历与并发规则

`value, ok := m[key]`用ok区分键不存在和键存在但值恰好为零。nil map可以读取和取长度，但写入前需要make或非nil字面量。delete删除不存在的键不会因此报错；map遍历顺序未规定，需要稳定显示顺序时先提取键并排序。

普通map不能在没有同步的情况下让一个goroutine写、另一个并发读写；需要锁、单一拥有者或适合场景的并发结构。map值赋给另一变量仍关联同一映射数据，参数传递不会自动获得隔离副本。slice同样可能共享数组，因此并发安全不是看变量名不同就能证明。

选择结构时结合操作：按位置有序遍历用slice，按稳定键查找用map，固定长度且值语义明确时可用数组。没有内建set类型时，可用`map[T]struct{}`表达成员集合，但仍需处理键的可比较性和迭代顺序。

## 用一个程序观察别名
```go
package main

import "fmt"

func main() {
	source := []int{1, 2, 3}
	shared := source[:2]
	shared[0] = 9
	copied := append([]int(nil), source...)
	copied[1] = 8
	fmt.Println(source)
	fmt.Println(copied)
	counts := map[string]int{"go": 2}
	value, ok := counts["python"]
	fmt.Println(value, ok)
}
```
shared 改写第一项时 source 也改变，因为底层数组相同。copied 拥有新的元素存储，但若元素本身是指针或其它引用结构，这仍只是相应层次的复制。浅复制和完全隔离不是同一个承诺。
## map 的零值与缺失键
map 保存键值关系，键类型需要满足可比较规则。读取不存在的键会得到值类型的零值，因此用 value,ok 区分“键不存在”与“值刚好是0”。nil map 可以读与查询长度，但写入会 panic，需要 make 或字面量初始化。
```flow
slice 别名关系
原 slice 描述｜指向底层数组一段
切片 source[:2]｜新描述，仍共享底层存储
修改共享元素｜两份描述都能看到变化
显式复制元素｜获得新存储，进一步考虑元素内部引用
```
map 遍历顺序不能作为业务排序；需要稳定输出时提取键并排序。普通 map 不允许不受控的并发读写，竞态不能靠“运行几次没报错”证明安全，使用锁、所有权或合适并发结构。
## 容量与内存生命周期
从大数组切出一个很小的 slice，仍可能使整个底层数组保持可达；长期保存小片段时可按需复制。预分配减少扩容，但要依据合理规模，不能根据不可信请求长度无限 make。

测试空 slice、nil、append 跨容量边界、共享修改与 map 缺失键，才能知道函数契约是否清晰。返回内部 slice/map 之前明确调用者是否有权修改，否则封装可能在不知不觉中失效。
