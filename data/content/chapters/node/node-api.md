## 从具体问题认识Node API 的校验、幂等与优雅退出

API 是客户端与服务端之间的行为契约。一个写接口除了接收 JSON 并存入数据库，还要判断调用者是否有权限、参数是否合法、重试是否会重复执行，以及进程退出时已经接受的操作如何结束。

例如“创建学习计划”请求可能已提交成功，但响应在网络中丢失。客户端再次点击时，如果服务端把它当全新操作，就会产生两份计划。接口正确性必须覆盖这种不确定状态。

## 校验、幂等与关闭连接分别保护什么

输入校验分为结构与业务两层。结构校验检查类型、长度和必填字段；业务校验检查资源归属、当前状态和操作是否合法。TypeScript 类型只约束开发时的代码，不会自动验证网络传来的 JSON。授权必须基于服务器确认的身份与资源关系。

幂等键把同一次业务意图的重试关联起来。服务端保存键、请求摘要、执行状态和结果；相同键相同参数可以返回已有结果，相同键不同参数应冲突。数据库唯一约束和事务用于处理并发，单进程 Map 只适合演示，无法跨进程或在重启后保证一致。

优雅退出先停止接收新请求，再给已接受请求有限完成时间，随后关闭连接池和其他资源。没有上限地等待长连接会使发布永远不结束；立即强退则可能中断写入与响应。任务若需要比 HTTP 请求更长的生命周期，应进入持久化后台任务系统。

## 写接口要维护的业务不变量

认证、输入校验、授权、并发控制和幂等分别回答不同问题。schema 合法不能证明资源属于用户；请求经过认证不能证明状态仍允许操作；幂等键相同也不能忽略不同请求体。把关键约束落在数据库唯一约束和条件更新上，应用层校验用于早反馈，不能成为多实例下的唯一保护。

## 分层设计的可测性

将 HTTP 适配、应用用例、领域约束与数据访问分开，错误类型在边界映射为稳定契约。单元测试证明业务分支，目标数据库集成测试证明事务与并发行为，独立产物启动测试证明部署依赖。为创建成功但响应丢失、死锁重试与外部通知双写设置故障注入，避免所有测试只覆盖成功路径。

## 把机制放到一条完整路径中

```flow
可靠写接口
入口检查｜限制输入并验证身份权限
幂等识别｜关联重试与请求摘要
事务提交｜维护业务状态和结果记录
生命周期结束｜响应或在退出预算内清理
```

## 配套代码：重试复用幂等键的模型

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

同一业务键重复提交返回原结果，参数冲突则拒绝；不模拟数据库并发事务。

```javascript
const operations=new Map(); let created=0;
function create(key, amount) {
  if(operations.has(key)) {
    const previous=operations.get(key);
    if(previous.amount!==amount) throw new Error('幂等键参数冲突');
    return previous;
  }
  const result={id:++created,amount}; operations.set(key,result); return result;
}
console.log(create('order-A',100).id,create('order-A',100).id);
try { create('order-A',200); } catch(error) { console.log(error.message); }
```

重试不重复创建，但不同参数不能悄悄复用旧结果。真实多实例要用数据库唯一约束和事务，内存 Map 不承担跨实例一致性和鉴权。

## 从示例走向实际使用

把路由层、业务操作与持久化适当分开：路由解释协议，业务层维护不变量，数据库事务保障相关写入一致。这样可以分别测试错误响应与状态变化。

至少覆盖重复请求、同键异参、并发提交、提交后响应丢失和退出中请求。接口设计不能只用“正常调用一次返回 200”作为完成标准。
