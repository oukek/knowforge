## 从分数到下一个 token
模型输出 logits，它们是未归一化分数，不是百分比。对正温度 T，分布为 `p_i = exp(z_i/T) / sum(exp(z_j/T))`。实际计算先减去最大 logit，利用 softmax 平移不变性避免溢出。低温度使分布更集中，高温度使其更平坦；T=0 通常由服务按贪心等约定处理，不能把 0 直接代入除法。

下一 token 概率是给定已有前缀的条件概率。“退款”这个词概率高，不能推出客户符合退款条件。整段答案还受知识、工具数据和任务定义影响；把最大 token 概率显示成“答案可信度 98%”缺乏校准依据。
## 截断采样的执行顺序
Top-k 先保留分数最高的 k 个候选；top-p 按概率排序，取累计质量首次达到阈值的最小前缀，然后对保留候选重新归一化采样。温度先改变概率，因而可能改变达到同一 top-p 所需的候选数量。不同服务的参数范围、顺序和支持情况需查对应模型接口，不能假设所有 API 完全一致。

| 方法 | 控制量 | 不能保证什么 |
|---|---|---|
| 贪心 | 每步取最高分 | 全局最优、事实正确或跨硬件逐字复现 |
| Top-k | 候选数量 | 每步保留相同的概率质量 |
| Top-p | 最小累计概率质量 | 必须有多个候选或业务正确性 |

若最大候选本身已有 0.9，而 p=0.8，保留一个候选就是正确结果，不应为了“随机性”强行加第二个。
## 可运行实验：不靠随机数也能理解采样
使用 logits `[0, ln(3)]`，T=1 的分布为 `[0.25, 0.75]`，T=0.5 为 `[0.1, 0.9]`。Python 实验固定一个 0.6 的分位点，先按 token 索引构造累积分布，再选中对应 token。这里固定分位点是为了让学习输出可验证，不是在模拟模型的真实内部随机源。

```python
import math

def distribution(logits, temperature):
    if temperature <= 0:
        raise ValueError('positive temperature required')
    scaled = [x / temperature for x in logits]
    peak = max(scaled)
    values = [math.exp(x - peak) for x in scaled]
    return [x / sum(values) for x in values]
```

把所有 logits 加上 10000，输出应不变；再试相等分数、极端分差、top-p=1、非法温度。比较候选集合和概率，不要只比较一次抽样结果。
## 重现性与输出多样性
固定 seed 有助于隔离实验变量，但云服务模型更新、批次、数值核与并行顺序可能仍影响结果。保存模型版本、提示版本、工具快照、解码参数及样本 ID；关键业务验收应检查结构和事实不变量，而非要求每次标点完全相同。

温度调低只能减少某种采样波动，不能修复错误的检索结果、过期库存或不明确的规则。相反，方案发散任务可能需要生成多个候选，再由可验证标准筛选。候选数量也会提高成本，应限定预算和停止条件。
## 如何建立有用的业务置信度
先定义事件，例如“分类正确”或“所有金额均有证据支持”，再在独立标注集上评估分数与真实正确率的对应关系。按分数分桶观察预测与实际比例，并检查不同语言、租户和难度切片。若用模型自报分数，它只是待评估特征，不能自动成为概率。

允许拒答或人工转接时，应测覆盖率与被接受样本错误率的关系：提高阈值通常牺牲覆盖，业务要为二者定目标。高风险动作继续依赖确定性授权与业务校验，不能让概率阈值替代权限。
## 诊断案例与边界
同一 FAQ 偶尔给出不同政策，先确认输入是否完全相同、索引版本是否变化、工具响应是否不同，再判断采样影响。准备一组固定上下文进行重复生成，同时准备真实流量切片，分别测稳定性和正确性。两种指标不能合并成“随机性越低越好”。

实验没有训练模型或校准置信度，仅验证数学机制。真正做校准时需保留未参与提示优化和阈值选择的测试集，并把拒答、错误类型与人工审核成本一起记录。
