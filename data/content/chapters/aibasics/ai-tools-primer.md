## 从具体问题认识Tool / Function Calling

工具调用让模型提出使用外部能力的请求，例如查询订单或计算价格。模型通常生成工具名称与参数，真正执行函数的是应用运行时。模型说“已经退款”并不能证明退款接口真的成功，必须以工具结果和业务状态为准。

一次工具往返包括定义能力、模型选择、参数验证、授权执行、结果返回和继续生成。每一步都有不同责任。

## 工具契约与可信执行边界

工具名称和说明帮助模型判断何时使用，Schema 描述参数形状。参数通过 Schema 只说明结构合法，仍需业务校验：订单属于谁、当前状态是否允许、额度是否足够。租户与用户身份应由后端上下文注入，不能相信模型自由填写的 ownerId。

只读查询与有副作用操作需要不同策略。查询可以在预算内重试，创建、发送和扣费需要幂等与必要确认。工具结果应区分成功、业务拒绝与系统失败，并返回有限结构化数据，避免把完整数据库或敏感日志重新送给模型。

模型可能选择错误工具、重复调用或形成循环，运行时应限制可用工具、次数、时间与输出大小。工具返回内容也可能包含不可信指令，不能因为它来自一次工具调用就提升为系统规则。协议关联 ID 用来配对调用与结果，重试与并行时尤其重要。

## 调工具是一套往返协议

宿主向模型提供工具名称、用途和参数结构；模型可能返回调用请求；宿主解析验证后执行；把结果与对应调用 ID 关联再交回模型；模型继续回答或提出下一步。模型生成了函数名称和 JSON，不代表函数已在服务器执行。

工具可以是读文档、查订单、计算或发通知。危险程度取决于真实副作用与资源范围，不能只按名称是否含 delete 判断。执行层应将模型当作候选行动提出者，身份和授权来自可信服务上下文。

## 工具定义要能被正确选择

描述写清用途、何时不该调用、参数单位和返回含义。相近工具要有可区分的职责，工具过多时可先按任务检索候选定义，而非每次塞进全部菜单。schema 约束参数形状，仍需业务验证。

| 字段 | 应明确 | 坏例 |
|---|---|---|
| 金额 | 最小货币单位与范围 | 10 是元还是分 |
| 资源 ID | 类型与作用域 | 模型提供租户即可跨域 |
| 分页 | cursor、总数或 truncated | 部分结果冒充全集 |
| 错误 | 可重试与状态不明 | 把失败返回为空列表 |

工具返回的外部文字也是数据，不能因为它来自工具就升级成执行指令。

## 结果、重试和副作用

每个调用结果应关联原调用，保持会话协议完整。未知工具、解析失败、无权限、超时和业务冲突要分别处理。已提交但响应丢失时，按稳定 operation_id 查账，不通过重新生成调用身份来“重试”。

写工具在提交前重新验证版本与授权，必要时要求人确认具体动作。并行读工具可以提高效率，但并发、总时间和费用由宿主控制，模型不能自行突破限制。

## 如何验收工具可靠性

除了最终文字，还要检查是否选对工具、参数单位是否对、授权是否通过、结果是否正确配对、是否产生多余副作用。准备重复调用、空结果、部分分页、工具失败和恶意结果测试。

面试从一次真实调用链讲起，明确模型看到什么、返回什么、谁执行、结果如何续接和在哪里停止。只说“接了 function calling”不足以说明工程实现。

## 把机制放到一条完整路径中

```flow
工具调用往返
暴露能力｜提供窄工具与参数契约
模型提议｜生成名称参数和调用身份
宿主执行｜校验授权并受控调用
返回观察｜记录真实结果后继续或停止
```

## 配套代码：Tool / Function Calling：模型如何使用外部能力

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
function execute(tenant, call) {
  if (call.name !== "get_stock") throw Error("unknown tool");
  if (
    Object.keys(call.args).join(",") !== "sku" ||
    typeof call.args.sku !== "string"
  )
    throw Error("invalid args");
  const records = { "a:sku1": 3 };
  return {
    callId: call.id,
    value: records[tenant + ":" + call.args.sku] ?? null,
  };
}
console.log(
  execute("a", { id: "c1", name: "get_stock", args: { sku: "sku1" } }),
);
console.log(
  execute("b", { id: "c2", name: "get_stock", args: { sku: "sku1" } }),
);
try {
  execute("a", {
    id: "c3",
    name: "get_stock",
    args: { sku: "sku1", tenant: "b" },
  });
} catch (e) {
  console.log(e.message);
}
```

租户由可信宿主传入，不由模型参数指定。示例只演示调用边界，生产不能用拼接字符串替代完整数据库授权。

## 从示例走向实际使用

从一个只读查询工具开始，测试缺参数、越权、返回空值和超时，再加入写工具与幂等。记录每次请求、验证结果和执行状态，便于区分模型错误与工具故障。
