## 类型与零值是程序的基本约定
变量声明后有明确类型，未显式初始化时得到零值：整数为0、bool为false、字符串为空，指针、slice、map、channel等可以为nil。零值可用不意味着所有 nil 值都能进行任意操作，例如 nil map 可读取却不能直接写入。类型检查能提前发现很多不匹配，但业务合法性仍需自己校验。

Go 不自动把 int 与 float64 混合运算，也不会把字符串数字自动当整数。显式转换表达了程序员的选择；解析外部文本使用 strconv 等函数并检查错误，不能只做类型强制转换。
## 声明、赋值和转换要区分语法作用

`var count int`声明带零值的变量，`var count = 3`从初始化表达式推断类型，函数内`count := 3`是短变量声明，`count = 4`更新已有绑定。短声明要求在当前作用域至少引入一个新变量，因此不能把所有赋值符号都换成:=。常量使用const，表达不会在运行时被重新赋值的值；它与一般变量的类型推断还有细节差异。

函数签名说明参数类型和返回类型，多个返回值是常见结构，例如业务结果与error。调用方应处理错误，而不是忽略第二个返回值后继续使用零值。Go没有用整数或字符串直接作if条件的隐式真值规则，空字符串判断要写`name == ""`，指针存在性判断写`pointer != nil`。

## 零值和溢出怎样影响业务代码

| 类型 | 常见零值 | 对业务的提示 |
| --- | --- | --- |
| 数字 | 0 | 未填写与真实0需要额外区分 |
| bool | false | 默认关闭是否符合需求要确认 |
| string | 空字符串 | 不自动表示缺失或非法 |
| 指针、slice、map等 | nil | 各类型允许的操作不同 |

静态类型让编译器知道可以执行哪些操作，但不会检查金额为负、年龄超过范围或ID属于另一用户。整数转窄类型可能截断，浮点转整数会丢失小数部分；这不是业务舍入策略。文本"12"要用解析函数转数字，`string(65)`表达Unicode码点对应字符，不是十进制字符串"65"。数据进入系统时应把解析、范围校验和业务校验分成清晰步骤。

## 写出分支与循环
```go
package main

import "fmt"

func main() {
	var total int
	for i := 1; i <= 4; i++ {
		total += i
	}
	if total >= 10 {
		fmt.Println("ready")
	} else {
		fmt.Println("wait")
	}
	fmt.Println(total)
	var enabled bool
	fmt.Println(enabled)
}
```
for 可以写计数循环、条件循环或无限循环，break/continue 改变当前循环流程。if 中条件必须是布尔值，不能像某些语言那样把整数当真假。switch 默认匹配后结束，不需要在每个分支尾部写 break；fallthrough 有特定语义，不应机械从其它语言迁移。
## 值复制、作用域与遮蔽
赋值通常复制值，但值内部可能保存指向共享数据的引用信息，slice 和 map 在后续课程里详细解释。函数参数也是按值传递，不能简单说“Go 有些参数自动按引用传”。传指针是把一个指针值复制过去，再通过它访问同一对象。
```flow
读一段代码时的顺序
找声明位置｜变量属于哪个作用域
确认静态类型｜哪些操作合法
确认初始值｜零值还是显式赋值
跟踪赋值与分支｜是否创建了内层同名变量
```
`:=` 在内层作用域可能创建同名变量，导致外层值并未更新。处理 err 时尤其要注意哪些变量是新声明的、哪些是已有绑定。编译通过只证明类型和语法等检查通过，不保证你操作的是期望的那个变量。
## 输入边界与工程习惯
int 的位宽与平台有关，持久化协议字段应明确范围与格式。整数溢出、浮点误差和金额舍入仍需设计。处理用户输入先解析、验证范围，再进入业务；不要把“静态类型”当成外部 JSON 已可信的理由。

测试零值、边界、负数、无效文本与大数，能比只看一个正常循环输出更快建立类型直觉。把分支写清楚通常比压成复杂表达式更容易维护。
