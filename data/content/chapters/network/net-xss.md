## 从具体问题认识XSS 与不可信内容渲染

XSS发生在不可信数据被页面解释成可执行内容时。它可以来自URL、保存到数据库的评论或接口返回字段，核心不是字符串里是否有某个关键词，而是数据进入HTML、脚本、属性或URL等哪种解释上下文。

攻击脚本在目标页面权限下运行，可能读取页面数据、伪造交互或代表已登录用户请求。HttpOnly限制直接读取Cookie，但不能阻止页面脚本借当前会话执行操作，因此它是额外保护而非XSS的完整解法。

## 文本显示、富文本与策略防线

显示普通文本优先使用textContent或框架的文本插值，让内容作为文字而不是HTML解释。需要富文本时采用维护中的清洗器，明确允许标签、属性与URL协议。HTML正文、属性值、JavaScript字符串和CSS各有不同语法，简单替换尖括号不能覆盖所有上下文。

innerHTML、动态脚本执行和不受控URL是需要特别审查的汇入点。框架默认转义并不保护v-html、dangerouslySetInnerHTML或第三方Markdown渲染器的所有自定义扩展。清洗之后再次用字符串拼接加入未经处理内容，也可能破坏原来的保证。

CSP限制可加载与执行的资源来源，可结合nonce或hash减少意外脚本执行；它需要与实际资源加载方式匹配，并通过报告逐步验证。Trusted Types等机制可帮助限制危险DOM汇入点，但兼容范围与接入成本需按环境确认。依赖更新和供应链控制同样重要，因为可信脚本本身被替换也会获得页面能力。

## 把机制放到一条完整路径中

```flow
不可信内容进入页面
识别来源与上下文｜URL、接口、数据库或模型输出
选择文本或受控富文本｜普通文字不使用HTML解释
清洗与协议校验｜标签、属性和链接规则明确
插入并执行策略｜CSP等防线补充，不能替代正确输出
```

## 配套代码：文本编码与危险 HTML

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

在 Worker 中仅操作字符串，不将危险内容插入真实 DOM。此编码只适用于 HTML 文本上下文。

```javascript
function escapeText(value) {
  return value.replace(/[&<>"']/g, char => ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'":'&#39;'}[char]));
}
console.log(escapeText('<img src=x onerror=alert(1)>'));
console.log(escapeText('A&B'));
```

把尖括号等编码后作为文本显示；它不是通用 HTML 清洗器，也不能直接用于 URL/脚本上下文。真实富文本使用受维护的清洗库，普通文本优先 textContent。

## 从示例走向实际使用

把输入到显示的链路画清楚：哪里解析Markdown、哪里清洗、哪里设置链接、哪里插入DOM。测试安全的恶意形状样本，覆盖事件属性、危险协议、嵌套HTML和自定义插件，不对公共站点做未授权探测。

安全渲染与权限隔离要同时存在。对AI输出也使用同样边界，不能因内容由模型生成就当可信HTML；日志和错误提示也可能成为展示入口。
