## 从具体问题认识页面与组件生命周期

生命周期是框架在对象建立、显示、隐藏和销毁等阶段调用的入口。页面和组件都需要生命周期，因为它们的存在时间并不相同：一个页面可包含多个组件，页面隐藏时组件未必已经销毁。

例如从列表打开详情，列表页面可能仍在页面栈中。此时停止可见区域的轮询应与“暂时不可见”关联，而释放这个页面独占的资源应与“真正卸载”关联，否则返回列表后可能重复注册监听或丢失应保留的状态。

## 创建、可见与销毁是三种不同信号

页面加载阶段适合解析入口参数和建立初始状态；显示阶段适合处理每次回到前台都需要的刷新；首次渲染完成后，才考虑依赖界面节点的操作。隐藏表示暂时不在前台，不等于对象已经消失。卸载表示该页面生命周期结束，应释放定时器、事件订阅和仍在进行的请求。

组件还具有自身的挂载、就绪和脱离阶段。父页面更新数据可能触发组件属性变化，而组件本身并没有重新创建，因此不要把所有数据派生逻辑都放在只执行一次的初始化钩子里。反过来，在每次显示时无条件添加监听，也会让一次事件触发多次处理。

异步请求往往比界面活得更久。请求开始时保存当前任务版本，响应到达后检查页面是否仍有效、参数是否仍匹配，再决定是否提交结果。仅在卸载时清掉定时器，不能阻止已经发出的请求返回；取消与结果有效性检查应配合使用。

## 把机制放到一条完整路径中

```flow
页面的一生
加载｜解析参数建立实例状态
显示｜恢复可见期间的工作
隐藏｜暂停不需要的活动
卸载｜取消任务并释放独占资源
```

## 配套代码：幂等启动与停止资源

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

模拟多次 onShow 不重复订阅，onHide 释放资源。

```javascript
let active = false, starts = 0;
function onShow() { if (!active) { active = true; starts++; } }
function onHide() { active = false; }
onShow(); onShow();
console.log(starts, active);
onHide(); onShow();
console.log(starts, active);
```

同一次显示期间只启动一次；隐藏后再次显示可重新启动。真实定时器、监听与请求还要保存清理句柄，并区分隐藏、卸载和进程被终止。

## 从示例走向实际使用

为每种资源标注创建者和释放时机：页面轮询随可见性暂停恢复，组件订阅随挂载脱离注册注销，共享登录状态由应用层拥有。资源归属比记忆钩子名称更重要。

测试打开、返回、再次打开、切到后台、快速切换参数这几条路径。日志带页面实例 ID，才能看清某次响应属于当前页面还是已经退出的旧实例。
