## 从具体问题认识缓存、模型路由与降级

缓存与模型路由可以降低成本，但节省的前提是结果仍适合当前用户和任务。供应商的提示前缀缓存复用推理中间计算，应用的答案缓存复用已有答案，检索缓存复用候选结果；它们的命中条件和失效原因不同。

同一句“能退吗”对不同订单、用户权限和政策版本可能有不同答案，因此问题字符串不能单独构成答案缓存键。

## 依赖版本与任务级经济性

答案依赖哪些信息，缓存键或校验逻辑就必须表达哪些边界：租户、授权版本、语料、提示、模型和业务状态。并非每个字段都必须直接拼进键，但必须有等价的失效或验证机制。高命中率不能以跨权限返回结果为代价。

提示缓存不等于新请求免费，也不保证回答完全相同。其适用长度、写入与读取计费及有效期按服务契约判断。应用侧应记录实际缓存使用量，不能把文本相同就当成供应商必然命中。

路由先保证能力与安全，再比较完整任务成本。便宜模型如果频繁失败并升级到贵模型，平均单次费用低却可能让成功任务更贵。降级还要保持输出契约，不能从带证据的答案降级成未经标注的自由猜测。

## 三种缓存不要混为一谈

模型 KV Cache 保存中间张量；供应商前缀缓存复用符合其规则的输入计算；应用答案缓存直接返回旧业务输出。三者的命中条件、节省部分和失效风险不同。前缀命中不意味着这次不用生成，也不意味着用户能读取任何旧答案。

OpenAI 的前缀缓存取决于完整渲染前缀及模型相关规则，工具定义、schema 或前缀内容变化可能影响复用。把随机时间戳插在稳定前缀之前可能降低复用；最低长度、断点和价格要查实际模型，不应写死一个适用于所有版本的阈值。

## 答案缓存键其实是一份依赖清单

只用 question 作键会把不同租户、语言或权限下的答案混在一起。至少明确租户、用户可见范围版本、规范化问题、语料版本、提示版本和影响输出的配置。若答案含个人数据，还要按主体或更细粒度权限隔离。缓存命中时继续验证当前权限，旧 key 正确也不等于现在仍可读。

```js
const keyParts = [tenant, accessVersion, corpusVersion, promptVersion, question];
// 用结构化序列编码，再由后端按需要摘要；不要用不转义的分隔符直接拼接
```

过度规范化也有风险：去掉问句中的产品型号、日期或否定词会让不同问题碰撞。语义缓存更需要相似度之外的身份、范围、版本和答案可复用性检查。

## 任务级成本才能比较路由方案

一次任务可能多轮模型、检索、重排和工具调用。成本应汇总所有尝试、失败、缓存写入与读入以及外部服务，不只看最终成功调用的输入 token。用总成本除成功任务数比较方案，并单列无成功时不可定义的指标。

| 任务类型 | 可考虑路由 | 必须验证 |
|---|---|---|
| 固定字段抽取 | 较小模型或规则 | 缺字段与异常输入 |
| 复杂规划 | 更强推理模型 | 工具轨迹、时间和成本上限 |
| 高风险写入 | 模型只生成候选动作 | 确定性授权与审批 |

路由不是让模型自行声明“我能解决”。先按可观测任务特征和质量集建立规则，再评估路由错误的代价。

## 降级必须保持契约

主模型超时可以尝试备用服务，但新服务必须支持同样的结构、工具语义和隐私边界。不能为了“成功返回 200”把严格 JSON 换成任意自然语言。总 deadline 应贯穿所有尝试，退避和排队同样消费预算。

若超时发生在写工具执行之后，先查 operation_id 的业务状态。切换模型重新规划可能重复付款、发信或建单；网络超时只代表客户端不知道结果，不代表服务器未执行。安全重试依赖幂等与查账，不能依赖换模型。

## 如何验证优化没有以质量换命中

同时记录按租户隔离的命中率、真实费用、P95、任务正确率、过期答案率与越权数。灰度时固定请求分布，避免只把简单问题路由到新方案造成选择偏差。缓存热身成本、失效风暴和回源并发也需要测。

用相同问题跨两个租户、同用户撤权、索引更新、提示更新、主服务超时、备用服务不支持工具六组故障注入验证。省下的 token 是中间结果，最终目标是稳定且正确地完成业务任务。

## 把机制放到一条完整路径中

```flow
安全的成本优化
列出依赖｜身份权限资料与业务状态
匹配缓存｜验证范围版本和有效期
受约束路由｜筛能力后比较任务级成本
持续评估｜检查命中收益与质量隔离
```

## 配套代码：缓存、模型路由与降级：节省成本但不串数据

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
function cacheKey(x) {
  return JSON.stringify([
    x.tenant,
    x.accessVersion,
    x.corpusVersion,
    x.promptVersion,
    x.question,
  ]);
}
const a = {
  tenant: "a",
  accessVersion: 1,
  corpusVersion: 7,
  promptVersion: 2,
  question: "可退吗",
};
console.log(cacheKey(a) === cacheKey({ ...a, tenant: "b" }));
console.log(cacheKey(a) === cacheKey({ ...a, accessVersion: 2 }));
console.log(cacheKey(a) === cacheKey({ ...a, corpusVersion: 8 }));
function readCached(entry, principal) {
  return entry.tenant === principal.tenant &&
    entry.accessVersion === principal.accessVersion
    ? entry.answer
    : null;
}
console.log(
  readCached({ ...a, answer: "旧答案" }, { tenant: "a", accessVersion: 2 }),
);
```

租户、权限或语料版本变化都产生不同 key；读取时仍检查权限版本。这里只验证隔离机制，不模拟供应商的真实 prompt cache。

## 从示例走向实际使用

用权限变更、文档更新和模型切换验证缓存失效。比较路由方案时把重试、升级和失败成本计入，并报告质量是否保持。

课内缓存键与读取检查是作用域示例，不是全部依赖清单。实际字段应由业务结果依赖关系推导。
