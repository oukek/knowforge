## 从具体问题认识FastAPI、依赖注入、生命周期与 async 边界

FastAPI 使用 Python 类型声明组织请求解析、校验和接口文档，并通过依赖注入把认证、数据库访问等公共能力提供给处理函数。它简化了边界代码，但不会自动决定事务、授权和任务可靠性。

依赖注入的核心是把函数需要的能力显式提供进来，例如业务服务接收仓储接口，而不是在内部偷偷创建数据库连接。这样测试时也能替换为受控实现。

## 请求依赖与应用资源生命周期

路径与请求模型定义输入边界，响应模型控制输出字段。依赖可以解析当前用户、提供连接或组合其他依赖，但不要把所有业务规则都藏进复杂依赖树。事务边界应与业务操作对应，避免每个小依赖各自提交导致整体无法回滚。

async def 适合调用可等待的异步 I/O；在其中直接调用阻塞库仍会占用事件循环。框架对普通同步路径函数与依赖有相应执行安排，但你自己调用的普通辅助函数不会自动因此变成后台任务。CPU 密集工作需要另行评估线程、进程或任务服务。

应用级连接池和模型客户端适合在 lifespan 中建立并在关闭时释放，请求级资源则按依赖作用域管理。进程内 BackgroundTasks 可以用于有限的响应后工作，但不等于持久任务队列，进程崩溃后不能保证恢复。长期 AI 任务应有独立持久状态。

## 把机制放到一条完整路径中

```flow
FastAPI 请求处理
解析边界｜请求模型与参数校验
提供依赖｜身份连接和业务服务
执行业务｜明确异步事务与权限
结束清理｜响应裁剪并释放对应作用域资源
```

## 配套代码：FastAPI、依赖注入、生命周期与 async 边界：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

class Service:
    def __init__(self,repo): self.repo=repo
    def get(self,key): return self.repo.get(key)
service=Service({'a':{'title':'A'}})
show(service.get('a'))
```

构造器注入让业务服务依赖可替换仓库，测试不必访问真实数据库；这不是 FastAPI 本身的执行示例。真实项目可用 Depends 组装同样的依赖，并通过响应模型、认证和事务明确请求边界。

## 从示例走向实际使用

把路由、业务服务与仓储适当分层，在测试中替换仓储与外部客户端。分别验证输入校验、权限与事务行为，不把自动文档当成唯一验收。

课内 Service 示例展示依赖传入，本机 FastAPI 项目还需要安装框架与 ASGI 服务，并测试启动关闭、异步取消和连接池释放。
