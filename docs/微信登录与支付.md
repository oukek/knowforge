# 微信登录与资源包购买

本实现参考 t-box 的公众号授权和微信支付 API v3 链路，使用面试项目自己的用户、会话与额度账本，不共享 t-box 数据或密钥。数据库新增普通关联字段与索引，没有外键。

## 配置与开通

在管理后台 → **微信接入** 配置，微信登录和微信支付分 Tab 管理。页面默认展示摘要，点击“编辑配置”打开弹窗，保存后即时生效，无需重启。现在不再读取 `WECHAT_*` 环境变量；之前填在环境变量中的内容需由管理员重新录入后台，确认可用后删除旧变量。

服务器只保留现有的 `AI_ENCRYPTION_KEY` 主密钥：32 字节、跨部署保持不变，与数据库分开安全备份。它复用于 AI 凭据及微信配置的 AES-256-GCM 加密。**配置整体（含 AppID、URL、商户信息、密钥与证书）均以密文存入数据库**，主密钥不存入数据库。缺少主密钥时不能保存，密文无法解密时不允许覆盖原值。

- 微信登录弹窗：填写具有网页授权权限的公众号 AppID、AppSecret，以及前端／API HTTPS 源地址；域名不带路径、尾部斜杠。在公众号后台配置网页授权域名为 API 域名（默认 `knowforge-api.ookew.com`）。
- 微信支付弹窗：复用同一公众号 AppID，填写商户号、商户证书序列号、商户私钥 PEM、微信支付公钥／平台证书 PEM、对应公钥 ID／平台证书序列号，以及 32 字节 API v3 密钥。
- 商户平台需开通 Native 和 JSAPI 支付，并绑定上述公众号 AppID；JSAPI 支付授权目录为前端购买页所在目录，默认 `https://knowforge.ookew.com/`。
- AppSecret、商户私钥、微信支付公钥／证书、API v3 密钥不回显；编辑时留空保留。更换公众号须重新填写 AppSecret，更换商户须重新填写对应商户私钥及 API v3 密钥。开启微信支付时校验 RSA 密钥、商户标识与密钥长度。
- 后台展示授权回调和支付通知地址。反向代理保留通知原始正文与 `Wechatpay-*` 请求头，不对通知要求用户登录。
- 管理接口要求管理员、有效会话与 CSRF，并使用版本号防止并发编辑覆盖。审计只记录操作人、版本号和开关状态，不记录配置正文、密钥或密文。

未配置登录或支付时，对应按钮明确显示不可用，不模拟成功。没有真实商户凭据的本地测试仅使用注入的测试网关，不能代替生产小额实付验收。

## 登录行为

公开 `/api/auth/register` 返回 410；新用户通过微信授权自动创建账号，不赠送可消费额度。后端只返回授权链接和登录流程凭据，前端本地绘制五分钟有效的二维码，微信内直接进入授权。授权完成后手机显示确认页，用户点击确认后，持有独立轮询密钥的原设备才能获取 HttpOnly 会话。state、授权票据和轮询票据一次性使用；OAuth token 不返回前端。

旧账号仍通过“已有账号登录”访问原有学习记录；同一微信 AppID + openid 对应同一学习账号。当前不会根据昵称、用户名或 UnionID 自动合并旧账号，防止误合并学习与付费数据。微信账号不显示改密码表单。

## 支付与额度

“我的 AI 额度”展示已发布资源包；点击购买打开支付弹窗。微信内且账号存在对应公众号身份时使用 JSAPI，其余情况后端返回 Native 支付链接 `codeUrl`，由前端本地绘制二维码。二维码绘制失败可重试，刷新链接后不会展示上一次二维码；后端不生成或返回二维码图片，也不依赖 `qrcode` 运行时包。手机浏览器可保存二维码后在微信中识别。本次未接入 H5 跳转、APP 原生支付或在线退款。

下单在服务端校验发布状态和版本，价格按整数分计算。订单固定商品版本、价格、额度及赠送额度；同一用户、同一版本存在有效待付订单时复用。每次请求有幂等标识，网络失败重试不会直接生成新订单。

只有经过 RSA 验签的查单结果或已验签、AES-GCM 解密的支付通知，且商户号、AppID、金额、币种与订单一致，才会在同一数据库事务中写入支付流水、额度批次、额度事件和审计。微信交易号唯一，重复通知不会重复发放。有效期从微信确认付款时间起算；购买额度和赠送额度分别形成批次。

支付弹窗定期查单，失败后可以手动核对。“我的支付订单”展示最近 50 笔，支持重新打开继续支付或核对。前端支付成功提示本身不会发额度。订单 15 分钟有效，过期订单在查单时先核对付款结果，再调用微信关单；通知仍可补确认，避免漏账。离线时依赖微信通知重试，管理员应对照商户平台账单核查异常订单。

每次保存生成独立的加密配置版本。新登录流程和新订单绑定发起时的版本；升级前没有版本绑定的订单使用当前后台配置核对，录入时须保持原商户身份。关闭新登录／新购买后，存量流程仍可完成，存量订单仍可核对。商户或公众号变更后按绑定身份处理存量数据；同身份的最新凭据用于查单与授权，支付通知按验签公钥 ID 尝试解密配置版本。运行时查找最近 200 个版本的轮换凭据；历史密文仍保留，不可直接清理有未结订单关联的配置版本。更换主密钥需先做独立的密文重加密迁移，直接改环境变量会造成解密失败。

测试中的 `authOptions.allowRegistration` 只用于保留历史账号密码行为的回归覆盖，入口脚本和环境变量均不启用该选项。

官方协议：[公众号网页授权](https://developers.weixin.qq.com/doc/offiaccount/OA_Web_Apps/Wechat_webpage_authorization.html)、[Native 下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791877)、[API v3 签名与验签](https://pay.wechatpay.cn/doc/v3/merchant/4012365342)。

## 头像与昵称

所有账号首次建立个人资料时从 16 个内置卡通头像中随机分配一个，旧账号缺少头像时在登录／读取资料时自动补齐并持久保存。头像使用随前端发布的 SVG 资源，不依赖微信头像地址。个人中心默认显示资料摘要，点击“修改资料”在弹窗中选择头像和修改昵称；再次微信登录不会覆盖用户的头像选择或昵称。头像更新仅接受内置 ID，与昵称在同一事务中保存。
