## 从具体问题认识Agent 可观测性

Agent 可观测性把一次任务拆成能关联的事件和耗时，帮助回答“卡在哪、为什么失败、花了多少”。只有最终答案和一条总耗时，无法区分排队、检索、模型生成、工具阻塞或审批等待。

用户界面需要业务阶段，运维需要指标，排障需要 trace。三者使用同一任务身份关联，但展示粒度与数据权限不同。

## 关键路径、事件与隐私最小化

Span 表示一段操作，父子关系记录调用归属，并行关系反映重叠执行。两个各耗时六十毫秒的并行工具，不能简单相加当用户等待一百二十毫秒；墙钟时间看起止与关键路径，资源工作量和费用可以按各操作累计。

事件描述状态变化，如排队、工具开始、审批等待与任务结束；指标聚合成功率、队列长度和延迟分布。不要把高基数字段如每个用户 ID 都当指标标签，否则会造成存储与查询压力。

日志与 trace 在导出前脱敏，优先记录参数摘要、大小、类别与受控引用。为排查保留原文时使用明确权限、期限和审计。观测目标是执行证据，不要求公开或伪造模型不可见的内部推理。

## 只记录最终答案无法排障

同一个“回答失败”可能来自检索空集、模型超时、工具权限不足、写入结果不明或渲染断流。需要把一次用户任务关联到各轮决策、模型请求、工具调用和业务操作。任务 ID、trace ID、调用 ID 与 operation_id 用途不同：调用 ID 关联一次尝试，operation_id 应跨重试保持同一业务意图。

OpenTelemetry 的 GenAI 语义约定提供可参考的规范化方向，相关约定有独立仓库且会演进。落地时固定采用的版本，业务仍应定义自己的成功、拒绝和副作用状态，不能把某个 span 结束就认定退款成功。

## Span 的父子关系与并行关系

根 span 表示任务，子 span 表示检索、模型或工具工作。并行兄弟 span 的耗时相加可能大于根耗时；把它们加起来显示“用户等待时间”会夸大延迟。端到端时长应看根区间或请求关键路径，累计活动耗时适合观察工作量但不等于等待时间。

| 字段 | 用途 | 不宜做什么 |
|---|---|---|
| task_id | 用户任务关联 | 放入所有指标标签形成高基数 |
| tool_call_id | 一次调用及返回关联 | 当作跨重试业务幂等键 |
| operation_id | 业务意图及查账 | 每次重试重新生成 |
| prompt/model version | 回归定位 | 只记一个 latest 字符串 |

异步队列与子进程需传播可序列化的关联信息，身份在新边界重新验证，不把 trace 标签当授权事实。

## 事件与指标分别承担什么

轨迹用于解释单次任务，指标用于看群体趋势。指标可以按工具类型、模型版本和受控错误类别聚合，避免用户 ID、完整问题等高基数或敏感字段。事件记录计划变更、审批、重试、取消与恢复，关键状态转移要有原因和版本。

费用按真实模型和工具使用汇总所有尝试，不能只记录成功 span。统计缺失时标记 unknown，而不是默认为零；部分费用可能稍后到账，需要允许对账更新。根任务失败仍可能已产生账单和副作用。

## 脱敏应发生在导出之前

完整提示和工具输出可能包含个人数据、内部文档和秘密。默认记录结构元数据、长度、来源 ID 与受控摘要；必要原文使用独立加密存储、访问审计和保留期。普通日志 redaction 不能保证语义改写的秘密都被清除，更不能补救已经发给外部导出器的数据。

```js
const safe = {tool: call.name, status: call.status, durationMs: elapsed};
// 不要默认附加 authorization、完整 args 或完整工具返回
```

调试录制需要可回放的最小事实快照，但生产写工具的回放应使用 fake 或只读模式，不能重放真实付款。

## 诊断与验收

在开发数据上注入一个慢模型、一次工具重试、一次取消和一次已提交但响应丢失，确认能从任务追到业务事实。检查失败日志没有秘密，采样后仍能保留足够错误轨迹。可以用尾部采样偏向失败与高延迟，同时对正常任务保留统计代表性。

面试报告应分别给任务成功率、业务违规、延迟分布、每成功任务成本和未知费用比例。清楚说出采样和脱敏造成的观测盲区，不要把“有 tracing”当成系统已经可解释。

## 把机制放到一条完整路径中

```flow
任务观测
生成关联身份｜任务尝试工具与版本可追踪
记录阶段｜事件与 Span 保留因果并行关系
安全导出｜最小字段脱敏权限与保留期
定位问题｜区分关键路径资源量和业务终态
```

## 配套代码：Agent 可观测性：轨迹、关键路径与隐私

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
const task = { start: 0, end: 100 };
const spans = [
  { tool: "search", start: 10, end: 70, cost: 2 },
  { tool: "policy", start: 20, end: 70, cost: 3 },
];
console.log({
  wallMs: task.end - task.start,
  workMs: spans.reduce((n, s) => n + s.end - s.start, 0),
  cost: spans.reduce((n, s) => n + s.cost, 0),
});
function safeEvent(event) {
  return {
    tool: event.tool,
    status: event.status,
    durationMs: event.durationMs,
  };
}
console.log(
  safeEvent({
    tool: "search",
    status: "ok",
    durationMs: 60,
    authorization: "secret",
    args: { email: "private" },
  }),
);
```

并行 span 时长求和代表累计活动工作，不是根请求延迟。字段白名单移除敏感原文；真实系统还需导出前脱敏、访问控制和保留期。

## 从示例走向实际使用

从一个慢任务沿 trace 找最长等待与关键路径，再用聚合指标判断是否普遍。前端实时事件应能回放或从快照恢复，断线不能丢掉最终结果。

课内同时输出 wallMs、workMs 和 cost，展示它们的单位与意义不同；safeEvent 用字段白名单降低意外泄漏。
