## 从具体问题认识解码参数入门

模型先计算下一 token 的候选分数，解码策略再决定选哪个。贪心直接选最高分候选，采样按概率选择。Temperature、Top-k 与 Top-p 影响候选分布或范围，不是事实正确率、创造力或安全性的直接旋钮。

同一组概率 [0.6,0.25,0.1,0.05]，贪心总选第一项，采样则可能选其他项。改变策略会影响多样性，但模型缺失的事实不会因此自动补上。

## 分布调整、截断与停止

Temperature 常通过缩放 logits 改变分布尖锐程度，较低温度通常更集中，较高温度更分散。Top-k 保留固定数量最高候选，Top-p 保留累计概率达到阈值的最小高概率集合，再归一化采样。两者控制方式不同，组合时行为依实现而定。

输出结束可能来自结束 token、长度上限、停止序列、工具调用或服务中断。达到最大输出长度得到的是截断结果，不能与正常完成混淆。结构化输出若被截断，可能缺少闭合结构或业务字段，需要验证与恢复策略。

较低随机性有助减少变化，但不保证跨设备、版本与服务实现逐字一致。随机种子也可能只有有限可复现范围。业务应优先验证内容与契约，而不是把温度设为零后就移除测试。推理型模型对参数支持也可能不同，应查看具体接口。

## 模型计算与选择策略是两步

**模型为下一个 token 给出候选分数，解码策略决定实际选择。** 如果当前候选分别是“好”“是”“有”，贪心策略每步选分数最高的一项；采样则按经过处理的概率随机选择，因而相同问题可能得到不同表达。

Temperature 调整概率分布的集中程度；Top-k 限定候选数量，Top-p 按累计概率选择候选范围。它们改变的是生成选择，不是给模型补充可靠事实；低温度也不能保证答案正确，具体参数行为需要看所用接口。

模型先产生词表分数，解码策略再决定选哪个候选。贪心取当前最高分，采样按概率选择。最高分选择不保证整段全局最优，采样多样性也不意味着事实更错；质量还取决于输入、证据和任务。

Temperature 对 logits 缩放，低温度让分布集中，高温度变平。温度零通常按具体服务约定处理成贪心等方式，不应在 softmax 公式中直接除以零。不同模型支持的参数与组合要按接口核对。

## Top-k 与 Top-p 怎么限制候选

Top-k 保留固定数量的高概率候选，top-p 保留累计质量达到阈值的最小排序前缀，随后重新归一化。Top-p 不是“保留百分之多少词表”。当头部概率很大时，候选可能只有一个。

| 参数或策略 | 控制什么 | 不能保证 |
|---|---|---|
| 温度 | 概率集中程度 | 事实正确 |
| top-k | 候选数 | 固定保留概率质量 |
| top-p | 累计概率质量 | 固定候选数 |
| 输出上限 | 最长生成预算 | 任务已经完成 |

多个过滤的顺序和边界在不同实现可能不同，复现实验要保存实际配置。

## 停止与可复现性

任务停止可能来自结束标志、工具调用、长度上限、取消或安全拒绝。收到一段语法完整文本不等于业务已完成；达到输出上限也不能当成自然完成。流式系统要保留终态原因。

固定 seed 有助实验，但模型版本、数值内核和并发调度仍可能影响结果。关键任务验收应关注结构、事实和动作不变量，而非逐字相同。温度降低不能修复错误索引或缺失权限校验。

## 从概念接到工程

创意任务可以生成多候选再筛选，但成本和延迟也增加。固定结构抽取应先强化输入与输出契约，高风险行为交给确定性校验。记录输出上限与实际终态，避免把截断产生的半个 JSON 当成可提交对象。

下一步可学习 logits 的稳定 softmax、校准、配对评估与业务置信度。先分清“我想让文字多样”与“我想让事实可靠”是不同目标。

## 把机制放到一条完整路径中

```flow
下一 token 选择
模型输出｜计算词表候选分数
调整分布｜按支持的温度等参数变换
截断采样｜选择候选集合并取得一个token
检查停止｜区分正常完成截断与工具事件
```

## 配套代码：解码参数入门：贪心、Temperature、Top-k/Top-p

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
function topP(probs, p) {
  if (!(p > 0 && p <= 1)) throw Error("invalid p");
  const ranked = probs
    .map((prob, id) => ({ prob, id }))
    .sort((a, b) => b.prob - a.prob || a.id - b.id);
  let total = 0;
  const ids = [];
  for (const item of ranked) {
    ids.push(item.id);
    total += item.prob;
    if (total >= p) break;
  }
  return ids;
}
console.log(topP([0.6, 0.25, 0.1, 0.05], 0.8));
console.log(topP([0.6, 0.25, 0.1, 0.05], 0.5));
console.log(topP([0.25, 0.25, 0.25, 0.25], 0.8));
```

Top-p 保留的是达到概率质量阈值的最小排序前缀，相同阈值对不同分布产生不同候选数。

## 从示例走向实际使用

用固定小分布手算 Top-k 与 Top-p 的候选集合，再运行采样统计。真实任务比较应记录模型版本、解码参数与失败类别，避免把一次偶然好结果当成稳定提升。

对自动评阅与代码生成，先定义正确性检查；对创作任务，再讨论多样性。参数选择来自任务目标，没有统一最佳温度。
