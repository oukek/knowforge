## 从具体问题认识this、箭头函数与绑定优先级

this通常回答“本次普通函数调用使用哪个接收者”，作用域则回答“名字去哪里查找”，两者不是一回事。对象里存着一个函数，不意味着这个函数从此永久属于该对象。obj.method()通过属性引用调用时可把obj作为接收者；把method取出再直接调用，原来的属性引用关系已经不存在。

箭头函数没有自己的动态this绑定，而是沿创建位置使用外层this。它适合保留外围上下文，但不适合所有需要由调用方决定接收者的方法。用箭头替换普通函数前，应先判断this到底应由定义位置还是调用方式提供。

## 从调用表达式判断接收者

普通直接调用在严格模式下this通常为undefined；非严格函数可能进行全局对象替换和基本值装箱。call与apply显式指定接收者，区别主要是参数逐项传递还是由类数组提供。bind创建保存接收者和前置参数的新函数，不会立即执行业务函数。

构造调用new建立新对象并以构造语义执行可构造目标，绑定函数被new调用时不能简单认为仍使用bind保存的对象。箭头函数不能通过call、apply或bind改写自身词法this，也不是可构造函数。把这些情况串成一个口号“new大于bind大于隐式”可以帮助记忆，但实际应先判断目标是否可构造、是否箭头或绑定函数，再检查本次调用形式。

回调接口如何调用函数也属于契约：数组迭代方法可能接受thisArg，某些事件接口设定接收者，另一些宿主直接调用。将obj.load直接交给回调注册函数可能丢失预期接收者，可以显式绑定或用闭包调用obj.load。闭包会保留obj引用，资源释放仍需考虑。

## 把机制放到一条完整路径中

```flow
判断this
识别函数种类｜箭头使用词法this，普通函数继续判断
识别调用形式｜方法引用、直接调用、call/apply或构造
应用绑定与严格模式规则｜不要把定义位置误当接收者
进入函数体｜使用本次确定的this
```

## 配套代码：成员调用、解绑定与显式 this

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

严格模式里普通函数的 this 取决于调用方式。

```javascript
const object = {
  name: '对象',
  read() { return this?.name ?? '没有 this'; }
};
const detached = object.read;
console.log(object.read());
console.log(detached());
console.log(detached.call({name: '显式绑定'}));
```

读取方法不会永久绑定接收者。脱离成员表达式调用时严格函数的 this 为 undefined；call 可为普通函数指定本次接收者。

## 从示例走向实际使用

先用严格模式最小例子验证普通函数、方法提取、绑定和箭头四种情况，再把实际框架封装加入实验。不要在服务端假定globalThis等于浏览器window，也不要依赖松散模式的自动装箱掩盖接收者错误。

业务代码倾向显式依赖和稳定调用约定：不需要动态接收者的纯函数直接接参数，需要对象状态的方法清楚保存调用关系。出现this为undefined时，检查调用点，通常比只看函数定义更能找到原因。
