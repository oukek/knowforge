## 从具体问题认识系统设计

SDK 是提供给其他应用调用的一组稳定接口与运行行为。调用者通常不关心内部实现，但会依赖初始化方式、错误类型、资源生命周期与版本兼容。SDK 的边界设计，决定后续能否改实现而不迫使所有接入方一起修改。

例如埋点 SDK 被重复初始化时，不应注册两套监听；销毁后应停止它拥有的定时器与连接。资源管理是公共契约的一部分，不是内部小细节。

## 公共接口、适配层与生命周期

公共 API 应表达调用者的业务意图，避免暴露内部对象结构。配置需要默认值、校验与版本策略；错误应有稳定类别和可恢复信息，而不是要求接入方解析不断变化的英文字符串。异步操作应明确超时、取消与重试由谁负责。

浏览器、Node 和小程序的网络、存储与生命周期不同，可以把核心逻辑与宿主适配层分开。核心部分通过注入的接口访问环境，测试时替换为受控实现。不要在模块导入时立即读取 window 或发网络请求，否则服务端渲染与测试环境可能直接失败。

初始化、使用、销毁与再次初始化需要状态机。幂等初始化避免重复副作用，销毁应只释放 SDK 自己拥有的资源，不能关闭调用方共享的连接。版本升级优先保持兼容，破坏性变化提供迁移说明与可并行过渡路径。

## 把机制放到一条完整路径中

```flow
可演进 SDK
定义契约｜公共输入输出错误与生命周期
隔离宿主｜通过适配接口访问环境能力
管理资源｜初始化与销毁保持对称
兼容演进｜用契约测试和迁移路径升级
```

## 配套代码：init/dispose 的幂等契约

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

反复初始化不重复注册，销毁后允许重新初始化。

```javascript
let active=false,subscriptions=0;
const sdk={
  init(){if(active)return;active=true;subscriptions++;},
  dispose(){if(!active)return;active=false;subscriptions--;}
};
sdk.init();sdk.init();console.log(subscriptions);
sdk.dispose();sdk.dispose();console.log(subscriptions);
sdk.init();console.log(subscriptions);
```

初始化与销毁都幂等，资源计数不会重复或变负。真实 SDK 还需释放监听、队列和包装函数，并考虑多个版本共存，不能只用全局布尔值管理复杂所有权。

## 从示例走向实际使用

先写一个接入示例与卸载示例，检查调用者需要知道多少内部细节。对关键行为建立契约测试，包括重复初始化、失败重试、取消和销毁后调用。

课内状态变量展示资源数量保持稳定，真实实现还应检查监听器、计时器、未完成 Promise 与宿主适配器是否全部得到清理。
