## 从具体问题认识Token 与 Tokenizer

计算机不会直接把一段中文当成“意思”交给语言模型。文本先经过分词器，被转换成离散 token 的编号序列，再映射为模型可计算的向量。token 是分词规则定义的片段，不固定等于一个字、一个单词或一个字节。

所以两段字数相近的中文、英文和代码，可能占用不同 token 数。精确预算必须使用目标模型对应的计数规则，不能用固定字符比例作为账单依据。

## 词表编号如何变成模型输入

词表把片段映射为整数 ID，编号只承担索引作用，数值接近不表示语义接近。模型中的 embedding 查表把每个 ID 转成向量，后续网络再结合位置与上下文处理。分词与向量表示是相邻但不同步骤。

子词分词在词表大小与表达能力之间折中：常见片段可以整体表示，少见词拆成更小单位。BPE 的简化理解是按已学习的优先规则合并相邻片段，真实实现还包括预处理、字节表示与特殊 token。模型升级若更换 tokenizer，相同文本的长度与切分可能变化。

完整请求还包含消息格式、工具定义、历史结果与多模态输入等开销。用户只输入一行，不代表模型输入只有一行。截断时必须保持协议结构，例如工具调用与结果对应关系，不能为了控制长度随意删掉半个 JSON 或一条配对消息。

## 字符、字节和 token 不是一回事

字符是文本符号，UTF-8 字节是编码后的存储单位，token 是分词器定义的离散片段，token ID 是该片段在词表中的索引。一个 token 可以对应完整单词、子词、空格片段或字节组合；中文也不保证一个字恰好一个 token。

模型拿到的通常是 ID 序列及相关位置和类型信息。Embedding 把 ID 映射为向量，但 token ID 本身不是语义距离：编号相近不说明两个词更相似。不同模型的分词器和消息模板不同，不能混用计数或 ID。

## BPE 的入门直觉

子词方法在可复用小片段与长词覆盖之间折中。简化 BPE 可从字符序列开始，根据学习得到的合并优先级把相邻片段合并，逐步形成词表片段。真实字节级实现还涉及规范化、预分词、特殊 token 和版本细节，本课只手工应用给定合并表。

例如 `l o w` 与合并规则 `(l,o) → lo`、`(lo,w) → low`，会得到一个片段 low；若没有第二条规则则保留 lo、w。不能把任意最长字符串匹配都称为 BPE，也不能拿教学词表估算真实 API 账单。

## 为什么计数影响工程设计

上下文上限和输入/输出费用通常围绕 token 或供应商定义的多模态计量计算。工具 schema、系统消息、历史结果也可能占输入预算。用户正文只有几百字，不代表完整请求只有几百 token。

| 现象 | 原因方向 | 处理 |
|---|---|---|
| 代码 token 多 | 符号、缩进、标识符与词表 | 用目标 tokenizer 测量 |
| 中英比例不同 | 分词与编码策略不同 | 不固定四字符估算 |
| 图片也占预算 | 视觉预处理及服务计量 | 查具体模型输入规则 |

输出上限也不等于总上下文上限，发送前应预留输出与协议开销。

## 常见错误与验收

不要按字符硬截取消息造成工具调用与结果不配对；不要把 token 上限异常当成网络不稳定；不要用一个模型的 tokenizer 为另一个模型做精确预算。保存分词器与模型版本，在升级时重跑代表性的中文、代码和长文样本。

验证时检查 encode/decode 的约定、特殊 token、空输入、换行和多字节字符。对已截断内容保留明确标志，防止模型把不完整材料当成完整事实。

## 把机制放到一条完整路径中

```flow
文本进入模型
文本预处理｜按 tokenizer 规则处理输入
分片编码｜映射为词表中的 token ID
向量映射｜把离散编号转换成数值表示
预算校验｜结合消息结构与输出预留控制长度
```

## 配套代码：Token 与 Tokenizer：文本怎样变成模型输入

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
function mergePair(tokens, left, right) {
  const out = [];
  for (let i = 0; i < tokens.length; i++) {
    if (tokens[i] === left && tokens[i + 1] === right) {
      out.push(left + right);
      i++;
    } else out.push(tokens[i]);
  }
  return out;
}
const first = mergePair([..."lowlow"], "l", "o");
console.log(first);
console.log(mergePair(first, "lo", "w"));
console.log({
  jsLength: "你好".length,
  utf8Bytes: new TextEncoder().encode("你好").length,
});
```

这里只应用固定合并规则，不是完整 BPE tokenizer。中文的 JS length 与 UTF-8 字节数也不能作为真实模型 token 数。

## 从示例走向实际使用

准备中文段落、代码、换行与表情样本，使用目标计数工具比较。把粗估用于早期预警，把实际供应商 usage 用于最终记录与结算，并保留模型版本。

课内合并表演示规则如何改变片段数量，不是真实商用 tokenizer。读完应能解释字符数、字节数、token 数和 embedding 维度四者的区别。
