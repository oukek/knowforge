## 路径是名称，文件是外部资源
Path对象方便组合和检查路径，但创建Path不会自动创建文件。相对路径依据进程当前工作目录解析，不一定是脚本所在目录，这也是部署后找不到文件的常见原因。配置应明确基础目录，避免依赖IDE恰好设置的工作目录。

文本模式进行编码解码，二进制模式处理原始字节。使用with确保关闭，写文件还要考虑异常、权限、磁盘空间与并发写入。浏览器Python环境中的文件属于隔离虚拟文件系统，不会直接访问用户本机目录。
## 读取模式和文件位置指针如何工作

`r` 读取已有文件，`w` 创建或截断后写入，`a` 追加，`x` 要求新建且不能覆盖已有文件。模式中的 `b` 表示字节，文本模式则进行编码解码。尤其注意 w 在打开时就可能清空原内容，不能先用 w 打开再决定是否覆盖。

文件对象维护当前位置，read 会推进它，再次 read 不会自动从头开始。seek 可以移动位置，但文本模式的位置标记与编码处理有约束，不应随意拿字符下标当字节偏移。逐行遍历适合文本记录；二进制大文件可使用固定大小分块，并累计真实读取量以限制资源消耗。

```python
from io import StringIO
stream = StringIO("first\nsecond\n")
try:
    print(stream.readline().strip())
    print(stream.read().strip())
    stream.seek(0)
    print(stream.readline().strip())
finally:
    stream.close()
```

## 路径处理与内容处理应分开

Path 的 `/` 运算组合目录与名称，name、suffix、parent 用于提取路径结构，不需要自己按斜杠拆字符串。绝对路径从根开始，相对路径从工作目录开始；配置文件位于代码旁还是运行目录下，应在项目约定里明确。用户上传的文件名只是输入数据，不能直接决定服务器实际保存位置。

文件系统操作还会遇到权限、空间、文件被删除或替换等外部变化。先 exists() 再 open() 之间仍可能发生变化，因此正常错误处理应围绕实际打开与读写，而不是把一次预检查当保证。保存业务数据时也要考虑覆盖规则、版本和备份：原子替换解决读者看到半份内容的问题，不解决两个写入者互相覆盖的问题。

## 一个不会污染项目的完整例子
```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "note.txt"
    path.write_text("学习 Python", encoding="utf-8")
    with path.open(encoding="utf-8") as stream:
        print(stream.read())
    print(path.name)
```
临时目录由上下文清理，编码明确。读取大文件时逐行或分块处理，read()全部读入可能消耗大量内存。检查文件大小后再读仍可能遇到文件变化，所以安全限制应体现在实际读取预算里。
## 原子替换与持久性不是同一个保证
写配置时可以先在同一文件系统的临时文件写完，再用replace替换目标，减少读者看到半份内容的窗口。若业务要求断电后持久，还涉及flush、fsync及目录同步等系统语义。原子可见不等于永久落盘，跨文件系统移动也可能有不同限制。
```flow
受控文件写入
确认允许目录和文件名｜拒绝越界路径
创建临时文件｜在目标文件系统内
写入并检查错误｜按需求刷新与同步
原子替换目标｜避免暴露部分内容
清理残留｜失败路径也要删除临时资源
```
## 不可信路径与并发
用户输入路径可能包含..、绝对路径、符号链接等。简单字符串拼接不能证明访问仍在允许目录，需结合规范化、目录约束和合适的底层打开策略，避免检查与使用之间的竞态。上传文件名应由服务端安全生成或严格映射。

多个进程同时写同一文件还需要锁、版本或数据库等协调，with只负责释放不负责互斥。测试不存在目录、无权限、部分写入、覆盖冲突与异常清理，才能覆盖真实环境。
