## 从具体问题认识流式响应、事件聚合与断线恢复

模型流式响应可能包含文本增量、工具参数片段、使用量和完成事件。它不是把普通完整响应随意切成字符串那么简单，业务需要把不同事件聚合成一致结果。首段文字到达只表示开始有输出，不表示任务已经成功。

例如工具参数分三次到达为 {"city":、"上海"、}，只有完整聚合并验证后，才适合交给工具执行。

## 传输聚合与任务恢复

适配器先处理字节解码与协议分帧，再把提供商事件转换成内部事件。工具调用可能有多个 ID 与参数流，必须按身份分别聚合，不能把不同调用的片段混在一个字符串里。未知事件应按契约记录或拒绝，避免静默丢失关键状态。

完成事件提供终止原因，使用量可能在末尾才出现。连接中断时不能把缺失 usage 自动当零，也不能把当前文本当完整成功；记录已知与未知计量，按供应商可查询能力或任务结算规则处理。

重连观察同一任务与重新请求模型不同。应用若需要恢复，应保存事件序号或结果快照，客户端从断点继续。上游无法续传时，重新生成可能得到不同内容，需要新尝试或生成版本，不能把新回答直接接在旧前缀后。

## 把机制放到一条完整路径中

```flow
模型流聚合
解析传输｜解码并识别完整协议事件
按身份归并｜分开文本工具和使用量
验证结束｜检查完成原因与结果完整性
持久恢复｜保存序号快照及尝试版本
```

## 配套代码：流式响应、事件聚合与断线恢复：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

parts=['{"city":','"上海"','}']
complete=''.join(parts)
show(json.loads(complete))
show(len(parts))
```

模型只演示参数片段合并，不是完整 SSE 或供应商事件解析器。真实流需要区分多个工具调用、文本增量与终态，处理跨块 UTF-8 和失败；合并后仍要校验参数与授权，不能仅因 JSON 可解析就执行。

## 从示例走向实际使用

用固定事件脚本测试任意切块、多个工具交错、末尾 usage、截断和重复事件。观察前后端最终正文、状态与账本是否一致。

课内字符串聚合只说明参数必须完整，真实实现需要事件类型、调用 ID 与序号。网络协议和业务完成条件应分别验证。
