## 从具体问题认识HTTP 方法、安全性与幂等性

HTTP 方法表达请求对目标资源的意图。安全方法的语义以读取为主，不要求调用者承担业务状态变化；幂等方法表示重复相同请求对服务器的预期效果与执行一次相同。安全与幂等是两个维度，也不表示响应内容每次必须完全一致。

读取课程可以产生访问日志，但不应顺便扣费或删除课程。重复删除同一资源后，状态码可能不同，最终“资源已删除”的效果仍可能符合幂等。

## 方法语义与业务实现

GET 用于获取表示，HEAD 获取相应元信息而不返回正文，POST 常用于提交由资源处理的操作，PUT 表达以请求表示建立或替换目标资源，DELETE 请求移除目标关联。PATCH 用于部分修改，其幂等性取决于补丁语义：设置 count=1 与 count+=1 不同。

方法名不会自动赋予实现正确性。若 PUT 每次都追加一笔扣费，代码就违背了预期幂等行为；POST 也可以通过业务幂等键实现安全重试。自动化客户端和中间层会利用方法语义，因此用 GET 执行有副作用操作还可能被预取、缓存或爬虫意外触发。

幂等关注预期效果，不要求每次返回同一时间戳或日志完全不变。安全也不等于无需权限，读取私人数据仍需认证与授权。请求正文、缓存与条件头的使用要按相应协议和服务契约说明，避免依赖各客户端支持不一致的行为。

## 配套代码：HTTP 方法、安全性与幂等性：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

resource={'count':0}
for _ in range(2): resource['count']=1
show(resource['count'])
for _ in range(2): resource['count']+=1
show(resource['count'])
```

重复设置固定值与重复增量产生不同效果，说明 PATCH 的语义取决于操作。这个内存模型不执行 HTTP 请求，真实服务还要处理并发、原子提交与重复请求缓存，不能仅用最后的数值推断网络协议实现正确。
