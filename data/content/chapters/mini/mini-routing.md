## 从具体问题认识五种路由 API 与页面栈

页面栈可以理解为用户当前导航路径的一组页面实例。打开新页面通常把新实例压到栈顶，返回则移除顶部实例并重新显示下面的页面。导航 API 的差别，核心在于如何改变这组实例，而不仅是“都能跳转”。

列表进入详情时通常希望保留列表位置；登录完成进入主界面时，可能不希望返回到登录页。两种需求对应不同的栈操作，选错 API 会造成返回路径奇怪、实例重复或数据刷新时机错误。

## 五类导航操作对应什么状态变化

navigateTo 用于保留当前页并打开非 tabBar 页面；redirectTo 用于关闭当前页再打开目标非 tabBar 页面；navigateBack 返回已有页面；switchTab 转到 tabBar 页面并按平台规则调整其他页面；reLaunch 则重新建立导航入口。具体限制应查当前文档，不能把这些操作看成同义词。

路由参数通常是可序列化的标识，例如商品 ID，而不是整个复杂对象或秘密凭证。目标页根据 ID 获取并校验数据，保证直接打开、分享进入和恢复时都能工作。URL 参数属于外部输入，应校验格式与权限，不能因为来自本应用的按钮就假设可信。

跨页通信需要区分持久共享状态和一次性结果。用户资料适合由统一状态层管理，选择地址后返回一个结果可用明确的事件或回传协议。返回后是否重新请求，应由数据是否过期或是否发生修改决定，避免每次显示都清空列表再加载。

## 把机制放到一条完整路径中

```flow
从跳转意图到页面栈
明确意图｜新增替换返回还是重建入口
选择 API｜匹配目标页类型与栈语义
校验参数｜只传必要业务标识
恢复状态｜按变化刷新返回页面
```

## 配套代码：压栈、替换、返回的状态模型

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

数组代表页面栈，只演示 navigateTo/redirectTo/navigateBack 的核心意图。

```javascript
const stack = ['首页'];
function navigateTo(page) { stack.push(page); }
function redirectTo(page) { stack[stack.length-1] = page; }
navigateTo('商品'); navigateTo('确认页');
redirectTo('结果页');
console.log(stack);
stack.pop();
console.log(stack);
```

压栈保留旧页，替换只改当前层，返回移除顶层。这里没有模拟 tabBar、页面栈上限和真实生命周期，实际路由规则以微信宿主为准。

## 从示例走向实际使用

画出“列表→详情→编辑→保存返回”的栈变化，同时标注每一步谁拥有数据。保存后可把变更标识传回，列表按 ID 更新或重新验证；不要依赖页面栈固定下标去访问另一个页面内部对象。

对分享直达、重复点击跳转和登录拦截分别测试。登录后恢复原目标需要保存经过校验的目标路径，并防止再次跳到登录页形成循环。
