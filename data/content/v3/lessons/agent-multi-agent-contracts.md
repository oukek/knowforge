## 先证明单 Agent 的瓶颈
把系统分成“规划者、研究员、审查员”不会自动提高质量。多 Agent 带来额外模型轮次、上下文复制、冲突和调试成本。只有任务可并行、专业上下文确实不同或权限需要隔离时，分工才可能有收益。先与单 Agent 加明确工具的基线对比。

单次汇总多个观点不等于事实已验证。相同模型、相同来源的多个回答可能高度相关，多数投票不能消除共同错误。关键结论仍需证据或程序校验。
## 子任务契约应比角色描述具体
每项子任务包含目标、输入快照、可用工具、资源范围、完成判据、输出 schema、预算和截止点。研究子任务返回事实与来源，不直接修改共享订单；执行子任务只接受已验证动作，不根据闲聊重新决定金额。

```js
const assignment = {
  id: 'research-policy', inputVersion: 7,
  output: ['claims', 'evidenceIds', 'unresolved'],
  canWrite: false, maxSteps: 4
};
```

LangGraph 子图可以提供组合边界；OpenAI Agents SDK 中 handoff 与把 Agent 当工具会影响控制权和结果回流方式。选用时明确谁掌握主任务，而不是只比较语法短不短。
## 共享状态需要所有权
把输入快照设为只读，各 worker 返回局部结果，协调者按规则合并。每个字段应定义单一写入者，或明确 reducer 的去重、交换律和冲突语义。两个 Agent 同时写 summary，最后写入者胜出会隐藏不一致。

| 状态 | 建议所有者 | 合并原则 |
|---|---|---|
| 用户目标 | 主任务协调者 | 用户变更触发新版本 |
| 检索事实 | worker 结果集 | 按稳定 ID 去重并保留来源 |
| 最终决定 | 明确决策节点 | 规则校验、冲突不静默覆盖 |
| 业务提交 | 受限执行服务 | 幂等和资源版本条件 |

不要让子任务通过共享全局变量绕过输入输出契约；跨租户或跨任务结果不得混入同一 reducer。
## 交接与恢复
交接应传目标、已确认事实、未决问题和授权边界，不是复制全部聊天历史。输入快照版本改变时，旧 worker 的结果可能已过期，协调者必须校验版本。handoff 只改变控制权，不自动转移真实用户授权。

失败时区分可独立重跑的只读子任务与已发生副作用的执行。回收所有子任务预算，避免协调者重试时又开启一组无人跟踪的 worker。终止条件包含成功、无进展、重复任务、成本与时间上限。
## 可运行实验：同 ID 不同事实要冲突
实验把两个 worker 的结果按 fact id 合并，相同内容的重投递去重，不同内容抛出冲突。它不实现模型协商，而是验证协调者的确定性边界。若只做对象展开，后一个值会悄悄覆盖前一个，失去排查线索。

修改一个 worker 的版本，让同 ID 对应不同价格，观察冲突；再采用不同 ID 保留两个来源，要求决策节点显式比较适用条件。事实归并不应通过“哪个 Agent 更自信”来决定。
## 用收益和失败成本决定是否保留分工
固定任务集对比单 Agent、多个工具以及多 Agent 三种方案，记录业务成功、总轮次、关键路径、总成本、冲突与人工接管率。并行只缩短可并行部分，串行协调和重复检索可能抵消收益。

加入 worker 超时、重复结果、输入版本变化、互相交接循环和权限升级请求。只有分工在质量、隔离或交付上产生可测收益时才值得保留；更少的角色和更清楚的契约通常更容易维护。
