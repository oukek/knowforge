## 从具体问题认识RAG 故障定位

RAG 排障的关键是找到证据在哪一步丢失。最终回答错了，可能是原文没有答案，也可能是正确片段已经召回却在预算裁剪时被删掉。直接换 embedding 或大模型，很容易改了不相关的环节。

为同一个失败问题保存语料版本、标注证据、候选排名、最终上下文与答案，才能把笼统的“效果差”拆成具体故障。

## 用阶段差集定位首次偏差

设必要证据为 A、B，初检候选含 A、B、X，而最终上下文只有 A、X。此时初检召回并没有漏掉 B，问题在重排或装配。比较阶段集合的差集，可以先缩小排查范围，再分析 B 被移除的原因。

Recall@k 看相关项覆盖，Hit@k 看是否至少命中一项，MRR 看首个相关项位置。多证据问题只命中一项可能仍无法回答，所以不能只用 Hit 宣称检索足够。空标注样本应单列，无答案能力另行评价。

诊断实验固定其他环节，分别尝试精确检索、不同候选数、关闭重排或保留完整上下文。若精确搜索也找不到正确片段，问题可能更靠前，如分块、编码或标注；若仅 ANN 丢失，再检查索引搜索参数。

## 把端到端错误拆成可观测阶段

知识助手回答错误，至少有四种不同原因：正确文档没进候选、进入候选但重排靠后、进入上下文前被预算裁掉、模型拿到证据仍回答错误。每阶段保存带版本的文档 ID 和分数，形成候选集、重排集、实际上下文集与最终主张的链路。只记录最后答案无法判断改 embedding 还是改生成契约。

数据入库也可能已经出错：扫描 PDF 的否定词被 OCR 丢失，表头与数据分开，时间范围没提取。先检查实际索引文本，而不是把原文件可读等同于模型可检索。

## 指标分母必须先定义

对于有明确相关文档集合的查询，Recall@k 是前 k 个唯一结果命中的相关文档数除以相关文档总数；MRR 是首个相关结果排名倒数的平均值。重复 ID 不能重复计命中。某些任务只需一篇完整证据，另一些需要多文档联合，不能把两种任务的覆盖标准混在一起。

无答案查询没有正例集合，Recall 分母为零，应返回未定义并单独评价拒答，而不是自动算满分。语料标注可能不完整，新增正确文档应经过人工补标，不能简单把所有未标记文档都判错。

## 一个最小诊断样例

设 Q1 需要 `{a,b}`，结果 `[a,x,b]`，Recall@2 为 1/2，Recall@3 为 1；Q2 需要 `{c}`，结果 `[x,c]`，首个相关排名为 2，倒数为 1/2。若将 Q1 的 `[a,a,b]` 当成两个命中，会错误夸大前两条覆盖。实验使用集合去重，同时保留原始排名用于首个相关位置。

```python
def recall_at_k(relevant, ranked, k):
    if not relevant:
        return None
    return len(set(ranked[:k]) & relevant) / len(relevant)
```

再比较 `candidateIds`、`rerankedIds`、`contextIds` 三份列表，找出证据首次消失的位置。仅比较最终 Recall 无法识别上下文裁剪的问题。

## 混合检索与重排怎样做消融

固定语料版本、查询、权限和预算，分别运行关键词、向量、混合以及混合加重排。先检验专有名词、编号、日期范围、多语言与否定条件切片，再看总体分。向量分数和 BM25 分数通常不在同一尺度，直接相加缺少依据；RRF 等按排名融合方法也有需要验证的超参数。

重排能提升候选排序，不能找回根本没被召回的文档。提高 top-k 会增加延迟和噪声，也可能挤掉更完整的证据。评估时固定最终输入预算，否则把更多 token 带来的收益误认为排序算法收益。

## 权限、更新与删除也是正确性

检索过滤需带租户和可见范围；候选进入模型前再次确认权限与版本。先全库检索再展示时过滤，可能既泄漏内容又降低有权限候选覆盖。向量库是否支持预过滤、怎样与近邻搜索配合，必须对所用实现测量。

更新文档要记录 sourceVersion、chunkVersion、embeddingVersion 和索引构建版本；删除与权限撤销要传播到索引、缓存、摘要和生成引用。旧文档残留往往表现为“模型幻觉”，但根因在数据链路。

## 以一张错误卡片完成排障

每个失败样本记录：用户问题、期望证据及标注理由、实际候选与排名、进入模型的精确片段、最终主张和引用、各阶段耗时、版本和授权范围。选取一个失败样本逐步注入正确候选、正确上下文，观察错误在哪一步消失，这是一种受控消融。

验收要包含有答案、无答案、多证据、冲突、旧版本、跨租户和恶意文档。分别报告检索覆盖、答案证据支持率、拒答准确性、延迟及成本。没有一个平均“RAG 分数”能替代这些诊断维度。

## 把机制放到一条完整路径中

```flow
RAG 定位
核实原文｜确认必要证据存在且有效
比较候选｜检查初检是否覆盖标注证据
比较上下文｜定位重排与裁剪造成的丢失
核对答案｜证据齐全后检查生成与引用
```

## 配套代码：RAG 故障定位：从召回漏失到证据被截断

下面代码在课内Python运行区执行；浏览器环境与本机CPython的网络、文件和原生扩展能力不同。



```python
def recall_at_k(relevant, ranked, k):
    if not relevant:
        return None
    return len(set(ranked[:k]) & relevant) / len(relevant)

def reciprocal_rank(relevant, ranked):
    return next((1 / i for i, doc in enumerate(ranked, 1) if doc in relevant), 0)

print(recall_at_k({'a','b'}, ['a','a','b'], 2))
print(recall_at_k({'a','b'}, ['a','a','b'], 3))
print(reciprocal_rank({'c'}, ['x','c']))
print(recall_at_k(set(), ['x'], 1))
candidate, context, required = {'a','b','x'}, {'a','x'}, {'a','b'}
print(sorted((candidate & required) - context))
```

重复文档不会提高召回率；没有正例集合时返回 None。最后一行找出候选中有、却未进入模型上下文的必要证据 b。

## 从示例走向实际使用

用错误卡片记录现象、首次偏差、假设、验证与修复结果，积累可重放回归集。每次提升报告受益切片与退化切片，避免一个平均值掩盖新问题。

课内重复候选只按集合计相关项，避免重复命中虚增召回；排名位置仍按真实列表计算，反映重复内容占用位置的代价。
