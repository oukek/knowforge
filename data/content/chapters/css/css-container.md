## 从具体问题认识CSS 变量、容器查询与主题

CSS自定义属性把值命名并通过层叠与继承传递，适合表达颜色、间距和主题令牌。它不是构建时简单文本替换：浏览器在具体元素上结合当前值解析var，因此同一个组件可在不同祖先主题中得到不同外观。

容器查询则根据组件所在容器的条件调整样式。页面视口很宽，但卡片被放在窄侧栏里时，媒体查询不一定能表达它真正拥有的空间，容器查询解决的是这种组件局部适配。

## 值的层叠、回退与容器隔离

自定义属性通常参与继承，可以在根定义默认主题，在局部区域覆盖。var的回退值处理未提供或相应无效情况，但不能当作任意业务校验；某个变量展开后对目标属性无效，最终值还要遵守CSS计算规则。使用@property注册可以声明语法、继承与初始值，但支持与行为需按环境验证。

建立尺寸查询容器需要相应container-type，查询描述后代在容器条件下使用哪些样式。容器隔离有布局语义，不能随便给所有祖先设置后假定尺寸计算不变。命名容器有助于深层组件明确参照哪一层，而不是意外命中最近的其它容器。

主题不应仅切换背景色，还要检查文字对比、边框、焦点和错误状态。业务品牌色、语义色与组件局部值可以分层命名，避免每处硬编码导致更换主题时遗漏。样式数据来自外部配置时也应限制允许值，不把任意CSS注入当普通颜色设置。

## 浏览器实验：同一卡片适应容器

修改host宽度即可观察卡片布局变化；变量定义在容器上并向后代传递。容器查询规则作用于后代，未支持时仍保留基础块布局。

```html
<style>
.host { container-type:inline-size; --accent:#28684f; width:80%; }
.card { border:1px solid var(--accent); padding:1rem; }
@container (min-width:30rem) { .card { display:flex; gap:2rem; } }
</style>
<div class="host"><div class="card"><strong>课程</strong><span>随容器调整</span></div></div>
```

## 把机制放到一条完整路径中

```flow
组件局部样式计算
层叠得到主题变量｜根默认与局部覆盖
确定查询容器｜容器类型和名称影响参照
根据可用空间选规则｜组件宽度与视口宽度分开
验证可读与可操作｜颜色、焦点、溢出和回退
```

## 配套代码：组件宽度与视口宽度不同

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

用 JS 模拟一个组件按自身宽度切换布局。真实样式应由 CSS 容器查询完成。

```javascript
function columns(containerWidth) { return containerWidth >= 480 ? 2 : 1; }
const viewportWidth = 1440;
console.log(columns(280));
console.log(columns(640));
console.log(viewportWidth >= 480);
```

视口虽宽，但侧栏组件可能只有 280px，仍应单列；主区域 640px 可以双列。这说明查询对象应是组件容器，而非把所有布局都绑定视口断点。

## 从示例走向实际使用

先为一个卡片定义少量语义令牌，再把它放进宽主区域和窄侧栏，验证同一组件的适应性。没有容器查询支持时提供可用基础布局，功能不应整体消失。

测试不同主题、大字体、长文本和嵌套容器。CSS变量减少重复，不替代设计规则；命名应描述用途，而不是只有green1、green2让人猜。
