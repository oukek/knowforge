## 从具体问题认识作用域、提升与 TDZ

程序里的变量名不是一个全局通讯录。函数、模块和代码块各自建立名字所在的环境，作用域规定某段代码能查找哪些绑定。绑定是“名字与值之间的关联”，不同作用域里的同名变量可以同时存在，内层名字会遮蔽外层。

JavaScript主要采用词法作用域：函数创建的位置决定它向外查找的路径，后来从哪里调用不会重新选择这条路径。学习提升之前，先把源文件画成嵌套的块和函数，再把每个声明放进所属环境，这比把所有变量想成挂在window上准确。

## 声明、初始化与赋值三个时刻

声明建立绑定，初始化使它开始具有可读取的值，赋值则改变已经初始化的绑定。var在相应环境建立时通常先初始化为undefined；let和const虽然在块内已经有绑定，但要执行到声明处才初始化。此前区域叫暂时性死区（TDZ），读取会抛ReferenceError，并不会越过这个未初始化的内层名字去找外层值。

例如外层有let n=10，内层块里先读取n、后写let n=20，第一次读取已经被内层声明遮蔽，因此失败。const约束的是绑定不能再次赋值，不会递归冻结对象；const state={}之后修改state.name仍然是对同一对象的操作。函数声明和赋给变量的函数表达式又有不同初始化过程，不能只背一句“函数会提升”。

循环里的let为迭代建立相应绑定，保存的回调可读取各轮自己的变量；var常让这些回调共享同一函数级绑定。闭包保留的是访问环境的能力，不是自动复制所有当时值。typeof未声明名字可以得到undefined字符串，但访问TDZ里的名字仍失败，因为这两种情况不是同一种查找结果。

## 把机制放到一条完整路径中

```flow
名字查找与读取
确定当前词法环境｜函数或块由定义位置决定
向内到外查找绑定｜内层同名声明遮蔽外层
检查是否已初始化｜TDZ中的绑定不能读取
读取或修改值｜const限制重新绑定，不冻结对象
```

## 配套代码：TDZ 和循环绑定

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

观察未初始化的词法绑定与每轮 let 的独立闭包。

```javascript
try {
  console.log(typeof value);
  let value = 1;
} catch (error) {
  console.log(error.name);
}
const callbacks = [];
for (let i = 0; i < 3; i++) callbacks.push(() => i);
console.log(callbacks.map(fn => fn()));
```

typeof 不能绕过 TDZ；循环 let 创建逐轮绑定，三个闭包读取各自的 i。把 let 改成 var 可观察所有回调共享同一绑定。

## 从示例走向实际使用

在模块、普通脚本和函数中分别验证顶层变量，不把浏览器全局对象的行为套给ESM。排查变量错误时先判断在哪个环境查找，再判断绑定是否初始化，最后才检查赋值内容；异常类型不同往往对应不同阶段。

实际开发优先让变量靠近使用范围，保持名字含义稳定。需要跨组件共享的数据应显式传递或由状态所有者管理，不要借同名全局变量建立隐式依赖。例子中的try/catch用于观察TDZ，并非建议用捕获ReferenceError代替清楚的初始化顺序。
