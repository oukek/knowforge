## 从具体问题认识Stream、背压与 pipeline

Stream 是分块处理数据的接口。读取一个大文件时，可以边读边发送，而不是先把整个文件放进内存。它降低的是同时保留的数据量，并让生产与消费可以交错进行，不保证每个使用流的程序都自动节省内存。

如果源每秒产生 10 MB，而目标只能处理 2 MB，中间仍会积压。背压是消费者把“先慢一点”的信号传给生产者，让数据流速受到下游能力约束。

## 缓冲区、背压与完整结束

Node 的可读流提供数据，可写流接收数据，转换流把输入变成输出。每一段可能都有缓冲，因此内存上界需要把各段缓冲与应用自己的待处理任务一起计算。highWaterMark 是影响背压的阈值，不是绝对内存硬上限，也不能限制你额外创建的 Promise 数量。

可写流 write 返回 false 时，表示当前数据已经交给流，但缓冲压力要求调用者暂停继续写入，通常等待 drain 再恢复。若把 false 当成写入失败并重发同一块，会重复数据；若忽略它持续写，就可能无限堆积。

pipeline 可以帮助连接多段流并处理错误与结束，但程序仍需处理业务副作用。例如下载失败后不能把半个文件当完整产物发布。正常结束、源错误、目标错误和主动取消都应关闭资源，并决定临时文件是否删除。流式转换还必须正确处理跨块字符、记录和协议边界。

## write(false) 的精确语义

该块数据已经被接受，只是缓冲到达水位；调用者应暂停后续写入，等 drain 再继续下一块。将同一块重写会产生重复内容。highWaterMark 不是进程级硬上限，还需计入每段流、对象模式的大对象和业务缓冲。用慢速 Writable 注入背压，观察队列是否稳定而非持续线性增长。

## 错误与取消必须穿透整条链

读取、解压、变换、写入任何一段失败，都应停止其他段并释放文件/网络资源。pipeline 汇聚完成与错误，AbortSignal 用于外部取消，但 CPU 循环仍需主动检查或移出线程。使用传输中途断开、磁盘写满、解析错误和消费超时做测试，确认没有挂起的 drain 等待和遗留任务。

## 把机制放到一条完整路径中

```flow
受控流式处理
分块读取｜避免一次加载全部数据
有限缓冲｜记录待消费数据量
反馈背压｜下游慢时暂停继续生产
完成清理｜统一处理成功错误和取消
```

## 配套代码：背压让生产者等待消费者

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

用异步逐项消费模拟限制积压；不调用 Node Stream，也不模拟 write/drain 的完整协议。

```javascript
let buffered=0, peak=0;
for (const chunk of ['A','B','C']) {
  buffered++; peak=Math.max(peak,buffered);
  await new Promise(resolve=>setTimeout(resolve,5));
  buffered--;
  console.log('消费',chunk);
}
console.log(peak);
```

每次等待消费完成再生产下一项，积压峰值为 1。真实 Stream 用 write 返回值和 drain/pipeline 传播背压，并处理错误和客户端断连。

## 从示例走向实际使用

实际文件处理可使用 node:stream/promises 的 pipeline，把输入流、转换器与输出流连接起来，再 await 整条链完成。只有完成后才更新业务状态为成功。

课内的串行消费实验表达“消费完成再继续”的节奏，真实 Node 代码与更多故障实验在流式处理进阶课程中展开。验证时加入慢消费者与中途错误，观察内存是否稳定。
