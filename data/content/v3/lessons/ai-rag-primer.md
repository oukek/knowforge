## Retrieval-Augmented Generation 的意思
RAG 是 Retrieval-Augmented Generation，检索增强生成：在生成之前或过程中找出相关外部信息，把证据放进模型可用上下文，再组织回答。它通常不修改模型参数，知识更新主要发生在文档与索引。不是把文档传过一次，模型就永久学会。

它适合有可检索知识、需要更新或追溯来源的任务。没有可靠资料时，RAG 不能凭空制造真相；精确库存与订单状态通常更适合结构化查询。检索文档仍需权限与时效控制。
## 离线与在线两条链路
离线：获取文档 → 解析清洗 → 分块 → embedding/关键词索引 → 元数据和版本入库。在线：理解查询 → 权限过滤 → 召回 → 融合/重排 → 选择证据 → 生成 → 主张与引用校验。两条链路分别观测，索引阶段丢失的信息很难靠生成补救。

| 环节 | 核心问题 | 常见坏例 |
|---|---|---|
| 分块 | 条件和结论能否一起看到 | 表头与数字拆开 |
| 召回 | 正确证据是否进入候选 | 产品编号匹配失败 |
| 上下文 | 预算内保留什么 | 关键条款被截断 |
| 生成 | 是否忠于证据 | 忽略“仅企业版” |

提高 top-k 不一定改善最终正确率，噪声和预算挤占也可能增加。
## 与搜索、微调、Agent 的关系
搜索可以直接返回文档列表；RAG 增加按证据组织答案。微调改参数行为，RAG 提供运行时事实，两者可组合。Agent 可决定是否检索和下一步行动，但普通 RAG 问答不一定需要 Agent 循环。

向量数据库是可选的检索基础设施，不等于 RAG 本身；小知识集可以先用简单可验证检索。关键是任务、证据和评估，不是堆工具数量。
## 可运行实验：最小词项召回
实验用关键词集合与查询词项的重合数给几份文档排序，再输出选中 ID 和版本。它是显式的词项匹配模型，不是 embedding、BM25 或真实语义理解。修改查询可观察编号或关键词命中，未知词应允许无结果。

即使拿到 top1，也不能自动回答所有问题。验证该片段是否完整支持结论，必要时补充其他文档或拒答。没有证据时返回空集合比随便选一个更符合契约。
## 怎样从最小系统走向可靠系统
先建立固定语料和问题集，包含有答案、无答案、冲突、权限和更新，分别记录召回与答案支持。逐步加入混合检索、重排和查询改写，并做消融比较；不要同时改十个变量后无法解释收益。

面试讲项目要说明语料规模与类型、分块依据、embedding 版本、权限、评估、延迟与坏例。没测过的指标如实说明，并给出补测方案，不编造“召回率 99%”。
