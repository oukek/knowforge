## 从具体问题认识AI 助手请求生命周期

AI 助手的一次请求，从用户点击发送开始，到可靠交付结果结束，经过的不只是模型 API。身份、任务创建、检索、工具、事件推送、结果保存和额度结算共同构成完整生命周期。

例如用户查询订单，后端首先确认身份与可见订单，然后准备上下文，模型可以提议查询工具，工具返回受控事实，最终结果与任务状态一起保存。

## 应用任务与模型尝试分层

任务是用户可追踪的一次业务工作，尝试是调用某个上游的一次执行。一个任务可能有多次尝试，但前端不应因此出现多个重复结果或重复扣费。重试沿用任务身份并单独记录尝试、原因与计量。

实时通信传递排队、检索、工具执行和完成等事件，事件有序号或快照版本。SSE 或 WebSocket 是传输选择，可靠性来自服务端持久状态与重连协议。断开连接不自动表示业务取消，用户取消也需要服务端确认当前可取消阶段。

工具使用认证上下文校验资源，而不是相信模型声明的租户。任务最终成功应以必要业务写入和结果保存完成为依据，费用预留按明确规则结算。前端的动画和文本只是状态的呈现。

## 先定义助手能做什么

问答助手、执行固定流程的工作流和可自主选择工具的 Agent 有不同风险与验收。以企业订单助手为例，回答订单规则可走受控 RAG，查订单走已授权工具，退款需审批及幂等业务 API。不要为了“智能”让模型决定用户是谁、可以访问哪些租户或是否有权付款。

## 一次请求怎样流转

入口生成 requestId，验证登录、租户与任务限制，建立 deadline 和资源预占。先识别意图并澄清关键缺项，按任务装配最小必要的历史、记忆、技能与证据；再选择满足能力、成本与区域约束的模型。模型可以返回答案或工具提议，运行时负责参数、权限和风险校验，再执行并将结构化观察送回下一轮。

所有循环有最大步数、工具调用数、token、费用和时间上限。工具失败要返回明确可诊断状态，重复调用用稳定 operationId 去重。写操作在执行前保存意图并必要时审批，执行后保存业务结果；检查点只保存运行进度，不自动提供外部副作用恰好执行一次。

## 状态与前端如何一致

运行状态至少区分 created、running、waiting_approval、completed、failed、cancelled 和 unknown_external_result。流事件携带 runId 与序号，客户端重连只追加缺失事件，不能把模型第二次回答拼到第一次尾部冒充恢复。浏览器断开是否取消后台任务应有明确策略，完成结果仍可查历史。

## 用订单场景走一遍

用户问“把昨天那笔退款”：先解析相对时间及用户时区，再确认是哪笔订单与授权，展示可退款项及影响，用户确认后执行。工具返回“超时但可能已提交”时先以 operationId 查业务状态，再决定下一步，不能换模型再退一次。最后给出来源或操作凭证，并结算资源、记录用量与审计。

## 示例、故障与观测

可运行模型只展示工具提议经过参数与授权过滤后的结果。实际系统每一轮记录模型、工具版本、输入摘要、开始结束、状态与错误，正文按最小必要脱敏。用无权限订单、参数缺失、审批拒绝、重复提交、上游超时和循环不终止等样本验证，不能只演示理想路径。

## 面试时讲清自己的实现范围

按入口、上下文、路由、模型循环、执行、持久化与评估画架构，再用一次失败轨迹解释组件职责。若只做过受控问答，就明确没有自主写操作和多 Agent，而不是把所有术语堆上去。方案完整性体现在失败能被解释、重试不会重复扣款、身份边界无法被提示覆盖。

## 把机制放到一条完整路径中

```flow
助手请求全程
身份与准入｜验证任务范围权限和预算
编排执行｜检索模型工具及有界重试
实时同步｜持久状态驱动阶段事件与恢复
完成结算｜保存结果回执和实际额度消耗
```

## 配套代码：AI 助手请求生命周期：从身份到可靠交付

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

使用本地 JavaScript 模型验证关键不变量；不调用真实数据库、模型或生产服务。实验简化之处与真实系统步骤见正文。

```javascript
function authorize(call, session) {
  if (call.name !== 'readOrder') return 'unknown_tool';
  if (!Number.isInteger(call.args.id)) return 'invalid_args';
  if (call.args.tenant !== session.tenant) return 'forbidden';
  return 'allowed';
}
console.log(authorize({name:'readOrder',args:{id:1,tenant:'A'}},{tenant:'A'}));
console.log(authorize({name:'readOrder',args:{id:1,tenant:'B'}},{tenant:'A'}));
console.log(authorize({name:'refund',args:{id:1,tenant:'A'}},{tenant:'A'}));
```

本段程序用于把状态、条件和数据之间的关系写清；真实实现仍需上文介绍的资源、权限与失败协议。
