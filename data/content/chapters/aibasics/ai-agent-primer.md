## 从具体问题认识AI Agent 是什么

AI Agent 围绕目标，根据当前观察选择行动，执行后再利用结果决定下一步。它的特点是部分控制流由模型动态决定，而不只是一次文本生成。一个名叫“专家”的聊天角色，如果没有行动与反馈循环，并不会仅因名字成为可靠智能体。

例如排查测试失败的 Agent 可以读取错误、查看代码、修改候选位置、运行测试，再根据结果继续。能否完成任务，还取决于工具权限、状态、预算和验证。

## 目标、观察、行动与停止

目标需要可判断的完成条件，如指定测试通过且未破坏相关行为。观察来自用户输入、工具结果和持久任务状态，行动通过受控工具执行。每轮模型选择后，运行时验证参数与权限，再把结果作为新观察输入，而不是直接相信模型的自我报告。

Harness 是围绕模型运行的执行组织，包括循环、工具、上下文、恢复、审计与停止规则。它负责把模型提议转成可控行为。模型能力强并不意味着 harness 可以省略幂等、取消或资源限制；这些是系统保证。

停止条件包括完成、无法继续、需要用户信息、预算耗尽与明确失败。仅限制最大轮数可以防无限循环，却不能保证此前步骤有价值。应检测重复无进展动作、工具错误与目标偏离，并提供可解释终态。

## 智能体的核心不是角色名字

在 LLM 应用中，Agent 通常指利用模型根据目标和当前状态选择行动，调用工具获取观察，再继续决策直到满足停止条件的系统。简化循环是 state → decision → action → observation → state。并非每次都需要工具，也并非所有多轮聊天都构成有意义的业务 Agent。

模型提出行动，宿主程序验证并执行。模型不能直接获得数据库、文件和支付系统的任意权限。提示里写“你是经理”不代表拥有审批权，名字叫 Researcher 也不证明有独立研究能力。

## 与聊天、Copilot 和工作流怎么区分

普通聊天主要返回内容；Copilot 通常辅助用户并保留明确人为控制；固定工作流明确安排节点和路径；Agent 在允许范围内根据观察选择下一步。真实产品可以混合：外层固定认证和审批，中间研究节点动态选择工具。

| 系统 | 谁选择下一步 | 适用判断 |
|---|---|---|
| 单次生成 | 调用者固定 | 摘要、草稿、抽取 |
| 固定工作流 | 代码明确路由 | 步骤已知且强约束 |
| Agent | 模型加宿主策略 | 下一步依赖不确定信息 |
| 多 Agent | 多个受约束子任务 | 分工收益需测量 |

自主性越高，需要的预算、状态、观测与恢复设计通常越多，不是只加一个循环。

## Harness 为什么重要

Harness 可以理解为围绕模型的运行支撑：工具注册与执行、上下文装配、状态持久化、权限、预算、取消、日志和验收。框架可以提供部分能力，应用仍需定义业务契约。MCP 是连接协议的一部分，不等于完整 Harness。

每个行动有工具名、参数、调用 ID，结果有结构化值和明确错误。停止包括业务完成、需要用户输入、资源预算耗尽、失败和无进展；不能只依赖模型说“我完成了”。

## 什么时候不该上 Agent

固定公式、权限校验、单步格式化或路径完全已知的流程，普通函数与工作流通常更易测试。先与单次模型加规则基线比较，只有动态决策带来可测收益才增加自由度。

学习验收是能画出目标、状态、策略、工具与停止条件，说明每一层失败如何处理，再给一个不能交给模型决定的权限例子。Agent 是完整系统问题，不能只回答某个 SDK 类名。

## 把机制放到一条完整路径中

```flow
Agent 循环
明确目标｜定义完成条件与允许范围
读取观察｜取得当前状态与工具结果
选择执行｜模型提议宿主校验并行动
评估停止｜完成失败补充信息或继续循环
```

## 配套代码：AI Agent 是什么：目标、行动、观察与停止

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
const tools = { lookup: () => ({ stock: 3 }) };
const state = { fact: null, steps: 0 };
function policy(s) {
  return s.fact
    ? { kind: "final", answer: "stock=" + s.fact.stock }
    : { kind: "tool", name: "lookup" };
}
let result;
for (let i = 0; i < 3; i++) {
  state.steps++;
  const action = policy(state);
  if (action.kind === "final") {
    result = action.answer;
    break;
  }
  if (!Object.hasOwn(tools, action.name)) throw Error("unknown tool");
  state.fact = tools[action.name]();
}
if (!result) throw Error("step budget exhausted");
console.log(result);
console.log(state.steps);
```

policy 是确定性替身，tools 是本地假数据。真实 Agent 需模型、认证、参数与资源授权、预算和持久恢复，本例只验证循环边界。

## 从示例走向实际使用

先判断任务是否真的需要动态行动。固定步骤的审批或数据转换用显式工作流往往更容易验证；只有观察会影响下一步选择时，Agent 才更有价值。

课内确定性循环用于展示结构，不代表具备真实智能规划。后续框架课程会把状态、工具与恢复落实到不同运行时中。
