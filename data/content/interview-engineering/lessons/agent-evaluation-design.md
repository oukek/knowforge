## 从任务契约开始构建
先把任务写成可判定的输入、允许动作、资源边界、最终产物和失败退出条件。例如“修复一个复现稳定的缺陷，提交最小补丁并通过指定回归”，比“当一个优秀程序员”可验证。确定固定流程是否足够，只有确需根据环境反馈选择下一步时才增加 Agent 循环与工具自主性。
## 最小运行时包含什么
状态记录目标、版本、已执行行动、观察、预算与终止原因。模型提出行动，宿主校验工具白名单、参数、路径与权限后执行。失败返回结构化观察，允许有界修正；写入操作使用幂等键。不能把模型口述“我已经测试通过”当成工具执行事实，必须保存测试退出码和产物证据。
## 效果好坏分三层评价
结果层看任务约束是否满足、事实或补丁是否正确；过程层看工具选择、无效循环、越权、重复副作用；运营层看人工接管、返工、P95、费用与用户采用。轨迹不必与唯一标准路径逐步相同，合法不同路径可以成功；但违规动作即使最终答案正确也要单独计失败。

评估集覆盖正常、长尾、无答案、权限、工具故障、长任务和中断恢复，并按任务类型分层。冻结验证集避免一边调提示一边记答案。相同模型多次运行估计波动，记录模型、提示、工具、数据版本；平均成功率会掩盖关键安全任务退化。
## 自动评分与人工校准
可执行断言、业务状态与引用校验优先；开放文本可以用量表和模型评审，但要抽样人工复核一致性、偏好和位置偏差。将答案与来源视为不可信输入，避免被评估内容指示评审器给满分。pass@k 表示允许多次尝试至少成功一次的某种口径，不能包装成单次生产成功率，成本也必须一起报告。

## 如何回答项目追问
给出任务定义、基线、样本来源、评价规则、失败分类与一次具体改进；没有线上数据时就说明只有离线实验。面试官更关心你如何证明 Agent 值得使用，以及失败后如何安全收敛，而不是你接了几种框架或模型。

## 朋友原题与口述参考
**原题记录：** ai agent怎么做的，怎么评估他的效果好坏？

从任务和可判定验收定义 Agent：目标/状态、模型决策、工具执行、观察回路、持久化与停止预算。执行层强制权限、参数和幂等，不靠提示约束；固定工作流足够时不强上自治。

评估分结果、过程与业务：任务正确且合规完成率，工具/权限/循环错误，人工接管和返工、P95、费用。冻结分层样本，用可执行验证与人工校准模型评审；同条件多次运行报告波动。给出基线、失败分类、消融与小流量回归，不能用演示成功或模型自评代替效果证据。

## 延伸追问与分析
**Agent 最终补丁通过测试，但多次读了无权限文件，这次算成功吗？**

结果与过程分别计分，越权触发安全失败，不能被最终正确覆盖。工具层应阻止越权并记录，修复能力边界后重跑对抗和正常任务，观察是否影响合法成功率。

检查点：过程约束、强制边界、独立指标。

**调提示后成功率从 80% 到 86%，你如何判断真的提升？**

确认同一冻结任务集、预算、版本和评分，采用配对差例分析并重复运行衡量随机性。报告样本量、不确定区间、分任务变化与成本；排查测试集泄露和评审偏差，再做小流量验证。

检查点：对照条件、随机波动、分层代价。

**多 Agent 比单 Agent 贵三倍，怎样证明这不是多此一举？**

用同一任务和总预算比较单 Agent、固定分工与动态协作；看任务成功、协调冲突、P95、人工返工。若提升只来自多次采样，就用单 Agent 多尝试作基线；复杂度需由净业务收益支撑。

检查点：公平基线、协调成本、业务收益。

## 实践任务与验收
选一个任务，例如“根据三份政策回答退费条件并引用有效段落”，人工写出 12 个正例、4 个无答案例、4 个权限反例，冻结文档版本和评分表。先实现固定 RAG 基线，再增加 Agent 的多轮检索，记录每次检索实际增加了哪条必要事实。若任务成功不变而工具调用翻倍，不应继续增加自治程度。

评分至少区分正确且有证据、正确但无支持、事实错误、应该拒答而未拒答、发生越权五类；不要把部分分数相加后掩盖安全失败。将成本按每完成任务统计，失败任务的费用也计入。挑五个模型评审与人工意见不一致的例子修订量表，再复核剩余样本。最后提交一页结论：采用哪个版本、理由、限制、回滚阈值，以及下一轮最值得增加的样本。
