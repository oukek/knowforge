## 从具体问题认识RAG 全链路诊断

“召回率低”和“答案不好”不是同一个故障描述。前者需要有标注证据和指标分母，后者还可能来自过期资料、上下文遗漏、生成失真或引用错误。排障手册的价值是让团队对同一现象采用一致检查顺序。

从一个可以复现的问题开始，沿数据进入系统到答案离开系统的路径追踪，比一次更换多个组件更容易得到可验证结论。

## 用最小实验排除错误假设

先确认用户有权访问的原文确实包含答案，并检查清洗、切分和索引版本。若答案被 PDF 提取漏掉，调大 top-k 无法找回不存在的内容。精确编号与同义表达问题分别检查关键词和向量路径。

拿已知正确片段直接放入上下文，观察回答是否改善。这是定位实验，不是上线方案：若仍然答错，重点看提示、推理与输出验证；若改善，再回到召回、重排和预算裁剪。

每次实验固定问题集和其他配置，记录修改影响的阶段。召回提高可能带来更多噪音和成本，最终还要看完整答案质量。不能把开发样本修好了就当所有用户问题都已解决。

## 从知识进入系统到答案离开系统

离线链路是采集授权数据、解析/OCR、清洗、保留标题与表格、按语义切块、生成 embedding、建立向量及关键词索引、携带文档版本和 ACL。在线链路是鉴权、问题理解或改写、带权限过滤的候选召回、融合去重、重排、按 token 预算组织证据、生成、引用校验与审计。更新和删除链路同样重要，否则回答会持续引用旧政策。

## 先定义“效果差”在哪一层

准备一组代表真实问题的评估数据，标相关证据 ID、必要事实、权限范围、版本与可接受拒答。Recall@K 是召回的相关项占全部标注相关项比例；Hit@K 是是否至少命中一项；MRR 看首个相关位置，nDCG 可表达分级相关。只有一个相关项时两种命中口径可能相同，多证据问题下不能混用。无完整标注的指标也需说明局限。

分别记录候选前 K、过滤原因、融合排名、rerank 前后排名和最终上下文。正确文档根本没入库、召回没有它、重排踢掉它、上下文裁剪丢失它、生成误用它，是五类不同问题，不能都靠换大模型解决。

## 召回率低如何逐层排查

先用 docId 或原文关键句确认文档、版本、租户 ACL、索引是否存在，再查解析丢行、表格碎裂和切块是否截断条件。比较关键词精确检索与向量检索，专有名词、编号和数字可用混合检索；检查 embedding 模型、维度、归一化和查询/文档编码方式是否匹配。ANN 参数调大前先对小样本做精确搜索上界，区分表示问题和近似索引漏检。

提高 K 会增加噪声、成本和延迟，并可能挤掉真正证据；query rewrite 可能改掉限定词，必须保留原查询作对照。hybrid 的融合与 rerank 阈值需要评估集验证，不能把不同系统的分数直接当统一概率。

## 召回有了，回答仍差怎么办

把人工给定的正确证据直接交给同一生成器做 oracle 实验：若仍答错，检查任务指令、表格表达、上下文顺序、引用与输出校验；若变好，优先修检索路径。权限过滤始终执行，诊断时不能关闭 ACL 后把越权证据用于回答。证据不足时应承认不足并请求澄清，而非逼模型编造。

## 可运行的小型评估

示例给出两条问题、各自相关文档集合和候选结果，计算 macro Recall@2 与 Hit@2，再比较补回一份关键文档的结果。它不调用 embedding，避免把随机模型输出误当确定性测试。替换集合可构造“至少命中一篇但漏掉另一篇”的多证据反例。

## 验收与面试表达

一次优化固定语料、问题集、版本与预算，只改变一个主要变量，并报告分领域、长尾、权限、过期文档和无答案问题的变化。最终关注事实正确率、引用支持率、拒答质量、P95 和成本；检索指标改善不自动等于业务成功。线上差例回流需要脱敏、人工审核和冻结回归集，不能把测试答案泄露到调参数据。

## 把机制放到一条完整路径中

```flow
RAG 排障手册
复现并标注｜固定问题权限与必要证据
检查入库｜核对清洗切分编码和版本
逐层对照｜比较候选排序与最终上下文
验证修复｜在固定切片上测质量和代价
```

## 配套代码：RAG 全链路诊断：召回、排序、证据与生成

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

使用本地 JavaScript 模型验证关键不变量；不调用真实数据库、模型或生产服务。实验简化之处与真实系统步骤见正文。

```javascript
function metrics(rows) {
  let recall=0,hits=0;
  for (const {gold,found} of rows) {
    const relevant = new Set(gold), top = new Set(found.slice(0,2));
    const count = [...top].filter(id=>relevant.has(id)).length;
    recall += count/relevant.size; hits += count>0;
  }
  return {recall:recall/rows.length,hit:hits/rows.length};
}
console.log(metrics([{gold:['a','b'],found:['a','x']},{gold:['c'],found:['c','d']}]));
console.log(metrics([{gold:['a','b'],found:['a','b']},{gold:['c'],found:['c','d']}]));
```

本段程序用于把状态、条件和数据之间的关系写清；真实实现仍需上文介绍的资源、权限与失败协议。

## 从示例走向实际使用

形成可复现错误集，标注症状、根因、修复和回归条件。面试时用一条真实故障链解释选择，而不是泛泛回答“换更好的向量模型”。

课内 metrics 假设每个样本都有至少一条金标准证据且样本集非空；正式评估需校验这个前提，并单独统计无答案任务。
