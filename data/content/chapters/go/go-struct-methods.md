## 用结构体描述业务数据
struct 把相关字段放进一个具名类型，例如订单的 ID 与状态。方法是关联到接收者类型的函数，不等于必须建立传统类继承树。Go 通过组合和接口组织行为，嵌入字段提供字段与方法提升，但不能把它简单当作其它语言继承的全部替代。

值接收者得到副本，指针接收者可以修改原对象或避免复制较大值。选择时也要看方法集合与一致性，不应只背“有修改就指针，没修改都值”而忽略类型契约。
## 字段与方法把状态和行为放到同一类型上

struct把多个字段组合成一个值，例如Course包含Title和Minutes。字段名表达含义，比把不同意义的值塞进一个slice更容易维护。结构体字面量使用字段名初始化更清楚，也减少字段顺序变化带来的误用。未提供的字段取零值；零值是否可直接使用应成为类型设计的一部分。

方法是在函数声明中增加接收者，表示这段行为属于某个类型。值接收者得到接收者的副本，修改普通字段不会回写原值；指针接收者通过地址访问原对象，适合需要修改状态或避免复制较大对象的情况。一个结构体包含map或slice时，即使复制结构体，内部数据仍可能共享，所以“值接收者”不等于深复制隔离。

## 指针与组合怎样用于对象设计

`&value`取得地址，`*pointer`访问指向的值。Go一般不提供普通指针算术，内存生命周期由编译器与运行时管理；把局部值地址返回可以合法，编译器会安排适当存储，不能照搬某些语言的栈地址规则。nil指针解引用会失败，因此构造与调用契约要明确是否允许nil。

嵌入字段可以提升一些字段或方法的访问，但不是传统类继承系统。若一个服务拥有Logger和Repository，显式字段组合通常能清楚表达依赖；不必为了复用方法大量嵌入导致方法来源难找。构造函数在Go里通常只是返回合适对象的普通函数，用来建立必要不变量，并不一定每个struct都需要一个。

同步原语等有不可随意复制的约束。含Mutex的对象开始使用后不能作为普通值反复复制，设计方法接收者、容器和参数时都要考虑这一点。类型封装不仅是字段私有，还包括修改规则、生命周期和并发契约。

## 完整的计数器类型
```go
package main

import "fmt"

type Counter struct{ Value int }

func (c *Counter) Add(delta int) { c.Value += delta }
func (c Counter) Snapshot() int  { return c.Value }
func main() {
	original := Counter{}
	copy := original
	copy.Add(2)
	original.Add(1)
	fmt.Println(original.Snapshot(), copy.Snapshot())
}
```
copy 是结构体值的复制，所以它的整数 Value 与 original 分开。编译器在适当可寻址场景可以帮忙取地址调用指针方法，但这不改变方法集合的规则；一个类型是否满足接口，仍需按值类型与指针类型分别判断。
## 指针不等于手工内存管理
`&x` 获取地址，`*p` 访问指向的值。Go 通常由垃圾回收管理可达对象，不需要手工 free；函数返回局部变量地址是允许的，编译器和运行时会保证有效生命周期。对象放栈还是堆受逃逸分析等因素影响，不能仅凭有没有 new 判断。
```flow
值与指针的区别
结构体赋值｜复制字段值
字段是普通数值｜副本修改独立
字段含 slice、map 或指针｜内部仍可能共享对象
传入指针｜通过同一目标访问和修改
```
## 封装与并发责任
字段首字母大小写影响包外可见性，但导出字段不能自动验证输入。需要维护不变量的类型可用构造函数和方法限制变化，例如余额不能任意负数。返回内部 map 或 slice 同样会暴露修改入口。

指针接收者也不意味着线程安全；多个 goroutine 同时调用 Add 仍需同步。方法的文档应说明所有权、是否可并发使用和零值是否有效。这些契约比“结构体相当于 class”更能指导真实代码。
