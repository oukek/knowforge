## 先确定需要改变什么
如果问题是今天的库存和内部政策更新，优先改数据接入、检索与工具；如果问题是稳定的输出风格、分类决策或工具使用模式，可以先构建提示和样本基线，再判断训练是否有足够收益。把每天变动的事实写进参数，会增加更新和删除成本，也不能提供逐条来源和访问控制。

SFT 使用输入与目标输出学习期望行为；偏好优化比较同一输入的优劣回答。两者都需要清楚的目标和高质量标注，不能把收集到的全部聊天记录直接当正确答案。用户满意也不一定代表事实或安全正确。
## LoRA 解决的是更新参数化
LoRA 冻结基座权重，用低秩矩阵表示权重增量。对 `W` 为 d×k，增量可写为 `B(d×r) @ A(r×k)`，训练参数量是 r(d+k)，小于完整更新的 dk（当 r 足够小时）。这说明可训练参数减少，不等于所有训练显存只剩这个比例；激活、优化器状态与批次仍影响峰值。

LoRA 不是一种任务目标，可以和 SFT 等训练目标组合。adapter 的效果依赖基座版本和目标模块，不能把一个 adapter 随意装到不同模型。合并、量化、部署时也要核对兼容性并重新验证质量。
## DPO 的数据与目标边界
DPO 使用同一 prompt 的 chosen/rejected 对，围绕偏好与参考策略的相对概率关系优化。它不是给两个不同问题的答案随意排高低，也不是上线后让模型自己打分就能无成本变好。偏好标签要写明理由：事实、指令遵循、冗长、风险、格式等维度可能冲突。

```python
pair = {
    'prompt': '依据给定政策回答是否可以退货',
    'chosen': '先核对购买日期和适用条款，再给出带条件的结论',
    'rejected': '没有订单信息也保证全部可退'
}
```

这只是样本结构，不是完整训练程序。实际训练还涉及 chat template、tokenization、损失配置、长度截断和持出评估，本课不下载权重也不消耗 GPU。
## 数据切分比训练曲线更容易出错
同一客户工单的改写、同一文档的不同 chunk、同一模板的轻微变体若随机分散在训练和测试集，会造成泄漏。按实体、文档家族和时间先分组，再切分；未来版本政策应留作时间外测试。规范化哈希能发现精确或近似重复，但无法覆盖全部语义改写，需要抽样审计。

| 分组轴 | 避免的泄漏 | 补充测试 |
|---|---|---|
| 客户/工单 | 记住同一实例 | 新客户和新实体 |
| 文档家族 | 相邻段或改写混入 | 未见文档结构 |
| 时间 | 学到测试时的未来信息 | 政策变更与过期事实 |

测试集不能反复用于选提示、选择 rank 或调阈值，否则它事实上变成了验证集。
## 可运行实验：低秩参数与泄漏检测
实验计算 4096×4096 矩阵、rank=8 的完整与低秩参数量：16,777,216 对 65,536，比例约 0.39%。这里只比较一个矩阵的可训练参数，不等于整个模型压缩了 99.61%。

再构造两个 split 中相同的 entity_id，检测交集。即使文本不相同，同一实体泄漏也要报告。修改实体集合，观察检查结果；进一步增加文档家族和时间范围约束，形成可在数据流水线执行的验收。
## 如何判断训练值得上线
与固定提示、RAG 和未训练基座在同一持出集比较，报告任务成功、格式、拒答、越权、成本和延迟，并检查通用能力回归。训练 loss 降低只说明对训练目标更拟合，不能自动推出生产收益。

版本化数据清单、标注规则、基座、adapter、配置和评估结果。发现敏感信息进入训练集时，删除原样本不等于已训练模型忘记它，应按实际训练服务和合规要求制定重新训练或替换策略。把数据治理当成训练系统的一部分。
