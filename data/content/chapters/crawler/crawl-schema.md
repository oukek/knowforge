## 从具体问题认识字段标准化、Schema 与质量隔离

采集到的文本不是可以直接用于分析的结构化数据。价格可能写成“¥12.30”，日期可能没有时区，缺失值可能是空串、横线或不存在节点。Schema 定义字段类型与约束，标准化则把来源表示转换成统一内部表示。

例如价格可以保存为 amount_minor=1230、currency=CNY，避免把货币符号与数字混在同一字段，也避免二进制浮点在金额换算中产生意外误差。

## 转换失败应保留可追踪原因

先定义必填与可选字段、单位、枚举和缺失语义。零价格与未知价格不同，空字符串与字段缺失也未必相同。日期应说明来源时区，不能把本地时间直接当 UTC。数字解析要处理千位分隔、负数与范围，不能随意删除所有非数字字符。

标准化函数应尽量纯粹：输入原始字段，输出规范值或明确错误。保留来源 URL、抓取时间与解析器版本，使异常能够追溯。字段级错误可以隔离记录或标注质量状态，策略取决于数据用途；不能把关键字段失败悄悄补成零。

Schema 演进需要版本与兼容处理。新增可选字段通常较容易，改变单位或字段含义则可能破坏下游 API 与向量索引。应先更新契约与迁移规则，再发布解析器，避免同名字段中混入不同尺度的数据。

## 把机制放到一条完整路径中

```flow
字段标准化
定义契约｜类型单位缺失与必填规则
提取原值｜保留来源与解析版本
转换校验｜生成规范值或具体错误
隔离发布｜合格数据进入下游异常留待检查
```

## 配套代码：字段标准化、Schema 与质量隔离：最小可验证示例

下面代码在课内Python运行区执行；浏览器环境与本机CPython的网络、文件和原生扩展能力不同。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

def normalize_price(text):
    from decimal import Decimal
    return int(Decimal(text.replace('¥','').strip())*100)
show(normalize_price(' ¥12.30 '))
show({'amount_minor':1230,'currency':'CNY'})
```

金额转换到最小单位便于稳定存储，示例只接受给定格式且假设两位以内小数。真实解析应处理非法、负值、额外小数位和币种差异，明确舍入或拒绝策略；不能把页面中的任意货币符号都删掉再猜币种。

## 从示例走向实际使用

用真实允许样本建立转换测试，包括空值、异常单位、超大数字和错误日期。将失败记录放入隔离区供检查，正式数据集保持可解释质量。

课内 Decimal 转最小货币单位适合固定两位小数的示意，真实来源若可能多于两位，应明确舍入或拒绝规则，不能依靠 int 静默截断。
