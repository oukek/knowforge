## 从具体问题认识采集目标、授权边界与数据最小化

数据采集是把允许访问的来源内容转换成可处理的数据。项目开始时首先要确定目标：需要哪些字段、多久更新一次、结果给谁使用，以及来源允许怎样访问。目标不清时，程序很容易下载大量无用页面，却无法形成可靠数据集。

例如整理公开课程目录，通常只需要标题、链接、主题与更新时间，不必同时保存评论者联系方式或账户相关信息。字段越少，解析、存储、更新与权限管理也越容易控制。

## 把采集范围写成可执行规则

来源清单应记录站点、允许路径、访问方式、频率和数据用途。优先使用正式 API、导出或明确授权的数据入口，避免因为浏览器能看到某个页面，就推断可以任意批量复制与再发布。robots.txt 是自动访问规则的一部分，并不是法律授权书或身份认证机制。

数据最小化需要落实到字段投影与保存期限。下载原始响应用于调试时，应限制访问与保留范围，避免把令牌、个人信息或登录页面长期写进公共日志。采集任务的凭据与结果数据分开管理，失败报告只包含定位所需信息。

技术上还要防止范围逃逸：页面链接可能指向其他域、下载文件或无限日历路径。调度前验证协议、主机、路径与深度，重定向后再次校验目标。范围规则既控制资源成本，也保证程序没有偏离最初授权与业务目标。

## 把机制放到一条完整路径中

```flow
采集任务边界
明确目标｜定义字段用途与更新频率
确认来源｜选择允许的接口和访问路径
执行限制｜校验域名深度速率与字段
生命周期｜管理保存访问与删除
```

## 配套代码：采集目标、授权边界与数据最小化：最小可验证示例

下面代码在课内Python运行区执行；浏览器环境与本机CPython的网络、文件和原生扩展能力不同。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

allowed={'title','url','fetched_at'}
raw={'title':'A','url':'/a','fetched_at':'2026-10-21','private_note':'remove'}
show({k:v for k,v in raw.items() if k in allowed})
```

字段白名单演示最小化输出，不等于已经完成授权或所有敏感信息识别。真实管道还需要源站访问范围、数据用途和保留策略；模型或页面中出现额外字段，也不应自动扩大采集范围。

## 从示例走向实际使用

先为一个明确允许的测试站点写小型采集契约，再实现抓取。契约包含字段示例、终止条件、失败处理和删除机制，之后所有代码都围绕它验证。

本课代码只演示字段白名单。真实项目还需核对来源条款与适用要求，遇到访问拒绝时调整授权与方案，不把绕过限制当作默认优化。
