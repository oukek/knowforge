## 从具体问题认识输入校验、字段白名单与边界转换

输入校验把不可信的网络数据转换为业务可以使用的结构。它不只是检查必填项，还要限制类型、长度、范围、未知字段与跨字段关系。认证说明谁在调用，校验说明数据是否符合格式，授权说明是否允许这个操作，三者不能互相替代。

例如用户可以修改文章标题，但不能通过额外提交 owner_id 把文章转给别人，也不能提交 role=admin 让自己升级权限。

## 从原始数据到业务命令

先在入口限制请求体大小和媒体类型，再解析结构。字段白名单明确允许写什么，未知字段可按契约拒绝或忽略，但敏感字段必须不会被批量赋值进内部对象。字符串转换、去空白和默认值应有一致规则，避免不同接口对同一输入作不同解释。

类型转换需要谨慎。字符串 "100" 是否允许作为数字、布尔 true 是否可能被某语言当作整数、空字符串是否代表缺失，都应明确。自动宽松转换虽然方便，也可能让调用错误长期隐藏。范围校验还要保护资源，例如分页 limit 不能无限大。

业务校验涉及数据库当前状态与权限，不能只靠 JSON Schema。余额、库存、资源归属和版本冲突需要在适当事务或条件写入中检查，避免校验后到写入前发生变化。错误应指向具体字段或规则，同时避免泄露内部实现。

## 把机制放到一条完整路径中

```flow
输入边界
资源限制｜检查大小媒体类型与请求频率
结构校验｜验证类型字段范围与转换规则
业务校验｜确认权限归属和当前状态
构造命令｜只把可信必要字段交给业务层
```

## 配套代码：输入校验、字段白名单与边界转换：最小可验证示例

下面代码在课内Python运行区执行；浏览器环境与本机CPython的网络、文件和原生扩展能力不同。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

writable={'title','summary'}
payload={'title':'new','role':'admin','owner_id':'other'}
show({k:v for k,v in payload.items() if k in writable})
```

字段白名单阻止敏感字段进入更新集合，但不验证 title 类型或当前用户对资源的权限。生产接口应组合类型、范围、归属和并发检查；如果策略是拒绝未知字段，还应返回明确错误而不是静默忽略。

## 从示例走向实际使用

分别测试类型错误、超长输入、未知字段、跨字段矛盾与并发状态变化。前端校验改善体验，后端校验仍是可信边界，不能因为页面已经限制输入就省略。
