## 模板为什么能变成 DOM
Vue 单文件组件里的 template 并不是每次更新都重新当 HTML 字符串解析。构建工具通常先编译模板，得到描述界面的渲染函数。渲染函数读取状态，产生虚拟节点，记录元素类型、属性、子节点与 key 等信息。第一次挂载据此创建真实 DOM，后续更新比较前后描述并修改必要部分。

虚拟节点是数据描述，不是一个隐藏的真实 DOM。它的价值是让框架用统一结构表达组件和更新，不能由此推断所有场景都比手写 DOM 快。手写一个单节点更新可以很简单，框架解决的是复杂界面的可组合性和一致性。
## 模板编译先把结构转成可执行的渲染描述

浏览器不原生理解Vue模板指令。编译器解析模板，识别元素、属性、表达式和指令，再生成渲染函数。渲染函数读取当前状态并产生VNode描述，这些描述记录节点类型、属性、子节点及必要的标识信息。VNode是界面的数据表示，不是真实DOM，也不是截屏。

编译器知道哪些部分是静态、哪些表达式会变化，因此可以生成有针对性的更新提示。运行时利用这些信息减少不必要比较，但不能简化成“Vue永远只比较变化的一个节点”。动态结构、插槽、组件边界与key仍影响需要做的工作，具体优化由版本与模板形态决定。

## 挂载与更新是两条相关但不同的路径

首次渲染没有旧树，需要创建并插入宿主节点，建立事件与组件实例；后续更新则比较新旧描述，复用可以保留的节点，并修改属性、文本、子节点或位置。节点类型不同或身份改变时，可能需要卸载旧实例再创建新实例，连带影响局部状态与生命周期。

列表比较的目标不仅是尽量少做DOM操作，还要让状态跟随正确实体。稳定key帮助识别同一项，随机key会使每次都像一批新对象，索引key在重排后可能把输入草稿留在错误数据行。算法细节必须服务于这种可观察正确性。

组件render执行、DOM被修改、浏览器画出一帧是三个不同事件。某次组件计算结果没变，可能不需要DOM改动；大量DOM写入也可能被浏览器合并后再布局。性能分析应分别观察框架计算、宿主更新和浏览器渲染，不能单用组件打印次数解释卡顿。

## 通过 h 理解渲染函数
```javascript
// 在 Vue 项目中作为一个组件模块使用。
import { h, ref } from 'vue';
export default {
  setup() {
    const count = ref(0);
    return () => h('button', {
      onClick: () => count.value++
    }, `点击 ${count.value} 次`);
  }
};
```
h 的参数表达元素、属性与子内容。每次需要渲染时读取当前 count；框架看到按钮类型未变，可以保留元素并更新相关文本或事件信息。模板让这些结构更可读，编译器还能分析哪些地方是静态的。
## 编译器信息怎样减少运行时工作
静态内容没有依赖状态，编译器可以提取或标记它，避免运行时每次都完整检查。动态属性、文本和子节点区域也可以附带优化信息。具体 patch flag 和生成代码属于实现细节，随着版本变化，学习时应理解“编译阶段已有的信息可以帮助运行时缩小比较范围”。
```flow
模板到界面
单文件组件源码｜template、script、style
编译阶段｜生成渲染函数并标记可优化区域
组件执行渲染｜读取状态，产生虚拟节点描述
挂载或 patch｜与旧描述比较，更新真实 DOM
浏览器渲染｜计算布局、绘制、合成
```
## 列表更新为什么不能只按位置猜
旧列表 A、B、C 改成 C、A、B，若每项有稳定 key，框架可以识别这些仍是原来的实体。若 key 只是索引，位置0的组件可能被解释成同一个位置的新数据，局部状态就可能与业务项错配。比较算法的目标既包含减少操作，也包含维持正确组件身份。

理解 diff 不必一开始背完整源码。先明确节点类型变化可能导致替换、key 决定匹配身份、属性和子节点分别更新。再研究头尾比较、映射表及减少移动的算法，才能知道它们在什么条件下有效，而不是把最长递增子序列当所有渲染的唯一原理。
## 性能排查的层次
更新慢可能来自渲染函数里的昂贵计算、组件数量、DOM 布局，或外部资源。给列表补 key 能修身份问题，却不会减少几万条记录本身的布局工作；memo 类优化也不能治好同步大循环。先用性能记录区分脚本与浏览器渲染，再定位组件和数据变化范围。
