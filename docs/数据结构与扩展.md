# 数据结构与扩展

## 资料库：data/catalog.json

顶层 `schemaVersion:1` 用来区分格式版本；`edition` 和 `updatedAt` 标记本次资料整理时间，不代表每个上游文档永远不变。

| 字段 | 内容 |
|---|---|
| modules | 18 个专题，含稳定 ID、标题、图标、优先级、计数和研读估计 |
| tracks | 四条推荐主线，映射专题 ID |
| lessons | 知识点主体、章节、关键词、示例、问答、来源 ID |
| questions | 原理、场景、单选和编码题，关联 lessonId/moduleId |
| labs | 手写实验契约、starter、solution、tests、hints、复杂度 |
| sources | 官方/一手来源 URL、核对范围、状态、核对日期 |
| corrections | 原材料说法、修正、证据边界与来源 ID |

每篇知识点字段：

```js
{
  id: 'js-concurrency',         // 稳定 ID：学习记录依赖它
  moduleId: 'js',
  title: '带并发限制的异步调度器',
  summary: '...',
  level: '核心', priority: 'P0',
  estimatedMinutes: 8,         // 估计研读时间，非真实已学时长
  keywords: ['并发', 'scheduler'],
  sections: [{title:'...',content:'Markdown 正文'}],
  interview: {
    question:'原理题', answer:'参考回答', rubric:['评分要点'],
    scenario:'场景追问', scenarioAnswer:'场景解法与边界'
  },
  language:'javascript',       // javascript 或 python；原知识点默认 javascript
  code: '可选示例',
  playground: {
    id:'example-js-concurrency', title:'...', description:'...',
    runtime:'javascript',       // javascript / python / model（教学模拟）
    language:'javascript',      // 新增 Python 示例标为 python
    code:'可直接运行的 JS', expectedLogs:['每次 console 调用的一行文本'],
    explanation:'输出原因和适用边界'
  },
  exercises: [
    {id:'output-js-concurrency',type:'output',title:'预测输出',
     prompt:'...',code:'原始 JS',expectedLogs:['...'],explanation:'...'},
    {id:'fill-js-concurrency',type:'fill',title:'补全代码',prompt:'...',
     starter:'...',solution:'...',signature:'function name(args)',
     tests:[{name:'边界场景',code:'equal(fn(...),expected)'}],
     hint:'...',explanation:'...'}
  ],
  sourceIds: ['mdn-js'],
  provenance: 'editorial',     // 编辑扩写练习，非面试真题
  updatedAt:'2026-10-21', order:1
}
```

题目 `type` 为 `oral / scenario / choice / coding`。单选题的 `correct` 是从 0 开始的索引；`explanation` 解释机制。开放题 `rubric` 只供自查，不是机器评分规则。编码题通过 `labId` 对应实验，代码答案在 `solution`。

## 新增内容

1. 在合适 `data/content/*.mjs` 中调用 `topic(moduleId,id,title,summary,mechanism,steps,pitfalls,question,scenario,scenarioAnswer,keywords,code,sourceIds)`。
2. `steps` 和 `pitfalls` 用 `|` 分隔条目；关键词用空格分隔。参数中不要混用分隔符表达其他语义。
3. 若新建源文件，把 import 加入 `scripts/build-data.mjs`。
4. 选择题在 `choices.mjs` 加入明确的四选一题，给唯一标准选项和解释。
5. 手写题在 `labs.mjs` 中新增明确函数签名和契约。`tests[].code` 是受控测试代码字符串，需正确转义换行与引号；不接收第三方在线提交内容作为题库脚本。
6. 在 `data/content/examples/` 对应文件中调用 `ex()` 添加本课示例、逐行预期日志和边界解释。平台模拟传 `runtime='model'`；必须是 Worker 能运行的纯 JS，不直接用 DOM、wx、require。预测输出题从示例自动生成。
7. 可在 `examples/fills.mjs` 用 `fill()`/`quick()` 增加补全题，指定 starter、solution、函数签名、提示和有区分力的用例。每课必须有示例；缺少示例、未知 ID 或重复 ID 会阻止生成。
8. 运行生成、检查、参考解测试与构建，阅读实际页面。`lesson-examples.test.mjs` 会用实际执行器核对所有示例和补全参考解。

稳定 ID 不宜随标题修改。删除或改 ID 会影响旧备份和学习关联，需设计迁移。

## 学习记录存储（MySQL / SQLite）

`server/database.mjs` 根据 `DB_DRIVER` 选择存储。`server/mysql-store.mjs` 使用 mysql2 Promise 连接池；`server/store.mjs` 保留 SQLite。两者共用 `server/study-store.mjs` 的备份状态、复习调度和参数化 upsert，JSON 数据格式一致。MySQL 表使用可配置前缀（默认 `knowforge_`），下表列出学习表的逻辑名称；账号版对应 `user_` 前缀表，包含 `userId`。

`createApp()` 和 `store.state()` 为异步方法，调用方需要 `await`。API 通过 `store.session()` 在单进程内串行执行读改写；MySQL session 用 AsyncLocalStorage 绑定同一连接，事务未提交或抛异常时自动回滚再归还连接。个人存储通过 `forUser(userId)` 返回，仅允许已知单表语句并强制加入用户条件，不能从请求体指定归属。`progress/notes/bookmarks/reviews/exams/settings/activity` 使用用户 ID 与原内容 ID 的联合主键，记录表按用户过滤。新增 `auth_users`、`auth_sessions`；新账号不会访问旧共享表。当前不支持多个应用进程同时改写同一份学习数据。

启动入口自动加载根目录 `.env`，进程环境变量优先；MySQL 配置和 SQLite JSON 迁移步骤见 [服务器部署](服务器部署.md#mysql-数据库配置)。

| 表 | 关键内容 |
|---|---|
| progress | lesson ID、new/learning/done、更新时间 |
| notes | 目标 ID、纯文本内容、更新时间 |
| bookmarks | 目标 ID、收藏时间 |
| attempts | question ID、objective/self/coding、答案、分数、是否掌握、时间 |
| lesson_attempts | exerciseId、lessonId、output/fill、答案或代码、是否通过、通过/总用例数、时间 |
| reviews | question ID、dueAt、间隔、连续掌握数、自评、薄弱标记 |
| exams | UUID 与试卷 JSON：题目、草稿、时间、结果 |
| settings | 每日分钟、周期、起始日期 |
| activity | 上海时区自然日、真实学习动作计数 |

客观题分数为 0/100；代码题为通过用例比例；开放题 `score=null`，保存自评与是否能独立回答。概览“选择题正确率”只统计 `objective`。代码试题数量与理论/场景数量相互独立，展示总题数时编码题只计一次。

复习状态 `wrong=1` 表示最近一次作答/自评尚薄弱，不是历史上曾错一次就永久不能清除。复习间隔为教学简化规则，所有时间戳存 UTC，界面显示上海时间。

`state.exerciseAttempts` 返回最近 5000 条随堂记录。它与 `attempts` 分开，不参与选择题正确率、题库总题数与复习调度。输出在服务端重新比较；代码补全与原实验室一样在浏览器验证，后端只校验用例数量并保存结果，不执行用户代码。它适合个人学习，不是防篡改考试成绩。

备份 `schemaVersion:1` 增加可选的 `exerciseAttempts`，旧备份仍可合并。合并以 exerciseId + createdAt + answer 去重，验证知识点和题型关联。浏览器未提交的草稿以 `knowforge:{userId}:` 为前缀，分别使用 `wxg-snippet-*`、`wxg-output-*`、`wxg-fill-*`、`wxg-code-*` 键存储，不进入 JSON 备份。

## API

接口前缀 `/api`，成功写入通常返回最新 `state`。`/api/auth/register`、`/api/auth/login` 接收账号密码，`/api/auth/me` 返回当前用户及 CSRF Token，`/api/auth/logout` 注销当前会话。个人学习接口未登录返回 401，写入缺少 `X-CSRF-Token` 返回 403；同浏览器跨标签切换账号时 `X-KnowForge-User` 不匹配返回 409。健康检查和公开学习资料导出无需登录。无效输入为 400、未知目标 404、冲突 409；请求体上限 12MB。浏览器写入校验 Origin，开发代理来源通过 `--dev` 明确放行。

| 方法/路径 | 请求/用途 |
|---|---|
| GET /health | 健康状态 |
| GET /bootstrap | 完整 catalog、学习 state、服务器时间 |
| PUT /progress/:id | `{status:'new'|'learning'|'done'}` |
| PUT /notes/:id | `{content}` |
| PUT /bookmarks/:id | `{active:boolean}` |
| POST /attempts/:id | 选择 `{answer:index}`；开放 `{answer,selfRating:0..3}`；编码 `{answer,passedTests,totalTests}` |
| POST /lesson-exercises/:id/attempt | 输出 `{answer:string}` 返回逐行 feedback；补全 `{answer:code,passedTests,totalTests}` 保存浏览器验证 |
| POST /reviews/:id | `{rating:0..3}`，独立调整复习计划 |
| PUT /settings | `{dailyMinutes,planDays,startDate}` |
| POST /exams | `{mode,moduleIds,count,minutes}` |
| PUT /exams/:id/draft | `{answers:{questionId:value}}` |
| POST /exams/:id/submit | `{answers,selfRatings}`，重复提交返回已有结果 |
| GET /export/catalog | 完整数据 JSON |
| GET /export/handbook | 完整 Markdown 手册 |
| GET /export/backup | 个人数据备份 |
| POST /import | 合并个人备份，校验后事务写入 |

`/runner.js` 由 Node 单独提供 CSP 响应头，并在开发模式由 Vite 代理。单纯把 dist 放到静态 CDN 上会失去 API、数据库访问和这条运行器响应策略；这是一个完整的 Vue + Node 项目。

`CodeEditor.vue` 封装 CodeMirror 6 和按需加载的 Prettier。`useCodeRunner` 为每次运行建立新 Worker，处理实时日志、终态、取消与超时。执行器的 `mode:'snippet'` 用于自由试验；传 `signature/tests` 用于补全和原实验室。消息类型为 console、clear、done；宿主只有收到 done 才结束，流式日志不会截断执行。

## 验证新题的原则

先写输入契约与容易错误的反例，再写标准解。测试应检查行为和不变量，如并发上限、结果顺序、节点引用、别名保持、拆帧和取消；不要只用几个漂亮的普通输入。计时器测试保留容差。算法复杂度属于需要人工评估的属性，不承诺小规模用例能严格证明复杂度。


## 2.0 扩展内容与双语言执行

`data/content/expansion/` 的 python、crawler、restapi、ai 文件定义 88 篇新资料；common 统一组装模块、来源、讲解、原理问答、场景题、单选题与运行示例，practice 定义额外的 Python 补全题。新的来源为 reference，表示列出核对范围与官方入口，不宣称逐字审计整个站点。

`lesson.language` 和 `playground.language` 选择编辑器、代码高亮、输出说明和执行器。`runtime` 用来区分真实语言示例与教学模型，不替代 language。Python 输出题通过标准库 json 的 show() 序列化，比较器允许 JSON 数值 1 和 1.0 等语义等值。

JavaScript 继续使用 `/runner.js`。Python 使用 `/python-runner.js`，从 `/python-runtime/` 加载本地 pyodide npm 包（314.0.7、CPython 3.14.2）。加载最多 30 秒，收到 ready 后用户代码最多 4 秒；每次 UI 运行新建 Worker，完成或取消即终止。Python stdout/stderr 映射到同一 console 消息协议，done 保存结果。Node 不执行用户代码。

Python Worker CSP 仅允许同源脚本、Wasm 编译及指定的运行资源路径，禁止子 Worker；开发代理对运行器保留浏览器 Host，使 CSP 路径源与前端来源一致。普通 stdlib 与虚拟文件可用，本应用不提供动态第三方包安装或任意联网能力。学习执行器不是防作弊平台，不提供严格内存配额。native 项目与 Worker 是不同环境。

`settings.trackId` 为可选的学习主线，all 表示全部；保存和备份校验当前 tracks，旧备份缺字段仍兼容。模块数量从 catalog 读取，模拟接口不再固定最多 14 专题。改名仅更新 UI、元数据和下载文件名；稳定内容 ID 保持不变；账号版浏览器草稿改用 `knowforge:{userId}:wxg-*` 键。

`GET /api/export/python-demo` 下载独立的 `examples/python/workbench.py`。项目仅允许显式本机样本站点，使用 sqlite3 保存独立数据，通过标准库 HTTPServer 提供分页、Problem Details 错误和确定性检索；不运行模型。

增加内容后运行 build:data、check:data、npm test 和 build。python-content.test 使用实际 Pyodide 执行 88 段示例和 40 份补全解，并确认空实现不能通过；native-python.test 用系统 Python 在临时目录验证完整链路。UI 交互、CSP 与浏览器布局仍需真实浏览器检查。


## 前后端入口

开发与构建后运行默认使用前端 16666、后端 6666。`FRONTEND_PORT` 覆盖前端端口，`PORT` 覆盖后端端口。`npm run dev` 和 `npm start` 均由 server/index.mjs 创建两个 HTTP server，统一启动、处理端口占用错误并在退出时关闭，两个服务只监听 127.0.0.1。

server/frontend.mjs 通过 Node HTTP 将 `/api`、`/runner.js`、`/python-runner.js` 和 `/python-runtime` 转发到后端，保持浏览器 Host 与响应 CSP，浏览器不直接请求受限端口 6666。开发时前端挂载 Vite middleware，HMR 复用前端 HTTP server；构建后前端托管 dist 与 SPA 路由。API 服务使用 createApp({serveClient:false})，不托管页面。页面写请求经代理后保持同源校验，不需要额外放行跨来源写入。

上文中的旧开发代理和验收记录中的单端口入口均属于历史架构；当前应通过 http://127.0.0.1:16666/ 访问。6666 属于 Chromium 的受限端口，保留为 Node 后端监听地址，项目不会修改浏览器安全配置。

开发入口使用 nodemon，nodemon.json 只监听 server/、shared/ 和生成后的 data/catalog.json，合并 200ms 内的连续改动，通过 SIGTERM 正常关闭两端 HTTP server、Vite 与数据库连接后重启。前端文件与 Vite 配置仍由 Vite 自己监听。不要将入口换回无范围限制的 node --watch，以免 Vite 临时配置触发循环重启。
