## 从具体问题认识会话状态、摘要、长期记忆与删除

AI 应用中的记忆，是把过去信息在未来合适时刻重新提供给模型。短期记忆服务当前任务，如刚查询的证据与待办步骤；长期记忆跨会话保存偏好、事实或经验。它们的区别主要是用途与生命周期，不只是存储在内存还是数据库。

“用户今天在排查 Vue 问题”可能只是本轮背景，“用户希望示例使用 TypeScript”则可能成为偏好。把所有聊天都永久存起来，会增加噪音、隐私风险与错误传播。

## 候选提取、确认与按需读取

写入先从对话中提出候选，再判断是否值得记忆、归属哪个用户、来源是否可信及是否需要确认。模型推测的职业不能直接升级为用户事实。记忆条目保存来源、时间、适用范围和版本，支持查看、纠正与删除。

读取按当前任务与权限检索，排序综合相关性、时效性和可信程度。检索到旧偏好后仍应服从用户本轮明确要求。高相似度不代表事实仍有效，因此对易变化信息需要有效期或复核机制。

压缩对话可以减少上下文，但摘要也可能遗漏否定条件或把猜测写成事实。摘要应区分已确认与待确认状态，并保留必要出处。长期存储不等于每次全部注入；装配上下文时只选与任务有关且授权的部分。

## 把机制放到一条完整路径中

```flow
记忆生命周期
提出候选｜从交互中识别可复用信息
验证归属｜确认来源范围与保留必要性
按需读取｜选择相关有效且授权的记忆
维护纠错｜更新失效冲突与删除派生副本
```

## 配套代码：会话状态、摘要、长期记忆与删除：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

memory=[{'user':'a','value':'python','confirmed':True},{'user':'a','value':'expert','confirmed':False},{'user':'b','value':'vue','confirmed':True}]
show([x['value'] for x in memory if x['user']=='a' and x['confirmed']])
```

示例只展示确认状态与用户隔离的过滤逻辑，没有自动从对话提取长期事实。真实系统需要验证写入、来源追溯与删除传播，可信 user 也应来自服务器认证上下文而不是模型参数。

## 从示例走向实际使用

给用户提供记忆管理入口，并测试改名、偏好反转、账号切换和删除后再次检索。删除还要考虑摘要、向量索引及缓存中的派生副本。

课内只筛选 confirmed 条目，展示事实晋升需要门槛；生产系统还要有来源、范围和冲突处理，不能仅靠一个布尔值解决全部问题。
