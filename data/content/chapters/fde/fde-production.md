## 从具体问题认识FDE 生产交付

生产交付要让系统在真实身份、真实数据和真实故障下持续工作。演示里手工上传一份干净文件、使用管理员账号并等待模型返回，掩盖了权限、更新、容量和恢复问题。

交付工程师需要把这些隐含条件变成接口契约、部署配置、监控和运行手册，使接手团队能够独立运行系统。

## 数据接入、运行状态与交接责任

数据接入明确来源、更新频率、字段含义、删除同步和权限映射。集成失败时区分暂时不可用与数据不存在，保留重试和对账能力。同步任务要有检查点和版本，避免每次全量重来或旧数据覆盖新数据。

应用任务状态由服务端维护，运行、等待审批、成功、失败和取消有合法转移。容量估算考虑一个任务会触发多少模型和工具尝试，不能只按用户请求数规划。部署配置与秘密分离，发布保留兼容回退路径。

运行手册回答具体问题：哪里看任务、如何判定上游异常、怎样停止新任务、怎样恢复存量和谁负责处理。文档还需要备份恢复与演练证据，不能只列几个监控链接。

## 从演示架构到运行架构

浏览器展示进度和待审批动作，API 处理认证、限流和创建任务，worker 执行检索与 Agent 流程，数据库保存任务与业务事实，外部连接器访问客户系统。模型密钥属于服务端；浏览器不能因为页面是 HTTPS 就安全持有一个全租户密钥。连接器身份和用户可见范围要分开建模，防止服务账户能看所有数据而用户权限被忽略。

异步任务应返回 task_id，前端用受认证的流或查询接口观察状态。定义 queued/running/waiting_approval/succeeded/failed/cancelled，而不是一个 loading 布尔值。断线后按任务 ID 恢复显示，避免重新创建具有副作用的新任务。

## 数据接入契约

记录数据来源、主键、更新时间、权限标签和删除策略。增量同步需要可恢复游标或水位，重复数据按稳定键去重；权限变化与删除应传播到索引和缓存。向量库中的过滤条件不是唯一授权边界，检索前后都应根据认证事实与资源策略约束，防止缓存跨租户复用。

## 分阶段发布

先进行影子运行，仅记录建议不影响业务；再让有限用户审阅草稿；最后对低风险子集自动执行。每阶段都定义最小样本、门槛与回滚条件。发布需要固定代码、prompt、工具 schema、模型配置和索引版本。不能把“把模型名换回去”当作完整回滚，因为旧任务可能已经写了新状态格式。

## 运行手册要回答的具体问题

服务不可用由谁响应，哪个指标触发告警，怎样停止写能力，任务怎么重放，审批停留多久算异常，密钥怎样轮换，备份如何恢复，审计记录保存多久。给业务方的是可理解的故障状态，给运营方的是 request_id/run_id 与链路证据。一次交付需要客户工程/业务负责人都能独立定位常见失败，不应让每次修改都依赖原作者在场。

## 故障演练与容量

模拟模型 429、连接器 503、数据库连接池耗尽、worker 被杀、前端断流和权限撤销。对每种故障写明重试/升级/拒绝策略，验证幂等与恢复。容量估计要乘入每任务模型轮数、工具扇出、重试和审核等待，不用“每秒多少 HTTP 请求”替代真实任务资源模型。

## 交付验收

交付包包含架构与数据流、环境变量名称、版本清单、权限矩阵、评估集与结果、回滚步骤、告警与值班、数据处理与删除说明、客户培训材料。用一次由接收团队执行的恢复演练检验文档，不靠“已发送 README”证明交接完成。

## 用故障时间线检查系统是否完整

假设浏览器 POST 创建 task-7，API 已提交 queued 后响应在网络中丢失。浏览器用同一业务幂等键重试，应拿到 task-7，而不是 task-8。worker 领取任务并写入租约与 fencing token；生成草稿后到 waiting_approval。此时手机断网，不应重新运行模型；重新连接只查询 task-7 的当前状态。审批通过后 worker 提交外部动作，若连接超时不能确定对方是否成功，先按业务键查状态，不直接重发。

状态转换至少带 task_id、from/to、state_version、actor、发生时间和原因。并发取消与提交不能只比较客户端显示：数据库里以预期 state_version 条件更新决定赢家；已经完成的外部动作需要补偿或人工处理，不能靠把任务状态改成 cancelled 撤销。前端显示“取消请求中”和“已取消”时，也应对应不同的服务端事实。

容量可以先做数量级估算：入口每秒 2 个任务，平均每任务 4 次模型调用，平均单次占用 3 秒，仅模型阶段稳态平均并发约为 2×4×3=24。它不等于应直接设置 24 个并发槽位：到达突发、长尾、重试、连接器和配额还会改变容量，需要压测验证，并保留有界排队和拒绝策略。审批等待不应长时间占住 worker 执行槽位，恢复应由持久状态驱动。

## 配套代码：FDE 生产交付：数据集成、权限、灰度与交接

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

浏览器内的确定性实验，用于验证关键不变量。真实服务/SDK 完整示例见正文；不会连接模型或外部服务。

```javascript
const transitions = {
  queued: ["running", "cancelled"],
  running: ["waiting_approval", "succeeded", "failed", "cancelled"],
  waiting_approval: ["running", "cancelled"],
};
function canMove(from, to) {
  return (transitions[from] ?? []).includes(to);
}
console.log([
  canMove("queued", "succeeded"),
  canMove("running", "waiting_approval"),
  canMove("waiting_approval", "running"),
]);
console.log({
  capacity: 10 * 3 * 2,
  meaning: "10 tasks x 3 tools x 2 attempts",
});
```

queued 不能直接被前端一条文本标成 succeeded；审批等待恢复到 running 后才继续执行。容量模型说明入口并发并不等于外部操作并发，实际还需用阶段分布和时间预算估算。

## 从示例走向实际使用

交付前安排一次由接手人员执行的故障演练，检查他们是否能在没有作者口头指导时定位和恢复。实际能操作的手册比长篇架构介绍更有价值。

课内状态转移与容量乘法分别展示合法过程和放大效应，真实容量还受并行度、时长与上游限额影响。
