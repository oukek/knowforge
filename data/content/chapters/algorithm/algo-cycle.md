## 从具体问题认识快慢指针、环检测与有序合并

链表有环，表示沿 next 前进会再次回到已经访问过的节点。判断时比较的是节点身份，不是节点值；两个不同节点都保存数字 1，不代表形成环。快慢指针用不同速度遍历，在不额外保存所有已访问节点的情况下检测环。

慢指针每次走一步，快指针每次走两步。无环时快指针最终到达空；有环时，两者进入环后会在有限步内相遇。

## 相遇与环入口的距离关系

设环外长度为 a，环长为 L，相遇点从入口沿环前进的距离为 b。相遇时快指针比慢指针多走的距离是若干圈 L，因此慢指针走过的总步数也与 L 有整倍数关系。由此可得，从相遇点继续走 a 步会回到环入口。

所以检测到相遇后，让一个指针回到头节点，另一个留在相遇点，两者都每次走一步；它们下一次相遇的位置就是入口。这里依赖的是距离同余，不是“两倍速度所以随便重置都行”。循环前要检查 fast 与 fast.next，防止在无环链表末尾访问空引用。

快慢指针也可寻找中点，但偶数长度时返回左中点还是右中点取决于初始化与循环条件。有序链表合并则是另一类双指针：每次取两个当前节点中较小者接到结果尾部，维护已输出前缀有序；不能把所有双指针问题混成同一个速度技巧。

## 把机制放到一条完整路径中

```flow
快慢指针找环
同步出发｜慢走一步快走两步
判断结束｜到空则无环相遇则有环
重置一端｜一指针回到链表头
同速前进｜再次相遇得到环入口
```

## 配套代码：把机制变成可运行函数

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

值相同不代表环，相遇与入口按节点引用判断。

```javascript
function detectCycle(head) {
  let slow=head,fast=head;
  while(fast&&fast.next){
    slow=slow.next;fast=fast.next.next;
    if(slow===fast){let p=head;while(p!==slow){p=p.next;slow=slow.next}return p}
  }
  return null;
}


const a={val:1},b={val:1},c={val:1};
a.next=b; b.next=c; c.next=b;
console.log(detectCycle(a)===b);
c.next=null;
console.log(detectCycle(a));
```

第一个输入的入口为 b；断开 c.next 后三个重复值仍然存在，但链无环。快慢指针比较引用，不通过 val 判断。

## 从示例走向实际使用

构造头部自环、环入口在头、环入口在中间与完全无环四种结构。节点值刻意重复，验证算法确实按对象身份比较。

合并有序链表时用哑节点简化头部处理，但要明确是否复用原节点。若两个输入共享节点或带环，普通合并的前提会被破坏，应按题目条件处理。
