## 从具体问题认识文档清洗、分块、重叠与来源追踪

分块把文档拆成可以检索并放进上下文的片段。它需要同时考虑长度、语义与来源：片段太短可能只有结论没有条件，太长可能混入大量无关内容。重叠可以缓解边界断裂，但会增加重复检索与存储。

例如“仅限正式员工”位于上一段，而报销金额位于下一段，机械切开后模型可能把限制条件遗漏。

## 以结构与证据完整性决定边界

清洗先去除无关导航、重复页眉页脚，同时保留标题、列表与表格关系。不能为了文本整洁把条款编号和单位删掉。分块可按标题段落形成候选，再按 token 长度控制，必要时保留父标题或邻接信息。

固定窗口的步长是 size-overlap，必须大于零，否则循环无法推进。重叠越大不一定越好：相邻片段高度重复会挤占 top-k，导致不同文档证据进不来。检索后可按文档范围合并邻接片段，减少重复上下文。

每片保存文档 ID、版本、原文偏移或页码、标题路径与权限。修改切分策略会改变片段身份与引用，重建索引时应处理旧片段失效。表格与代码块可能需要专门策略，避免把一行表头与数据拆到不同片段。

## 把机制放到一条完整路径中

```flow
文档分块
结构清洗｜保留标题单位与表格关系
确定边界｜结合语义段落和长度预算
关联来源｜保存位置版本权限与父标题
检索验证｜检查断裂重复和证据覆盖
```

## 配套代码：文档清洗、分块、重叠与来源追踪：最小可验证示例

下面代码在课内Python运行区执行；浏览器环境与本机CPython的网络、文件和原生扩展能力不同。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

def chunks(text,size,overlap):
    if not 0<=overlap<size: raise ValueError('overlap')
    return [text[i:i+size] for i in range(0,len(text),size-overlap)]
show(chunks('abcdefgh',4,1))
```

这是按 Python 字符切片的滑窗，未执行 tokenizer，也未处理段落和句子边界。size-overlap 保证推进，最后一块可能短于 size。生产管道应记录原文偏移、权限和版本，并用任务评估选择策略。

## 从示例走向实际使用

从真实失败问题回到原文，检查答案是否跨边界、条件是否被清洗删除、检索是否被重复片段占满。比较多种策略时固定模型与查询集。

课内字符窗口说明重叠机制，不是 token 分块器。生产长度应按目标计数规则控制，并抽查切分后的可读性。
