## 从具体问题认识二分边界与动态规划

二分查找通过单调性质排除一半候选；动态规划通过子问题关系复用结果。两者都不是靠“代码很短”成立，而是每一步保留了足以继续求解的信息。二分保存边界事实，动态规划保存状态含义。

本课把二分边界、零钱最少数量与序列问题放在一起，重点是学习如何写出不变量和转移依据，而不是认为它们属于同一个算法模板。

## 边界不变量与子问题最优性

lower_bound 寻找第一个不小于目标的位置，可以维护半开区间 [l,r)。l 左侧都小于目标，r 及其右侧都不小于目标；检查中点后只移动与比较结果对应的一侧。l=r 时候选区间为空，该位置就是边界，可能等于数组长度。

动态规划先定义 dp 的每个下标意味着什么。零钱问题可定义 dp[s] 为凑出金额 s 的最少硬币数；最后一枚若是 c，前面必须凑出 s-c，于是比较 dp[s-c]+1。dp[0]=0，无法凑出的状态为 Infinity，这些初始化直接来自题意。

最优子结构表示最优方案的相应子部分也满足子问题最优条件，但必须确保状态包含未来决策所需信息。若限制某类物品只能用一次，只记录金额可能不足以区分可用物品范围，需要增加维度或安排正确遍历顺序。贪心则更强，要求当前选择可以永久确定，不能因为 DP 能求解就假设贪心也成立。

## 二分维护的是区间事实

lower_bound 在已排序数组上找第一个 >= target 的位置，返回 n 表示不存在。采用 [left,right) 时，初始化 right=n，循环 left<right；若 nums[mid]<target，则 mid 及其左侧都不可能是答案，令 left=mid+1，否则 right=mid。每一步区间缩小，循环结束 left=right 即边界。

不要用 (left+right)>>1 计算任意大索引，它会触发 32 位整数转换；使用 left+Math.floor((right-left)/2)。重复值、全小于、全大于和空数组是边界定义的检验，不是附加装饰。

## 动态规划的四个问题

状态代表什么，转移依赖哪些较小状态，初始条件如何定义，遍历顺序如何保证依赖已计算。最少硬币数可定义 dp[x] 为凑出 x 的最少硬币个数，dp[0]=0，不可达为 Infinity；枚举最后一枚硬币得到 dp[x]=min(dp[x-c]+1)。这与统计组合数量不是同一个问题，交换循环顺序可能改变计数语义。

## 贪心反例与 LIS

面额 [1,3,4] 凑 6，最大面额优先得到 4+1+1，最优是 3+3，说明局部最优不一定能扩展成全局最优。LIS 的 tails[len] 记录该长度递增子序列可达到的最小结尾，用二分替换第一个 >= x 的位置；tails 本身未必是原数组中的一条真实子序列，返回长度可以，恢复路径则需前驱索引。

## 加权区间调度

按结束时间排序任务，dp[i] 表示前 i 个任务的最大收益。选择第 i 个任务时，使用二分找到最后一个 end<=start[i] 的兼容任务，转移是 max(不选的 dp[i-1], profit[i]+兼容前缀最优)。按最高收益或最早开始贪心都可能失败；无权的最多任务数量与带权最大收益需要区分。

## 可运行例子与证据

```javascript
function lowerBound(a,target){
 let left=0,right=a.length;
 while(left<right){const mid=left+Math.floor((right-left)/2);if(a[mid]<target)left=mid+1;else right=mid;}
 return left;
}
console.log(lowerBound([1,2,2,4],2)); // 1
console.log(lowerBound([1,2,2,4],5)); // 4
```
把 < 改为 <= 就变成寻找第一个 > target 的另一种边界。迁移训练应要求解释新的循环不变量，而不是只背最后一行改了符号。

## 测试与复杂度

零钱兑换按金额上线评估 O(amount×面额数) 是否可承受；LIS 长度可 O(n log n)，朴素 dp 为 O(n²)。用随机小样本和暴力解做差分测试，再用大样本验证复杂度。正确答案样例只能证明某个输入，不能证明边界和最优性。

## 把机制放到一条完整路径中

```flow
从定义到实现
定义状态｜候选区间或子问题含义
写出依据｜单调排除或最后一步分解
确定初值｜边界来自题目允许的空状态
手推验证｜用反例检查遗漏与错误选择
```

## 配套代码：二分边界与动态规划：状态、转移和最优性

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

浏览器内的确定性实验，用于验证关键不变量。真实服务/SDK 完整示例见正文；不会连接模型或外部服务。

```javascript
function lowerBound(a, t) {
  let l = 0,
    r = a.length;
  while (l < r) {
    const m = l + Math.floor((r - l) / 2);
    if (a[m] < t) l = m + 1;
    else r = m;
  }
  return l;
}
console.log([
  lowerBound([], 3),
  lowerBound([1, 2, 2, 4], 2),
  lowerBound([1, 2, 2, 4], 5),
]);
const coins = [1, 3, 4],
  dp = Array(7).fill(Infinity);
dp[0] = 0;
for (let i = 1; i <= 6; i++)
  for (const c of coins) if (i >= c) dp[i] = Math.min(dp[i], dp[i - c] + 1);
console.log(dp[6]);
```

lower_bound 允许返回数组长度，这是合法插入边界而不是越界错误。零钱兑换的结果 2 对应 3+3，直接反驳“总选最大面额必然最优”。

## 从示例走向实际使用

写二分时先选闭区间还是半开区间，并完整保持一种约定。写 DP 时先用一句话解释状态，再列所有最后一步，检查是否覆盖且没有误重复。

用零钱 [1,3,4] 凑 6 可检验贪心：先取 4 得三枚，3+3 只需两枚。这个反例说明局部面值最大并不保证全局枚数最少。
