## 名字在哪里找到值
函数读取名字时按语言作用域规则查找局部、外层函数、模块全局和内置等位置。作用域由代码结构决定，不是按调用者是谁动态决定。函数内出现对某名字的赋值，通常会使它被视为局部名字，若在赋值前读取便可能出现 UnboundLocalError。

global 表示绑定模块级名字，nonlocal 表示使用外层函数的已有绑定。它们改变名字归属，不是让对象突然可变。一个外层列表即使不声明nonlocal，仍可调用append修改对象；重新给外层名字赋新列表才涉及绑定改变。
## 一个名字究竟在哪个范围里查找

在函数体内读取一个名字时，通常依次看当前局部作用域、外层函数作用域、模块全局作用域和内置名字，这就是常说的 LEGB。模块全局不是“整个进程所有文件共用的同一字典”；每个模块有自己的命名空间。类体与推导式还有各自细节，不能用一个简单口诀解释所有语法场景。

若函数体中存在对名字的普通赋值，编译器通常把它归入该函数的局部名字，即使赋值写在读取之后。因此函数里先读 x、后写 x，并不会先去全局找 x 再切换成本地值，可能直接出现 UnboundLocalError。global 声明操作模块级绑定，nonlocal 声明操作外层函数已有绑定；它们应服务于明确状态所有权，不能到处使用来绕过参数传递。

## 闭包保留的是环境中的绑定

内层函数可以使用外层函数的局部名字，即使外层已经返回。这个函数与相关环境形成闭包。它适合封装小范围持久状态，例如每个计数器各自维护数量。两次调用工厂函数会建立两份环境，不是所有返回的函数共享一个全局计数器。

```python
def make_counter():
    value = 0
    def increment():
        nonlocal value
        value += 1
        return value
    return increment

first = make_counter()
second = make_counter()
print(first(), first(), second())
```

循环中创建的闭包若都引用同一个循环名字，调用时读取的是那个绑定届时的值，不自动保存每一轮快照。需要固定当时值时可通过工厂参数建立新绑定，或有意识地使用默认参数求值时机。前者通常更容易解释，尤其当捕获的数据不是简单数字时。

作用域的用途并非让数据尽量隐藏，而是让谁能修改什么一目了然。需要跨多个对象协调的复杂状态应有明确对象或服务边界；闭包中层层嵌套可变容器也可能造成难追踪的依赖。

## 闭包保留的是绑定关系
```python
def counter():
    value = 0
    def next_value():
        nonlocal value
        value += 1
        return value
    return next_value

a = counter()
b = counter()
print(a(), a(), b())
```
两次调用counter建立不同环境，所以a连续增加而b独立开始。闭包可以封装局部状态，也会让被引用对象存活更久；是否泄漏取决于长期引用和业务需要，不能说用了闭包就泄漏。
## 循环中的延迟绑定
```python
functions = [lambda: i for i in range(3)]
snapshots = [lambda i=i: i for i in range(3)]
print([fn() for fn in functions])
print([fn() for fn in snapshots])
```
第一组调用时读取同一个循环绑定，最终都是2；第二组利用默认参数在创建函数时求值，分别保存0、1、2。这里与“可变默认参数要小心”不矛盾：是否共享、何时求值必须结合对象类型与目的分析。
## 工程中的状态生命周期
模块全局缓存、事件回调和装饰器都可能保存闭包。写异步任务时明确需要创建时的值还是执行时最新值，并用显式参数减少意外捕获。测试多个实例、重复调用和不同调用顺序，才能发现共享状态。

尽量让需要修改的状态有清楚拥有者，不用大量global解决跨函数通信。可将业务状态放到对象或明确上下文中，让依赖在函数签名或构造时可见。
