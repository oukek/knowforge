## 组件何时真正存在
组件创建后先建立状态和渲染逻辑，挂载后才拥有可访问的 DOM。响应式更新可能触发渲染，卸载意味着组件及其资源生命周期结束。onMounted 适合需要真实元素的工作，onUnmounted 适合释放订阅、定时器和外部实例；在 setup 中同步注册这些钩子，避免异步后才临时登记造成上下文丢失。

组件内部的生命周期不等于浏览器页面生命周期。一个 SPA 路由跳转可能卸载某些组件，整个浏览器文档却继续存在。页面隐藏也不一定卸载组件，所以持续采集、轮询和媒体播放还需要考虑可见性与业务状态。
## 缓存组件与缓存数据不是一回事

普通条件切换可能卸载旧组件，重新进入时创建新实例并重置局部状态。KeepAlive为符合条件的动态组件保留实例，使返回时可以继续使用之前的输入、滚动位置等状态。它保存的是组件实例及其相关引用，不是把页面变成一张静态截图，也不自动保证后端数据仍新鲜。

被缓存组件离开显示区域时进入停用阶段，再次显示时激活；这与真正卸载不同。只在onUnmounted里停止轮询，可能导致隐藏但缓存的组件仍继续请求。需要按onActivated和onDeactivated管理前台活动，并在真正卸载时完成最终清理。

## 选择缓存范围与失效规则

include、exclude和max等配置用于控制哪些组件被缓存以及容量。max能限制实例数量，但单个实例也可能保留大列表、编辑器或图片引用，仍需要评估内存。组件名称匹配、key和路由参数共同影响缓存身份，不能让不同用户或不同文档错误复用同一份草稿。

返回缓存页面时，可以保留用户界面状态，同时根据时间、版本或明确事件重新验证服务端数据。登出、权限改变或租户切换时应主动清除相关状态，不能把缓存命中当授权依据。提交草稿后，缓存中的其它视图也可能需要失效或同步更新。

验证时分别测试首次进入、切走、再次激活、容量淘汰和最终卸载。观察订阅数、定时器与网络请求是否按预期变化，比只看输入框内容还在更能证明生命周期处理正确。

## 普通组件先把资源清理写完整
```html
<script setup>
import { ref, onMounted, onUnmounted } from 'vue';
const seconds = ref(0);
let timer;
onMounted(() => { timer=setInterval(()=>seconds.value++,1000); });
onUnmounted(() => { clearInterval(timer); });
</script>
<template><p>已打开 {{ seconds }} 秒</p></template>
```
如果反复进入页面后计时变快或请求增多，可能是旧实例的资源没有释放。不要只把变量设为 null；真正的计时器、监听器或连接需要调用相应停止方法。异步请求还要避免完成后写入已经不需要的状态。
## KeepAlive 改变了离开页面的含义
KeepAlive 可以缓存动态组件实例，切走时未必卸载，而是 deactivated；重新展示时 activated。它保留表单和滚动相关状态很方便，但也会保留内存与外部引用。只在 onUnmounted 清理的轮询，在缓存失活期间可能继续运行。
```flow
缓存组件的状态变化
首次展示｜创建与挂载，再激活
切换到其它组件｜失活，实例仍在缓存
再次展示｜复用状态并激活
缓存淘汰或父级结束｜真正卸载，最终释放资源
```
对于需要暂停的任务，可在 onActivated 启动、onDeactivated 停止，并使启动函数幂等，避免首次挂载与激活重复创建资源。缓存大小用 max 控制，include/exclude 按规则选择组件，key 也影响实例身份。
## 缓存不是数据永不过期
缓存中的列表可能已经过时，重新激活时应根据更新时间、用户操作或服务端版本决定是否重新验证。直接每次重置全部状态会失去缓存的目的，永远不刷新又会展示错误数据。把 UI 状态保留与业务数据时效分开管理。

验证时连续切换多次，检查活动计时器和订阅数量，再测试达到缓存上限后的淘汰。对大型编辑器、地图、媒体组件，要按库的生命周期要求暂停或销毁，而不是认为 KeepAlive 会替第三方对象处理所有资源。
