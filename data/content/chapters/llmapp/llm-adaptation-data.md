## 从具体问题认识模型适配与训练数据

SFT、LoRA 和 DPO 描述不同层面的训练选择。SFT 是用示范答案学习任务行为，LoRA 是用低秩参数更新减少可训练参数，DPO 是利用偏好对优化相对选择。它们不是互斥的三个模型名称，LoRA 可以用于某些 SFT 或偏好训练流程。

选择方法之前先明确需要改变什么：输出格式不稳、领域表达不合适、偏好不一致，还是缺少实时资料。最后一种通常需要数据访问，而不是不断训练。

## 目标、参数化与数据证据

全量更新一个 d×k 权重矩阵需要调整 d×k 个参数。LoRA 将增量表示为两个低秩矩阵的乘积，参数量约为 r(d+k)，当 r 很小时显著减少可训练参数。但优化器状态、激活与基础权重仍有成本，不能把参数比例直接解释成总显存比例。

偏好对包含同一输入下较好与较差的回答，质量取决于偏好定义和标注一致性。DPO 不是把任意点赞日志直接变成可靠训练数据，日志中可能混入曝光偏差、任务难度差异和恶意反馈。

数据切分应按实体、来源或时间隔离，避免同一问题改写跨集合。最终验收同时检查目标能力、边界行为与原能力退化；训练集损失不能替代业务指标。

## 先确定需要改变什么

如果问题是今天的库存和内部政策更新，优先改数据接入、检索与工具；如果问题是稳定的输出风格、分类决策或工具使用模式，可以先构建提示和样本基线，再判断训练是否有足够收益。把每天变动的事实写进参数，会增加更新和删除成本，也不能提供逐条来源和访问控制。

SFT 使用输入与目标输出学习期望行为；偏好优化比较同一输入的优劣回答。两者都需要清楚的目标和高质量标注，不能把收集到的全部聊天记录直接当正确答案。用户满意也不一定代表事实或安全正确。

## LoRA 解决的是更新参数化

LoRA 冻结基座权重，用低秩矩阵表示权重增量。对 `W` 为 d×k，增量可写为 `B(d×r) @ A(r×k)`，训练参数量是 r(d+k)，小于完整更新的 dk（当 r 足够小时）。这说明可训练参数减少，不等于所有训练显存只剩这个比例；激活、优化器状态与批次仍影响峰值。

LoRA 不是一种任务目标，可以和 SFT 等训练目标组合。adapter 的效果依赖基座版本和目标模块，不能把一个 adapter 随意装到不同模型。合并、量化、部署时也要核对兼容性并重新验证质量。

## DPO 的数据与目标边界

DPO 使用同一 prompt 的 chosen/rejected 对，围绕偏好与参考策略的相对概率关系优化。它不是给两个不同问题的答案随意排高低，也不是上线后让模型自己打分就能无成本变好。偏好标签要写明理由：事实、指令遵循、冗长、风险、格式等维度可能冲突。

```python
pair = {
    'prompt': '依据给定政策回答是否可以退货',
    'chosen': '先核对购买日期和适用条款，再给出带条件的结论',
    'rejected': '没有订单信息也保证全部可退'
}
```

这只是样本结构，不是完整训练程序。实际训练还涉及 chat template、tokenization、损失配置、长度截断和持出评估，本课不下载权重也不消耗 GPU。

## 数据切分比训练曲线更容易出错

同一客户工单的改写、同一文档的不同 chunk、同一模板的轻微变体若随机分散在训练和测试集，会造成泄漏。按实体、文档家族和时间先分组，再切分；未来版本政策应留作时间外测试。规范化哈希能发现精确或近似重复，但无法覆盖全部语义改写，需要抽样审计。

| 分组轴 | 避免的泄漏 | 补充测试 |
|---|---|---|
| 客户/工单 | 记住同一实例 | 新客户和新实体 |
| 文档家族 | 相邻段或改写混入 | 未见文档结构 |
| 时间 | 学到测试时的未来信息 | 政策变更与过期事实 |

测试集不能反复用于选提示、选择 rank 或调阈值，否则它事实上变成了验证集。

## 如何判断训练值得上线

与固定提示、RAG 和未训练基座在同一持出集比较，报告任务成功、格式、拒答、越权、成本和延迟，并检查通用能力回归。训练 loss 降低只说明对训练目标更拟合，不能自动推出生产收益。

版本化数据清单、标注规则、基座、adapter、配置和评估结果。发现敏感信息进入训练集时，删除原样本不等于已训练模型忘记它，应按实际训练服务和合规要求制定重新训练或替换策略。把数据治理当成训练系统的一部分。

## 把机制放到一条完整路径中

```flow
模型适配选择
明确目标｜判断需要行为变化还是外部知识
选择训练方式｜区分损失目标与参数更新方法
治理数据｜统一偏好并隔离同源样本
对照验收｜确认真实收益和能力退化
```

## 配套代码：模型适配与训练数据：SFT、LoRA、DPO 及泄漏控制

下面代码在课内Python运行区执行；浏览器环境与本机CPython的网络、文件和原生扩展能力不同。



```python
d, k, rank = 4096, 4096, 8
full = d * k
adapter = rank * (d + k)
print(full)
print(adapter)
print(round(adapter / full * 100, 2))
train = [{'entity':'ticket-1','text':'原问题'}, {'entity':'ticket-2','text':'其他问题'}]
test = [{'entity':'ticket-1','text':'原问题的改写'}, {'entity':'ticket-3','text':'新问题'}]
leaks = {r['entity'] for r in train} & {r['entity'] for r in test}
print(sorted(leaks))
```

参数比例只对应一个指定矩阵。实体交集抓到文本不同的同一工单泄漏，说明只按文本精确去重不够。

## 从示例走向实际使用

先做小规模高质量数据试验，与原模型加提示的基线比较。如果收益只存在于同源测试题，需要重新检查泄漏与分布代表性。

课内同时计算低秩参数量与实体交集，分别对应训练资源与评估可信度两件事，不应把它们混成一个“微调成功”指标。
