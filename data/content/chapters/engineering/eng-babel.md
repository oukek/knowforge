## 从具体问题认识Babel、AST、语法转换与 polyfill

Babel 一类转换工具把某种 JavaScript 语法表示转换成目标环境可理解的形式。AST 是抽象语法树，把表达式、声明和函数等结构表示为节点。语法转换改变代码怎么写，polyfill 则补充运行时缺少的能力，两者解决不同问题。

例如旧环境不认识箭头函数，需要语法转换；旧环境没有某个 Promise 静态方法，即使语法解析成功，调用时仍会失败，需要相应运行时实现或替代设计。

## 解析、遍历、生成与运行时能力

解析器先把源码转换成语法树，插件遍历并修改目标节点，生成器再输出代码和 source map。source map 记录生成位置与原始位置的关系，帮助错误定位；多次转换若丢失映射，生产堆栈就可能只能指向压缩后的无意义位置。

转换目标由实际支持的浏览器或运行时决定。目标越旧，需要的语法转换和辅助代码可能越多，但也不是所有新能力都能完整模拟。涉及宿主行为、性能特征或底层协议的功能，不能仅靠一个 polyfill 保证完全等价。

TypeScript 类型擦除、语法转译和类型检查也应分开理解。某个工具能把 TS 变成 JS，并不表示它执行了完整类型检查。构建链中应明确哪个步骤检查类型、哪个步骤转换语法、哪个步骤注入运行时辅助，避免误以为“构建成功”已经覆盖所有质量要求。

## 把机制放到一条完整路径中

```flow
源码兼容处理
解析源码｜建立 AST 与来源位置
语法转换｜针对目标环境修改节点
能力补充｜按需提供缺失运行时实现
目标验证｜在实际支持环境执行关键路径
```

## 配套代码：语法兼容与运行时方法兼容分离

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

用注入的能力表模拟缺少内置方法，不修改全局 Promise。

```javascript
function firstAvailable(values, runtime) {
  if (typeof runtime.any !== 'function') return '需要 polyfill 或替代方案';
  return runtime.any(values);
}
console.log(firstAvailable([], {}));
console.log(firstAvailable([1,2], {any:values=>values[0]}));
```

代码能解析不代表运行时方法存在。这里注入的 any 只作同步能力占位，并不是 Promise.any 实现；真实 polyfill 要按目标环境选择和验证。

## 从示例走向实际使用

根据用户环境制定支持范围，用最小目标环境运行关键功能。检查最终产物是否包含必要的辅助实现，同时避免全量引入巨大兼容包。

排查兼容问题时先分类：解析阶段报语法错误、执行阶段缺少方法，还是 API 行为不一致。分类正确后，才能决定修改构建目标、补充运行时能力或调整功能方案。
