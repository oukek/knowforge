## 为什么工具执行需要独立边界
能生成代码不代表应该获得宿主机器的全部权限。模型输入与检索内容都可能诱导危险行动，代码也可能意外读到秘密、无限循环或消耗磁盘。执行环境应只获得当前任务需要的文件、网络和工具能力，宿主继续负责授权、资源与产物校验。

容器通常共享宿主内核，Web Worker 主要隔离执行线程，二者都不能单凭名称保证完整安全。课程编辑器的 Worker 用于分离执行和超时终止，不应据此宣称可以安全运行任意不可信生产代码。真实隔离强度取决于平台、配置与威胁模型。
## 能力应以具体资源表达
与其给“可以运行 shell”，不如给只读输入目录、可写工作目录、批准的网络目标、固定工具和时间/内存/磁盘上限。凭据按任务临时注入并限制作用域，任务结束撤销。模型看到的工具菜单和实际宿主策略必须一致，后者是最终强制点。

| 能力 | 应有边界 | 需要防止 |
|---|---|---|
| 文件读取 | 允许根目录和文件类型 | 绝对路径、穿越和符号链接 |
| 网络 | 出口域名、解析与重定向策略 | 内网探测、元数据接口和外传 |
| 进程 | 固定入口、资源配额 | 命令注入、后台残留进程 |
| 产物 | 独立输出目录和审核 | 越权覆盖与直接公开敏感文件 |

模型在提示里答应不读其他目录，不构成操作系统级限制。
## 路径检查的常见陷阱
简单 startsWith('/work') 会接受 '/workspace-secret'；字符串去掉 '../' 不能处理编码、平台分隔符和符号链接。需要在目标平台解析规范路径、验证目录边界，并在打开文件时处理链接和检查到使用之间的竞态。

```js
// 本课只演示已经规范化的 POSIX 路径边界
const inside = path === root || path.startsWith(root + '/');
```

生产还要防止检查后链接被替换，可使用受支持的安全打开方式、只读挂载和隔离文件系统。课程实验明确不提供完整文件系统防护，不能直接复制当沙箱。
## 网络与秘密的边界
仅检查 URL 字符串不足以防 SSRF，还要检查解析 IP、重定向目标、代理路径和允许的协议。开发时需要访问本机服务可以显式放行特定地址，不应因此在线上放开整个私有网段。将工具结果中的链接视为待验证输入。

密钥不能随环境变量全集传给子进程，也不能嵌在命令行日志中。对外请求采用短期、范围受限的凭据；审计只保留必要元数据。输出脱敏是补充，不能替代执行前限制，因为原文可能已经被发出。
## 可运行实验：策略组合而非真实执行
实验只检查经过规范化的路径、允许域名与写入动作，返回 allow/deny，不执行命令、不访问网络。'/workshop' 应拒绝，'/work/output.txt' 可按权限写入，未知网络目标拒绝。相同路径在只读能力下仍不能写入。

修改 root、host 和 write 能力观察授权矩阵。然后思考符号链接、DNS 重绑定和后台进程：这些都超出字符串策略模型，必须由真实宿主执行层处理。分清教学模型和生产保证是本课重要目标。
## 生命周期、产物与验收
每次任务记录执行身份、环境版本、允许能力、资源峰值和退出原因。超时应结束整个任务进程组或相应隔离单元，取消后确认子进程、文件锁和网络连接清理。持久化输出之前扫描文件类型、大小、敏感内容与归属，发布需要单独授权。

测试路径前缀相似、符号链接跳出、压缩包解压穿越、重定向、无限输出、磁盘满、取消和凭据过期。高风险执行环境应使用成熟隔离方案并独立审计；不能靠一段正则表达式承诺任意代码安全。
