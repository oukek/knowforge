## 从具体问题认识短期与长期记忆

记忆混乱通常不是简单把向量库清空就能解决。根因可能在写入时把推测当事实、读取时混入其他用户、更新后旧摘要未失效，或者冲突规则只按时间覆盖。需要沿写入、索引、检索和注入全链路定位。

短期状态记录当前任务进展，长期记忆保存未来可能复用的信息。数据库里存得久，不代表它就适合作为长期事实。

## 从污染隔离到可信重建

出现污染先停止继续自动写入可疑来源，并保留必要审计证据。按用户、来源、时间和提取版本定位受影响记录，避免一边排障一边让错误记忆继续扩散到摘要和后续会话。

纠错时回到原始授权证据，区分确认事实、推断与过期状态。对冲突设置待核验，而不是任选最新值。修复主记录后同步失效向量索引、摘要与缓存，必要时重建派生数据。

预防机制包括写入质量门、用户查看纠正、来源与版本、有效期和读取隔离。新提取器上线用固定样本验证误记率与冲突率，不能只看“成功保存了多少条”。

## 用作用域而非存储介质区分

短期记忆通常是一次线程/任务的消息、当前状态和待办，即使通过 checkpointer 存数据库，仍可属于短期作用域。长期记忆跨会话保留用户偏好、事实、经验与程序性规则。二者不等于“内存和数据库”或“最近十条与全部历史”；检索知识库是组织知识，也不自动等同个人记忆。

## 长期记忆如何形成

先从交互中提取候选，分类为事实、偏好、事件或未经证实的推断；对可保存范围取得适当用户同意，检查敏感性、来源与主体。记录 tenant/user、类型、规范键、值、来源、发生/有效时间、置信来源、版本、过期与状态。结构化属性放关系/文档存储，语义检索可附向量，向量库不是唯一事实账本。

写入采用候选、验证、合并、激活步骤，不能把模型的所有总结直接永久保存。用户一句“举个例子，假设我住北京”不应覆盖真实城市；被引用文本也不是用户承诺。高风险身份、权限和财务事实应来自业务系统，不能从聊天推断后赋权。

## 检索和注入怎样控制

先按租户/主体、类型、有效期与来源过滤，再按任务相关性检索和重排，去冲突后在预算内加入上下文。把记忆作为带来源的资料，不能升级成系统指令。短期历史用摘要加近期窗口，关键未完成约束保留结构化状态；被裁剪的原文可按版本回读。

## 记忆混乱的修复步骤

先暂停可疑写入并按用户/类型隔离，保留审计。检查实体归属、重复键、时间线、模型提取错误和跨租户污染；事实有有效时间与来源优先级，不是“更新更晚就真”。冲突时标 disputed、向用户澄清或回查权威系统，旧版本标 superseded 而非无痕覆盖。删除需传播到主存、向量、摘要和缓存，并考虑备份恢复后删除标记重放。

## 示例与验证策略

可运行例子以用户确认优先、按规范键存储，拒绝把推断值覆盖已确认值，保留冲突说明。真实系统应对并发写入用版本 CAS/事务，对跨用户相似姓名做隔离测试。记忆评价看检索正确性、冲突率、纠正传播、遗忘达成和任务帮助程度，不能只看“能记住很多事”。

## 面试如何讲清完整生命周期

分别回答“何时写、写什么、如何查、冲突怎么办、何时忘、用户如何纠错”。长期记忆不是无上限堆历史；必要时从可靠事件重新构建派生视图，并冻结问题版本。没有用户可查看和删除的入口，记忆很容易变成无法解释的隐藏状态。

## 把机制放到一条完整路径中

```flow
记忆污染修复
隔离来源｜停止可疑自动写入并定位影响
核实原证据｜区分确认推测冲突与失效
修复派生数据｜同步索引摘要和缓存
加强质量门｜测试提取规则与用户纠错路径
```

使用本地 JavaScript 模型验证关键不变量；不调用真实数据库、模型或生产服务。实验简化之处与真实系统步骤见正文。

```javascript
const memory=new Map();
function remember(key,value,source) {
 const old=memory.get(key);
 if(old?.source==='confirmed' && source!=='confirmed') return 'conflict_review';
 memory.set(key,{value,source}); return 'saved';
}
console.log(remember('u1:language','zh','confirmed'));
console.log(remember('u1:language','en','inferred'));
console.log(memory.get('u1:language').value);
```

## 从示例走向实际使用

设计记忆管理页面和纠错事件，用户改正一次后所有后续检索都应尊重新事实。删除与账号切换尤其要检查派生缓存。

课内 confirmed 优先于 inferred 展示一种保护规则；真实系统还应允许新的明确更正，并保留为何替换的证据。
