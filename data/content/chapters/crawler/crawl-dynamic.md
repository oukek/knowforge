## 从具体问题认识动态页面、浏览器自动化与显式等待

有些页面初始 HTML 只包含应用壳，内容在 JavaScript 执行后通过接口获取并渲染。普通 HTTP 客户端不会执行页面脚本，因此看到空列表未必是选择器错了。浏览器自动化可以运行真实页面，但资源成本与状态复杂度都更高。

先观察允许访问的页面如何加载数据：若有正式 API 或可用静态内容，未必需要启动浏览器；确实依赖交互与脚本时，再使用浏览器流程。

## 等待业务条件而不是猜秒数

页面 load 事件不等于业务数据已准备好，网络暂时空闲也不一定代表应用完成。应等待可观察的业务条件，例如加载标记消失并出现结果或明确空态。固定 sleep 两秒在快环境浪费时间，在慢环境又可能不够。

等待条件要区分加载中、成功空结果、成功有结果和失败。只等待第一条记录出现，会让合法空列表永久超时；只等待容器出现，则可能过早读取空壳。超时时保存必要的页面状态与日志，帮助判断是导航失败、接口失败还是选择器变化。

浏览器上下文隔离会话与存储，任务结束后关闭页面和上下文，限制同时打开的数量。不要为了并发无限启动浏览器实例。自动化需要的账号权限仍受正常授权约束，不能把浏览器工具当作绕过访问限制的理由。

## 把机制放到一条完整路径中

```flow
动态页面采集
导航启动｜建立受控浏览器上下文
识别状态｜区分加载成功空态与失败
显式等待｜等待具体业务条件成立
提取清理｜读取稳定内容并释放浏览器资源
```

## 配套代码：动态页面、浏览器自动化与显式等待：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

states=[{'loaded':False,'rows':[]},{'loaded':True,'rows':[]},{'loaded':True,'rows':['A']}]
show(['loading' if not s['loaded'] else ('empty' if not s['rows'] else 'ready') for s in states])
```

状态模型把加载中、成功空集和成功有值分开，没有启动真实浏览器。真实自动化应等待可验证的业务条件并为超时保留证据；不能从 rows 为空就直接断言页面没有数据。

## 从示例走向实际使用

对自有测试页设置延迟加载、空列表与接口错误，验证等待逻辑能分别结束。将提取函数尽量保持纯粹，让浏览器只负责取得稳定 DOM。

课内状态数组解释为什么 loaded 与 rows 要一起判断。真实自动化还应处理弹窗、导航变化和页面销毁，但不应靠不断增加固定等待时间掩盖状态设计问题。
