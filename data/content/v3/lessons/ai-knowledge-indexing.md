## 文档不是天然可检索文本
PDF、表格、图片和网页需要解析；OCR 可能丢字，表格可能失去表头关系，页面导航可能变成噪声。索引前先抽样检查实际文本，保留文档版本与来源定位。原文件读起来正确不代表解析后的片段正确。

Chunk 是用于检索和装配上下文的片段，粒度取决于任务和结构。固定长度易实现，按标题/段落/语义边界更能保留关系，但需要处理超长段、代码和表格。重叠减少边界割裂，也会增加重复、费用和去重难度。
## 元数据不是附属装饰
每块至少有稳定 chunk_id、source_id、source_version、位置与权限范围，还应记录 embedding 版本和构建版本。更新或删除时用这些关系定位派生数据，不靠内容相似猜哪块过期。

| 字段 | 用途 | 缺失后果 |
|---|---|---|
| 来源与位置 | 引用与原文回查 | 只剩无法核验的向量 |
| 租户/ACL | 检索与读取授权 | 相似内容跨用户泄漏 |
| 内容版本 | 更新和缓存失效 | 旧政策残留 |
| 向量版本 | 模型升级 | 不兼容空间混用 |

分块 ID 可以按业务版本规则稳定生成，注意删除再同步不能把旧内容复活。
## ANN 与精确近邻
精确搜索计算所有候选距离；近似近邻 ANN 用索引结构换取更低查询代价。HNSW 是图式近邻方法之一，索引参数影响召回、内存、构建和延迟。向量库还可能支持过滤与混合查询，实际行为要对实现验证。

ANN 的 Recall 与最终答案正确率不是同一个指标。过滤在近邻前后不同可能改变候选覆盖，不能只开一个索引开关就宣布 RAG 完成。
## 可运行实验：固定窗口分块与边界
实验将一个数组按 size=4、overlap=1 分块，记录 start 和 end，验证最后短块以及不丢元素。它把数组元素当教学 token，不实现真实 tokenizer，也不处理语义结构。非法 overlap 大于等于 size 应拒绝，避免步长为零死循环。

将关键条件放在切片边界，观察同一块是否同时包含条件和结论。之后加入按段落分块，比较证据完整性与重复，而不是只看块数减少。
## 如何验收入库质量
准备含标题、否定、跨页表格、代码、扫描件和版本更新的资料，检查原文→文本→块→索引的映射。对删除和撤权做回归，确认向量、缓存、摘要与引用链同步失效。

记录离线解析与 embedding 成本、索引规模、在线召回和生成质量。调优分块时固定语料、问题和最终上下文预算，避免把更多输入 token 带来的收益误认作算法提升。
