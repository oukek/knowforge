## 从具体问题认识分页、过滤、排序与稳定游标

列表 API 需要限制一次返回的数据量，并定义过滤与排序。分页不仅是加 limit，还要保证客户端知道如何继续，以及数据变化时结果具有什么稳定性。offset 适合简单跳页，游标适合沿稳定顺序继续，两者各有代价。

例如按更新时间列出文章，很多文章可能拥有相同时间。只用时间作为下一页边界，会让并列记录重复或遗漏，需要唯一并列键参与排序。

## 稳定游标与查询约束

复合排序可使用 (updated_at,id)，游标保存上页最后一项的对应值。下一页查询遵守同一方向与比较规则，并使用匹配索引。游标应被视为不透明协议，包含必要版本或查询条件绑定；客户端不应自己猜内部编码。

过滤与排序字段使用白名单映射到数据库列，不能直接把用户字符串拼成 SQL。参数值用绑定参数处理，排序方向与字段名则通过受控枚举选择。页大小有合理上限，昂贵总数统计可按业务需求提供，而不是每页都无条件 count 全表。

游标不自动提供整次遍历的快照一致性。数据在请求之间新增、更新或删除时，仍需说明是动态列表、固定快照还是某个截止时间范围。权限过滤必须参与每页查询，不能先取全量再在前端隐藏。

## 把机制放到一条完整路径中

```flow
稳定列表接口
定义查询｜固定过滤排序与页大小边界
读取游标｜验证版本及查询作用域
范围查询｜按复合键取得下一页
返回继续点｜携带不透明游标与明确结束状态
```

## 配套代码：分页、过滤、排序与稳定游标：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

rows=[(10,1),(10,2),(11,1)]
after=(10,1)
page=[row for row in rows if row>after][:2]
show([list(x) for x in page])
```

用排序键与唯一 ID 组成稳定边界，避免相同时间戳被跳过。这里不涉及真实数据库快照或签名游标；实际查询必须与相同排序规则配套索引，且权限过滤在返回结果前执行。
