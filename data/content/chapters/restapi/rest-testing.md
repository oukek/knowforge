## 从具体问题认识API 契约、集成、越权与故障测试

API 测试要验证外部契约与业务状态，而不只是检查某个函数返回了预期字符串。接口可能状态码正确却写错用户数据，也可能正常场景通过但并发重试造成重复扣费。测试范围应由风险和不变量决定。

单元测试适合纯业务规则，集成测试验证数据库与框架协作，契约测试验证消费者看到的协议，端到端测试验证关键用户路径。不同层次互相补充。

## 从正常路径扩展到权限与故障

每个资源至少建立匿名、本人、其他用户与跨租户访问矩阵，覆盖读取、修改、删除和导出。错误响应检查状态、字段与敏感信息，而不是只断言“抛异常”。输入测试包含类型、长度、未知字段和边界数值。

写接口测试并发与恢复：同一幂等键同时提交、事务中途失败、提交后响应丢失、旧版本条件更新。使用真实数据库集成测试验证唯一索引与事务行为，内存 mock 无法证明这些竞争条件正确。外部服务用受控替身注入超时、限流和异常格式。

测试数据隔离且可重复，时钟、随机数与网络依赖尽量可控制。断言应围绕结果与不变量，不紧绑内部函数调用次数，否则合理重构就会让测试大量失败。少量关键端到端路径比重复覆盖同一简单实现更有价值。

## 配套代码：API 契约、集成、越权与故障测试：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

cases=[('owner',200),('other_user',404),('anonymous',401)]
show([{'actor':actor,'expected_status':status} for actor,status in cases])
```

矩阵中的 404 是本示例选择的资源隐藏策略，不是所有 API 必须如此；也可按契约使用 403。测试应先明确策略，再验证实际返回、公开字段与数据库变化，避免把任意状态码硬编码成普遍标准。
