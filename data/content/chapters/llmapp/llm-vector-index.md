## 从具体问题认识向量索引、ANN、元数据过滤与删除

向量索引让系统在大量向量中较快找到近邻。精确搜索逐一比较，近似近邻搜索通过索引结构减少工作，以一定召回损失换取速度与容量。索引不是数据真相来源，它是可重建的检索结构。

文档删除、权限变化和模型升级都会影响索引有效性，因此向量库接入不仅是写入与查询两个接口。

## 候选搜索、过滤与生命周期

ANN 参数影响候选探索范围，探索更多通常提高召回并增加延迟或资源，但具体关系依索引算法与数据分布。先用小规模精确搜索建立基线，才能判断低召回来自 embedding 还是近似索引。

元数据过滤应与权限一致。先取全库 top-k 再过滤，可能得到很少合法结果，也可能在中间链路暴露不该访问的资料；应使用满足隔离要求的检索策略，并验证过滤与 ANN 的实际交互。租户过滤不是用户可随意提交的普通条件。

更新需要替换旧文档片段，删除需要失效相应向量与缓存。异步索引任务提交前检查文档与模型版本，防止旧任务晚到把已删除或更新的内容重新写回。大规模迁移可建立新索引、验证后切换别名或路由，并保留回退。

## 把机制放到一条完整路径中

```flow
向量索引生命周期
构建版本｜固定空间与文档元数据
授权搜索｜过滤后获得近邻候选
更新删除｜按文档版本替换失效片段
迁移验证｜新旧索引对照后受控切换
```

## 配套代码：向量索引、ANN、元数据过滤与删除：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

docs=[{'id':'a','tenant':'t1','score':0.8},{'id':'b','tenant':'t2','score':0.99}]
visible=[d for d in docs if d['tenant']=='t1']
show([d['id'] for d in sorted(visible,key=lambda d:-d['score'])])
```

样本强调高相似度不越过权限边界，没有实现 ANN 索引。真实系统中可信 tenant 来自认证上下文，过滤与索引参数要联合评估；不能接受用户自行提交的租户字段就直接扩大检索范围。

## 从示例走向实际使用

测试新增后可查、更新后旧片段消失、删除后无法召回，以及跨租户相同文本不串数据。记录索引版本和构建状态，避免半成品索引直接上线。
