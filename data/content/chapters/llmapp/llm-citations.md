## 从具体问题认识引用、证据支持与冲突处理

引用把回答中的主张连接到可检查来源。链接能打开，只说明地址有效；文档主题相关，也不一定支持回答里的具体数字或结论。可靠引用需要验证身份、版本、权限与语义支持。

例如答案说“所有员工都可以报销 500 元”，引用段落却写“正式员工”，链接虽然真实，主张仍然扩大了适用范围。

## 主张与证据的多对多关系

把答案拆成可核对主张，每条关联一个或多个证据片段。一个主张可能需要两段共同支持，一段资料也可能支持多个主张。引用 ID 应来自后端实际提供集合，模型不能自由生成任意编号或 URL 作为证据。

先检查引用是否存在、是否授权、是否为有效版本，再检查内容是否支持。资格检查可以确定性完成，语义支持可能结合规则、模型评估与人工抽样，但不能因为 ID 合法就宣布答案有据。时间与地域条件也属于支持关系。

冲突来源需要说明差异与优先依据，例如生效日期、文档级别或适用对象。没有可靠规则时应呈现不确定，不能拼接成一个自信结论。引用展示保留页码、段落或原文范围，方便用户快速复核，而不是只跳到整份长文首页。

## 把机制放到一条完整路径中

```flow
引用验证
拆分主张｜识别可核对的事实与条件
检查资格｜来源存在授权且版本有效
核对支持｜判断完整支持矛盾或缺失
呈现位置｜让用户直接查看相关原文
```

## 配套代码：引用、证据支持与冲突处理：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

allowed={'c1','c2'}
citations=['c1','invented']
show([x for x in citations if x not in allowed])
show(all(x in allowed for x in ['c1']))
```

集合校验能发现虚构 ID，但不能证明 c1 的内容支持回答。完整验收还要检查片段与陈述关系、来源版本和用户权限；这一步是确定性验证，可在任何模型生成后执行。

## 从示例走向实际使用

准备真实但不支持、已过期、跨权限、部分支持和多证据共同支持的样本。分别验证资格与语义，避免测试只覆盖不存在 ID。

课内 allowed 集合只检查引用身份，不检查主张含义。它是第一道门，后续证据契约课程继续展开完整验证。
