## 从具体问题认识Agent 执行沙箱

执行沙箱限制 Agent 能接触的文件、网络、进程和资源。它的目的不是让模型永远不提出危险动作，而是让越界提议无法产生对应效果。提示词只能表达意图，操作系统和服务边界负责强制限制。

例如允许读取 /work 下的资料，不代表允许写入，也不代表可以访问名称相似的 /workshop。权限应按具体资源与动作表达。

## 能力授权与真实隔离的差别

路径策略要考虑规范化、相对路径、符号链接和检查后替换竞态。字符串 startsWith 只能做教学示意，真实文件访问应依赖受控目录、文件句柄或操作系统隔离，避免检查路径和实际打开对象不一致。

网络策略限制目标、协议和重定向，并考虑 DNS 变化与内部地址。仅过滤初始 URL 不能阻止后续跳转。秘密尽量由工具服务使用，不直接放入模型上下文或可读文件；输出和日志同样可能成为泄漏通道。

运行环境还要限制 CPU、内存、时间、进程与产物大小，任务结束后清理临时资源。产物从沙箱带回主系统前再次验证类型和用途。隔离方案需要按实际威胁与平台能力评估，不能把一个进程目录当完整沙箱。

## 为什么工具执行需要独立边界

能生成代码不代表应该获得宿主机器的全部权限。模型输入与检索内容都可能诱导危险行动，代码也可能意外读到秘密、无限循环或消耗磁盘。执行环境应只获得当前任务需要的文件、网络和工具能力，宿主继续负责授权、资源与产物校验。

容器通常共享宿主内核，Web Worker 主要隔离执行线程，二者都不能单凭名称保证完整安全。课程编辑器的 Worker 用于分离执行和超时终止，不应据此宣称可以安全运行任意不可信生产代码。真实隔离强度取决于平台、配置与威胁模型。

## 能力应以具体资源表达

与其给“可以运行 shell”，不如给只读输入目录、可写工作目录、批准的网络目标、固定工具和时间/内存/磁盘上限。凭据按任务临时注入并限制作用域，任务结束撤销。模型看到的工具菜单和实际宿主策略必须一致，后者是最终强制点。

| 能力 | 应有边界 | 需要防止 |
|---|---|---|
| 文件读取 | 允许根目录和文件类型 | 绝对路径、穿越和符号链接 |
| 网络 | 出口域名、解析与重定向策略 | 内网探测、元数据接口和外传 |
| 进程 | 固定入口、资源配额 | 命令注入、后台残留进程 |
| 产物 | 独立输出目录和审核 | 越权覆盖与直接公开敏感文件 |

模型在提示里答应不读其他目录，不构成操作系统级限制。

## 路径检查的常见陷阱

简单 startsWith('/work') 会接受 '/workspace-secret'；字符串去掉 '../' 不能处理编码、平台分隔符和符号链接。需要在目标平台解析规范路径、验证目录边界，并在打开文件时处理链接和检查到使用之间的竞态。

```js
// 本课只演示已经规范化的 POSIX 路径边界
const inside = path === root || path.startsWith(root + '/');
```

生产还要防止检查后链接被替换，可使用受支持的安全打开方式、只读挂载和隔离文件系统。课程实验明确不提供完整文件系统防护，不能直接复制当沙箱。

## 网络与秘密的边界

仅检查 URL 字符串不足以防 SSRF，还要检查解析 IP、重定向目标、代理路径和允许的协议。开发时需要访问本机服务可以显式放行特定地址，不应因此在线上放开整个私有网段。将工具结果中的链接视为待验证输入。

密钥不能随环境变量全集传给子进程，也不能嵌在命令行日志中。对外请求采用短期、范围受限的凭据；审计只保留必要元数据。输出脱敏是补充，不能替代执行前限制，因为原文可能已经被发出。

## 生命周期、产物与验收

每次任务记录执行身份、环境版本、允许能力、资源峰值和退出原因。超时应结束整个任务进程组或相应隔离单元，取消后确认子进程、文件锁和网络连接清理。持久化输出之前扫描文件类型、大小、敏感内容与归属，发布需要单独授权。

测试路径前缀相似、符号链接跳出、压缩包解压穿越、重定向、无限输出、磁盘满、取消和凭据过期。高风险执行环境应使用成熟隔离方案并独立审计；不能靠一段正则表达式承诺任意代码安全。

## 把机制放到一条完整路径中

```flow
沙箱执行
授予最小能力｜限定目录动作网络与资源量
建立隔离环境｜阻止越界资源访问
执行与监控｜传播取消并限制时间产物
检查回收｜验证输出并清理临时状态
```

## 配套代码：Agent 执行沙箱：能力、文件边界与外网控制

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
function authorize(cap, action) {
  // 输入已是规范化 POSIX 路径；不处理真实文件系统链接与竞态。
  const inside =
    action.path === cap.root || action.path.startsWith(cap.root + "/");
  if (!inside) return false;
  if (action.write && !cap.write) return false;
  if (action.host && !cap.hosts.includes(action.host)) return false;
  return true;
}
const cap = { root: "/work", write: false, hosts: ["docs.example.test"] };
console.log(authorize(cap, { path: "/work/readme.txt" }));
console.log(authorize(cap, { path: "/workshop/secret" }));
console.log(authorize(cap, { path: "/work/out", write: true }));
console.log(authorize(cap, { path: "/work/out", host: "evil.example.test" }));
console.log("策略模型不替代操作系统隔离");
```

严格目录边界避免相似前缀，写入和网络是独立能力。路径必须由可信适配器规范化，真实链接、DNS 和竞态不在此模型保证范围。

## 从示例走向实际使用

用路径穿越、同名前缀、符号链接、重定向、超时和超大输出做边界测试。观察拒绝发生在真正资源访问层，而不是仅在模型回复中表示拒绝。

课内明确假设 POSIX 路径已规范化，不执行真实文件操作；它演示能力组合，不证明操作系统隔离已经成立。
