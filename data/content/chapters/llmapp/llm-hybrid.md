## 从具体问题认识关键词、语义召回与 RRF 混合检索

关键词检索擅长精确词项、编号与稀有名称，语义向量检索擅长不同措辞表达相近意思。混合检索让两类候选互补，但它不是把两个分数随意相加。不同检索器的分值尺度通常没有直接可比性。

用户问 ERR_CONNECTION_RESET，精确字符串很重要；问“连接突然被断开怎么办”，语义检索可能更有帮助。同一评估集应同时包含这些类型。

## 排名融合与候选去重

RRF 按排名贡献而非原始分值融合，例如每个列表中第 r 名贡献 1/(k+r)。同一文档在多路排名靠前会累加更高分，k 控制头部差异的影响。它避免直接混合不同量纲，但仍需要调参与评估，并非任何数据都最优。

每一路应先按稳定文档或片段身份去重，权限过滤与查询条件保持一致。若一个列表把相同文档重复多次，简单累加会不公平地抬高它。融合后可扩大候选，再由重排选择最终上下文，不能只看融合后的第一项是否“像答案”。

查询改写也可能改善召回，但应保留原查询中的数字、实体与限制。把错误码改写成模糊描述可能丢掉精确线索。比较时做消融：仅关键词、仅向量、融合、融合加重排，观察哪些查询类型真正获益。

## 把机制放到一条完整路径中

```flow
混合检索
保留查询约束｜实体编号与语义意图
多路召回｜关键词与向量各取候选
去重融合｜按统一身份组合排名
后续筛选｜重排并验证证据覆盖与成本
```

## 配套代码：关键词、语义召回与 RRF 混合检索：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

def rrf(lists,k=10):
    scores={}
    for ranking in lists:
        for rank,key in enumerate(ranking,1): scores[key]=scores.get(key,0)+1/(k+rank)
    return sorted(scores,key=lambda key:(-scores[key],key))
show(rrf([['a','b'],['b','c']]))
```

b 在两个通道都出现，按排名贡献相加后靠前。样例是人工排名，没有执行真实 embedding 或关键词索引；生产应确保每通道内 ID 唯一、过滤正确，并对常数和候选预算做评估。

## 从示例走向实际使用

建立包含缩写、编号、同义表达和多条件问题的标注集，分别报告各路召回与最终结果。候选数量增加会带来重排和上下文成本，需要一起衡量。

课内 RRF 假设每路排名没有重复 ID，生产实现应验证这个前提。分数只是排序信号，不能解释成答案正确概率。
