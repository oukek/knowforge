## 从具体问题认识Prompt、RAG、微调与训练数据治理

微调是在已有模型上继续训练，使它更符合特定任务的输出方式或行为模式。它与检索不同：检索在推理时提供外部资料，微调改变参数。知识经常更新、要求引用来源的场景，通常不能只靠微调解决信息新鲜度。

例如让模型按统一客服分类体系输出标签，可以考虑高质量监督样本；让模型知道今天库存，则应查询实时系统。先判断需要改变的是行为、知识访问还是业务流程。

## 训练数据与泛化验证

监督微调把输入与期望输出配成样本，训练模型提高这类输出的概率。样本应代表真实输入分布，包含边界和拒绝条件；大量重复或错误答案会放大偏差。数据量不是唯一标准，标注一致性与任务定义通常更关键。

训练、验证和最终测试应按可能泄漏的实体、时间或来源分组切分。只是把行随机打散，可能让同一文档的改写同时出现在训练与测试里，造成虚高。去重不只比较完全相同字符串，还要考虑近重复及模板生成的同源样本。

先与提示、检索和更合适的基座模型比较，确认微调收益超过训练、维护与更新成本。评估既看目标任务提升，也看原能力退化、边界行为和部署延迟。训练损失下降说明更拟合训练目标，不自动等于业务成功率提高。

## 把机制放到一条完整路径中

```flow
微调决策链
定位差距｜判断行为知识还是流程问题

训练对照｜比较基座提示检索与微调
验收发布｜检查收益退化和版本可回滚性
```

## 配套代码：Prompt、RAG、微调与训练数据治理：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

train={'a','b','c'}; validation={'c','d'}
show(sorted(train & validation))
show(not bool(train & {'e','f'}))
```

精确 ID 交集检查能发现明显泄漏，真实数据还需要近似去重、同源文档和时间划分策略。示例没有训练模型，训练收益必须在独立真实任务集验证，不能用此集合操作替代数据治理。

## 从示例走向实际使用

记录数据版本、标签规范、基座模型与训练参数。新版本在固定验收集和真实切片上比较，保留回滚路径。用户敏感数据进入训练前还要确认用途与授权。

课内集合交集只能发现完全相同 ID 的泄漏，是数据检查起点；真实项目还应做近重复检测与按来源分组验证。
