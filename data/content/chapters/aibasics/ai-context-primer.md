## 从具体问题认识上下文、历史与记忆

模型在一次推理中只能利用实际提供给它的上下文与自身参数。聊天界面显示的全部历史，不一定都被发送；应用可能裁剪、摘要或检索其中一部分。因此“模型忘了”需要先检查它这一轮到底看到了什么。

上下文窗口有限，历史越长越需要选择。简单保留最后几条消息，可能留下寒暄却丢掉最初的约束、用户已批准的决定或尚未完成的工具结果。

## 任务状态与聊天文本分别保存

将上下文拆成稳定指令、当前目标、已确认事实、进行中状态、必要历史与检索证据。任务状态可以用结构化字段保存，例如目标资源、允许操作、已完成步骤和待确认事项；不必每次从全部聊天文本重新猜测。

摘要减少长度，但会损失细节并可能引入错误。摘要应保留来源、版本与不确定性，不能把用户假设改写为已验证事实。检索只把当前相关内容放入上下文，需要权限与时间过滤；旧偏好或过期政策不应因为语义相似而覆盖新事实。

工具调用与结果形成协议关系，裁剪时需要保持配对与必要状态。上下文预算还要预留输出、工具定义和多模态开销，不能把最大窗口全部塞满用户历史。更长上下文也不保证注意与推理质量线性提高，内容组织与检索质量仍重要。

## 模型实际看到了什么

**模型本轮能看到什么，由实际传入的上下文决定。** 界面即使显示了前一天完整聊天，后端也可能只发送最近几条和一份摘要；如果订单号被截掉，模型就不能保证继续知道它。

可以把上下文想成一次考试允许带入考场的资料：历史记录、系统要求和检索文档占据有限空间。长期保存的用户偏好需要由应用明确读取，结构化业务状态也应有可信来源；展示在页面上并不自动等于已包含在模型请求中。

例如用户在新会话中说“还是同一家店”，如果应用没有检索并提供已授权的偏好记录，模型不一定知道是哪一家。

上下文是当前推理请求可使用的信息，包括规则、用户输入、历史、工具和证据。界面展示完整聊天，不代表服务真的把全部消息发给模型。产品可能截断、检索或摘要历史；是否有服务端状态也取决于接口实现。

参数知识来自训练，会话历史是记录，应用状态是结构化业务事实，长期记忆是应用选择保存和读取的信息。它们不是同一存储，更不是模型拥有无限私人记忆。访问控制和删除规则要分别设计。

## 任务最小状态应该保留什么

一个订票任务至少需要当前目标、已确认条件、未决问题、已执行动作与凭据、限制和事实来源。中间几十次搜索日志可以压缩，但“尚未确认付款”不能丢掉。上下文不是越长越好，噪声和冲突也占预算。

| 内容 | 适合保存位置 | 重新使用前检查 |
|---|---|---|
| 已付款凭据 | 业务数据库 | 当前操作状态 |
| 对话摘要 | 应用状态/会话存储 | 版本、来源与缺失 |
| 用户偏好 | 受控长期记忆 | 作用域、确认与有效期 |
| 大段搜索原文 | 版本化资料与索引 | 权限和时效 |

不要把一段流畅摘要当作权威支付事实，也不要让模型自报“已确认”就越过真实确认流程。

## 裁剪、摘要与检索的取舍

裁剪简单但会丢信息；摘要压缩语义但可能遗漏或改变条件；检索按需找回片段但受召回质量影响。可组合使用：稳定任务状态始终保留，较旧细节通过来源指针按需读取。工具调用与结果需保持合法配对。

压缩后对关键问题回归：用户到底同意了什么、哪一步已经提交、还缺什么、证据从哪来。不能只计算字数减少比例。某些服务的原生压缩状态项是不透明数据，按对应接口约定续接，不随意编辑。

## 如何验证“忘记”的原因

保存本轮实际输入快照或受控来源指针，定位信息没被发出、被压缩遗漏、检索漏召回还是模型没正确使用。相同 UI 历史可能对应不同模型输入，不能只截图对话定位问题。

验收长会话包含目标变更、纠正偏好、过期事实、重复操作与用户撤回。真正的可靠记忆需要可追踪、可纠正和可删除；无限追加聊天往往同时增加费用与错误。

## 把机制放到一条完整路径中

```flow
上下文组织
提取任务状态｜目标约束与已确认事实
选择相关材料｜历史摘要与授权检索
校验预算结构｜保留工具配对并预留输出
验证使用效果｜区分未提供与未正确理解
```

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
const history = [
  "old search",
  "old draft",
  "recent question",
  "recent clarification",
];
const state = {
  goal: "book ticket",
  pending: "payment confirmation",
  operationIds: ["query-1"],
};
const input = { state, history: history.slice(-2) };
console.log(input.history);
console.log(input.state.pending);
console.log(input.state.operationIds);
```

关键任务状态独立于裁剪后的闲聊历史。真实付款凭据应来自业务系统，不能凭这段内存对象获得授权。
