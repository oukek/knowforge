## 从具体问题认识增量水位、迟到数据与删除同步

增量采集只处理上次以来新增或变化的数据，减少重复下载。水位是记录进度的边界，例如已处理的更新时间与 ID。它必须与来源排序和迟到规则一致，否则看似高效的增量可能永久漏掉记录。

只保存最大更新时间 10，再查询更新时间大于 10，会漏掉稍后才出现但同样标记为 10 的记录。使用复合水位可以解决并列顺序的一部分问题，但不能自动解决所有迟到数据。

## 稳定游标、重叠窗口与删除

若来源按 (updated_at,id) 稳定排序，可以保存这对值作为继续位置，比较时采用同一排序规则。水位只在对应数据可靠保存后推进，失败恢复可重复读取边界附近记录，再通过业务键与版本去重。

来源数据可能迟到、时间被回填或时钟不一致，因此常需要重叠回看窗口或周期性全量对账。窗口大小应根据实际迟到分布与业务要求决定，不能保证任意固定五分钟永不漏数。若来源提供变更日志或稳定事件序号，通常更适合追踪变化。

删除不会自然出现在“更新时间更大”的查询里，需 tombstone、删除事件或快照对账。一次分页没看见某条记录，也不能直接断言它已删除，因为可能是权限变化、请求失败或分页范围不同。删除传播还要覆盖缓存、搜索和向量索引。

## 把机制放到一条完整路径中

```flow
增量同步
确定水位｜选择稳定时间序号与并列键
获取变化｜按游标并适当回看
可靠更新｜按身份版本幂等写入
补偿对账｜处理迟到删除与长期遗漏
```

## 配套代码：增量水位、迟到数据与删除同步：最小可验证示例

下面代码在课内Python运行区执行；浏览器环境与本机CPython的网络、文件和原生扩展能力不同。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

rows=[(10,'a'),(10,'b'),(11,'a')]
watermark=(10,'a')
show([list(row) for row in rows if row>watermark])
```

元组按字典序比较，使同一时间的 b 不会因只看时间而被跳过。真实接口必须提供一致的排序契约，ID 的比较方式也要与源端一致；若排序不稳定，应依靠回看、快照或对账补足，而不是仅在客户端比较元组。
