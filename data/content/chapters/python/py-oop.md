## 类描述行为，实例保存具体状态
class执行后创建类对象，调用类通常创建实例并执行初始化过程。实例方法通过self访问当前对象；self只是约定名称，但调用绑定会把实例作为对应参数传入。__init__负责初始化已创建实例，不应返回另一对象。

类属性位于类上，实例属性通常由self赋值建立。类属性中的可变列表会被实例共享，这与每个实例在__init__里新建列表不同。很多“不同用户数据串了”的问题来自没有分清这两个位置。
## 类、实例、属性和方法分别是什么

类描述一类对象的构造方式和可用行为，实例是某次创建得到的具体对象。`self` 是实例方法显式接收的对象参数；调用 `item.rename("Go")` 时，Python 会把 item 作为方法的第一个参数。__init__ 负责初始化已经创建的实例，严格说并不是分配实例的全部过程；初学时先把创建与初始化配合起来理解即可。

实例属性存放每个对象自己的状态，类属性由类提供，多个实例可能通过查找规则访问同一个值。可变列表若放在类属性中，会被所有未遮蔽该属性的实例共享；每个实例自己的集合应在初始化中创建。

```python
class Course:
    category = "learning"
    def __init__(self, title):
        self.title = title
        self.tags = []
    def rename(self, title):
        if not title.strip():
            raise ValueError("标题不能为空")
        self.title = title

first = Course("Python")
second = Course("Go")
first.tags.append("basic")
first.rename("Python 基础")
print(first.title, first.tags, second.tags)
```

## 封装是维护不变量，而不是只给名字加下划线

把名称修改封装为 rename，是为了保证标题非空这一规则始终成立。单下划线表达内部使用约定，不是不可绕过的权限控制；property 可以在属性访问时执行逻辑，但复杂或昂贵操作通常用显式方法更清楚。真正敏感的授权必须由应用边界检查，不能靠对象字段命名保护。

继承表达“是一种”的行为替换关系，组合表达“拥有并使用另一个对象”。如果只是想复用十行发送代码，可以给服务传入 sender 对象，而不必构造多层继承。子类改写方法时应保持调用者依赖的输入、输出和失败契约；否则表面类型相同，实际不能安全替代。

Python 的多态通常基于对象提供的行为，而不要求所有实现继承同一个父类。一个支持 read 的对象可以是文件、内存流或测试替身。明确依赖最小能力，比让一个巨型基类承担所有功能更容易测试与演进。

## 用组合建立清楚职责
```python
class Cart:
    def __init__(self):
        self.items = []
    def add(self, name):
        self.items.append(name)
    def count(self):
        return len(self.items)

a = Cart()
b = Cart()
a.add("book")
print(a.count(), b.count())
```
每次初始化创建独立items，因此a变化不影响b。如果把items=[]移到类体里，就会出现共享容器。方法返回内部列表也会把修改入口交给调用者，应按接口需要返回副本、只读视图或受控操作。
## 继承、super 与方法解析
继承允许复用或替换行为，但层次越深越难推理。super遵循方法解析顺序，不只是机械地“调用直接父类”。多重继承尤其要求协作方法签名和一致调用约定；不要为了复用几行代码建立复杂继承图。
```flow
一次实例方法调用
名字指向实例｜确定对象身份
按属性查找规则找到方法｜可能来自类与基类
绑定 self｜把当前实例交给函数
读取或修改实例状态｜遵守对象不变量
返回结果或异常｜调用者按契约处理
```
## 协议与组合常常更灵活
许多Python接口依据支持的行为工作，例如迭代、上下文管理、长度等。对象不必继承某个巨大基类才能被使用，可以通过协议提供必要能力。外部服务、存储和策略适合作为依赖传入对象，让测试替身替换它们。

封装不是把所有字段都改成双下划线；关键是状态有效性、修改入口和生命周期。测试多个实例、子类覆盖、无效输入与共享依赖，确认对象边界符合业务而不是仅能调用方法。
