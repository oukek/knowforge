# KnowForge

**Learn. Practice. Build.**

A learning workbench for full-stack engineering, AI agents, algorithms, and deliberate practice.

**KnowForge · 知行实验室** 是一个基于 Vue 3 与 Node.js 的本地工程学习工作台。把知识讲解、可运行示例、自动验证练习、面试题库和复习记录放在一起，让你边读、边写、边验证。

主要内容为中文，支持 JavaScript 与 Python 双语言代码实验。学习数据可保存在服务端 MySQL 或本机 SQLite，支持账号密码公开注册，无需验证码，也无需配置模型 API Key。未登录会跳转到 `/login`，登录后返回原本访问的页面。

### 代码编辑与运行

编辑器使用 **CodeMirror 6**，支持语法高亮、括号配对、自动缩进、行号与代码草稿恢复。JavaScript 提供常用 API 补全和按需加载的 Prettier 格式化；Python 使用四格缩进。

| 操作 | 快捷键 |
| --- | --- |
| 运行代码 | `Ctrl / ⌘ + Enter` |
| 格式化 JavaScript | `Shift + Alt + F` |
| 缩进 / 反缩进 | `Tab` / `Shift + Tab` |
| 离开编辑器 | 先按 `Esc`，再按 `Tab` |

JavaScript 在独立 Web Worker 中执行；Python 通过本地 Pyodide 运行时在 Worker 中执行。运行支持实时输出与手动停止，普通 JavaScript 实验默认 4 秒超时；ACM 判题每组最多 3 秒、整次最多 15 秒，显示执行进度；Python 首次初始化需下载约 13 MB 资源并编译 WebAssembly，独立限时 180 秒，显示下载与初始化阶段。后续运行复用浏览器中的版本化资源缓存。课程示例无需调用外部模型或采集真实网站。

Python 加载较慢时显示环境准备窗口：PC 居中弹窗，手机底部面板，展示连接、清单、资源读取、初始化四个阶段，以及资源就绪数量、已读取大小和时间日志。可收起继续阅读、取消加载或复制日志；环境就绪自动关闭，之后仍可回看本次日志。快速加载不闪现弹窗。加载失败可以重新加载并运行，重试会重新校验资源；初始化失败不会记为补全题答错。环境日志和代码的 `print` 输出分别展示。

### 验证与复盘

- **预测输出**：按日志顺序逐行提交，查看缺行、多行和内容差异；JSON 值按结构比较，数值和字符串仍然区分。
- **代码补全与实验**：补上函数实现，逐条查看用例结果，并使用提示或参考解复盘。
- **单选题**：由服务端判分并展示解析。
- **原理与场景题**：对照答案要点自评，记录薄弱项和后续复习。

开放题目前采用自评，没有接入大模型自动打分。模拟面试分别展示客观题成绩和开放题复盘。

正文中的对比表格统一显示表头底色、单元格网格和隔行底色；手机与窄屏 iPad 可在表格内左右滑动，超宽时显示提示，也支持键盘聚焦后横向滚动。

## 快速开始

### 环境要求

- **Node.js 22.13 或更高版本**（部署建议 Node.js 24），支持 MySQL 与 Node 内置 SQLite。
- **npm**，用于安装依赖与运行脚本。
- 本机 **Python 3.11+** 仅用于独立 Python 配套项目及相关集成测试；浏览器中的 Python 练习使用 Pyodide。

### 开发运行

下载或克隆仓库后，在项目根目录执行：

```bash
npm ci
npm run dev
```

打开 **[http://127.0.0.1:16666/](http://127.0.0.1:16666/)**。

一条命令同时启动前端 **16666** 与后端 API **6666**，两个服务都只监听本机 `127.0.0.1`。浏览器通过前端入口访问页面；API、JavaScript / Python 运行器及 Python 运行时资源由前端服务转发到后端，热更新使用前端端口。停止使用 `Ctrl+C`。

6666 属于 Chromium 的受限端口，因此应在浏览器访问 **16666**，不需要放开浏览器端口限制。

如需自定义端口，macOS / Linux：

```bash
FRONTEND_PORT=16667 PORT=6667 npm run dev
```

PowerShell：

```powershell
$env:FRONTEND_PORT = "16667"
$env:PORT = "6667"
npm run dev
```

此时访问 `http://127.0.0.1:16667/`。两个端口必须不同；端口被占用时启动会明确报错，不自动递增。FRONTEND_PORT 仅用于本地开发及预览；生产后端只使用 PORT。

### 构建后本地预览

```bash
npm run build
npm run preview
```

本地预览通过 `http://127.0.0.1:16666/` 访问，托管 `dist/` 并代理 6666 的后端。`npm start` 用于仅启动 API 的模式，生产默认只监听 `127.0.0.1:6666`，前端由 OSS 提供。运行时需要项目依赖，包括本地 Pyodide 文件。

### GitHub Actions 手动部署

前后端使用两个独立工作流，均只支持手动触发，推送、PR 和标签不会自动部署：

| Actions 名称 | 工作流文件 | 发布目标 |
| --- | --- | --- |
| **Deploy frontend (OSS)** | `.github/workflows/deploy-frontend.yml` | 构建前端，上传 OSS |
| **Deploy backend (SSH)** | `.github/workflows/build-package.yml` | 编译独立 backend-dist 产物，更新 `/www/wwwroot/knowforge` 并按配置重启 |

两者直接复用仓库已配置的 Secrets 和 Variables，名称保持不变，不需要创建 GitHub Environment，也不需要按工作流重复填写。前端仅使用 `OSS_*` 配置，后端仅使用 `SSH_*` 配置；数据库使用服务器进程的环境变量，可直接配置在 PM2，也可使用可选的 `.env`。

将工作流提交到默认分支后，在 **Actions** 中选择对应名称，点击 **Run workflow**、选择分支并运行。`deploy` 默认开启；取消勾选则前端只构建、后端只生成部署包。两条工作流互不触发，可以单独运行。修改接口、知识数据或 Worker 时需要部署后端；两端都有改动时，对同一个 commit 先部署后端，再部署前端。

构建产物在对应运行的 **Artifacts** 中保留 30 天。后端独立运行包可手动解压后运行 `npm ci --omit=dev` 和 `npm start`。包中只有编译后的 API 服务、题库、实验及下载资源和后端专用依赖清单，不包含前端 dist、原始源码树或整个 docs；保留可选 .env 和既有服务入口。生产已移除 16666 网关，Nginx 必须回源 `http://127.0.0.1:6666`。

本地执行 `npm run build:backend` 可检查 `backend-dist/`；执行 `npm run package:deploy` 构建并生成后端压缩包。服务器运行的是编译产物，不执行构建。配置项、重启命令与正式域名配置详见 [服务器部署](docs/服务器部署.md)。

正式前端：`https://knowforge.ookew.com`；正式 API：`https://knowforge-api.ookew.com`。域名已配置在代码中，生产构建自动使用，开发继续走本地代理。请求携带 API 域名会话 Cookie，跨域预检与 CSRF 校验由后端处理；无需新增 Actions Secrets 或 Variables。

### 配置

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `FRONTEND_PORT` | `16666` | 仅本地 dev / preview 的页面、代理与 HMR 端口，生产不监听 |
| `PORT` | `6666` | 后端 API 与运行资源端口 |
| `DB_DRIVER` | `sqlite` | `mysql` 或 `sqlite`，显式选择存储引擎 |
| `DB_PATH` | `runtime/study.sqlite` | SQLite 数据库路径，MySQL 模式忽略 |
| `MYSQL_HOST` / `MYSQL_PORT` | `127.0.0.1` / `3306` | MySQL 地址与端口 |
| `MYSQL_USER` / `MYSQL_PASSWORD` | — / 空字符串 | MySQL 账号与密码 |
| `MYSQL_DATABASE` | — | 已存在的 MySQL 数据库名 |
| `MYSQL_TABLE_PREFIX` | `knowforge_` | 应用表前缀，1–40 个字母、数字或下划线 |
| `MYSQL_SSL` / `MYSQL_SSL_CA` | `false` / — | 启用证书验证的 TLS；可选 CA 文件绝对路径 |

例如，在 macOS / Linux 下使用独立学习库：

```bash
DB_PATH=runtime/personal.sqlite npm run dev
```

启动入口读取进程环境变量，支持 PM2 面板或 ecosystem 配置；项目根目录 `.env` 为可选补充，已有进程环境变量优先。可以复制 `.env.example` 为 `.env`，填写数据库信息后运行 `npm run dev` 或 `npm start`。`.env` 已排除 Git 与部署包。

服务器使用已有 MySQL 时，设置 `DB_DRIVER=mysql` 并填写 `MYSQL_*`。应用自动在指定库中创建账号、会话和个人学习表，不创建数据库；账号需要该库的建表、查询、插入、更新、删除权限。连接失败会终止启动，不会悄悄切回 SQLite。配置示例、TLS 和迁移步骤见 [MySQL 部署配置](docs/服务器部署.md#mysql-数据库配置)。

## AI 评阅、出题与模拟面试

AI 由管理员统一配置，用户无需填写 Key，也无需打开个人 AI 开关。在主观题填写回答后可点击 **AI 评阅我的回答**；知识点和题目下可点击 **举一反三** 生成 1–3 道个人场景题。生成题可继续作答、收藏、记笔记及复习，明确标注 AI 来源；内容仍需结合课程复核。

**AI 学习与历史** 提供调用记录、关联题目/知识点、资源流水和可恢复的文字面试。练习模式逐轮点评，面试模式结束后展示评价；每场 2–10 个主题，每主题最多追问一次。任务在后端运行，离开页面后可从历史查看。主观题有效评阅保留 AI 评分来源并安排复习，接口错误和无效模型结果不会记成用户答错。

首次启用步骤：

1. 在服务器生成一次 32 字节加密密钥，将结果配置为 PM2 环境变量 `AI_ENCRYPTION_KEY`（或写入可选 `.env`），重启后端。密钥只放服务器，保持稳定并单独备份。

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

2. 先注册并登录，在 `/profile` 个人中心复制 8 位用户 ID，再在同一账号数据库下指定管理员。下列 `12345678` 必须替换为自己的实际 ID：

   ```bash
   # 源码开发目录
   npm run admin -- promote --id 12345678
   # 服务器编译产物目录 /www/wwwroot/knowforge
   node server/admin.mjs promote --id 12345678
   ```

   使用 PM2 配置数据库且没有 `.env` 时，终端命令不会自动继承应用环境。先用 `pm2 list` 找到进程名或 pm_id，再执行：

   ```bash
   node server/admin.mjs promote --id 12345678 --pm2 knowforge
   ```

   将 `knowforge` 替换为真实 PM2 进程名或数字 ID，并使用相同的系统用户和 `PM2_HOME`。命令只读取该进程的数据库配置，不输出凭据、不重启应用。缺少数据库配置或指定 SQLite 文件不存在时会停止，不会误建空库。

   `demote --id 12345678` 可撤销管理员身份，`--id` 也兼容内部 UUID。原登录账号方式继续支持，可明确写 `promote --username 登录账号`；8 位纯数字的登录账号需使用 `--username`，避免与用户 ID 混淆。公开注册不能指定角色；管理员身份从后端校验，刷新页面生效。

3. 管理员进入 `/admin` →“服务与模型”，添加一个或多个服务商，各自配置 Base URL、Key、协议，再给每个服务商添加多个模型。先保存连接，再读取该服务商的 models；未提供列表的服务可手填模型 ID。每个模型可选择评阅、出题、面试用途，设置启停、优先级、权重与最大并发。支持 OpenAI 兼容 Chat Completions 和 Responses，模型可分别选择输出格式及 Chat 的输出上限参数。
4. 在“用户与额度”搜索用户，可配置免费资格、赠送/补偿额度，或按已发布资源包发放。新账号初始额度为 **0**；免费资格生效时无需个人余额。模型下的“测试此模型”归平台调试，记录 Token 与预计成本，不扣管理员个人额度。

服务商 Key 使用 AES-256-GCM 加密，模型调用仅发生在 Node 后端；前端构建变量与普通备份不包含凭据。服务商地址必须使用 HTTPS、公网地址；DNS 校验后固定连接 IP，不跟随重定向。管理界面不支持内网模型地址。

用户只能调用评阅、关联出题和当前面试轮次三个业务入口，不能传入自定义 system/messages、服务地址或模型。AI 回答限制 10–3000 字符，请求体 24KB，完整上下文有字节预算；每用户同时一个任务、全站同时三个任务，IP 请求频率与用户/题目/全站近 24 小时次数限制共同生效。服务池默认每任务最多尝试 3 个不同的模型目标，单次超时 25 秒、总超时 80 秒，后台可调整（总超时最高 90 秒）；响应上限 1MB，并限制输出 Token。Prompt 把回答作为不可信数据处理，但不承诺完全消除提示注入，成本仍由后端硬限制约束。

AI 额度采用固定精度整数计量，内部 1 额度 = 1,000,000 微额度，API 使用十进制字符串，避免浮点误差和每次调用整点进位。普通调用开始前按批次预占，完整结果校验并持久化后立即按真实用量及费率快照结算，释放差额；缓存输入与推理输出不重复加总。自动切换只对最终有效结果结算一次，所有失败尝试的上游消耗单独保留。技术失败、拒答和无效结果不扣用户额度；用户答错或获得零分但评阅有效，仍属正常服务。

有效结果缺少 usage 时，执行状态为成功、用户结算独立待核对，作答及复习记录正常保存。付费模式保留预占并暂停新的付费调用，管理员可按依据结算；默认 24 小时仍未核对则释放预占，上游成本继续留档。免费用户不冻结个人额度。未知用量不伪装成零 Token，结算不超过当次预占，超出部分作为平台异常成本处理。

调用历史按用户隔离，记录实际请求消息、回答、可见模型回复、题目/评分快照、模型、耗时、Token、额度与异常状态；普通用户只能查看自己的记录，管理员可查看明细。后台任务中断后，通过租约检查进入核对流程，不自动重复调用；个人预占受核对期限约束。**本版没有支付或购买入口**，管理员发放额度使用独立流水；后续资源包购买可通过唯一订单号接入额度发放，复用现有预占与结算链路。

### 多服务商调度与恢复

- 先选优先级数值最小的健康模型；同级模型按当前并发和权重分配。高优先级模型故障、冷却或并发占满时使用备用模型。权重作用于模型目标，多个服务商可同时承担流量。
- 网络异常、超时、5xx 会暂时隔离服务商；429 限流遵循 `Retry-After`，无法区分时默认冷却 60 秒。已识别余额/总额度不足冷却至少 1 小时；401/403 暂停到管理员修正 Key/权限并恢复。400/404 等模型或参数不兼容仅暂停该模型；无效结构化输出暂时隔离模型。连续失败逐步延长冷却，最长 24 小时。
- 冷却结束后由后续业务请求放行一次恢复探测，成功重新参与调度。没有后台定时付费探测。健康状态保存在数据库，重启不会清除冷却。取消请求和模型拒答不继续切换。
- 每个逻辑任务最多预占、结算各一次；每次上游尝试独立记录服务商、模型、耗时、请求 ID、错误、请求参数、回复与 Token 明细。超时后的失败尝试可能已产生费用，成功切换后这些费用不再向用户叠加，后台保留“上游成本待核对”并允许记录核对依据。该核对与用户预占结算互相独立。
- 上游全部不可用时返回明确错误。未交付有效结果会释放用户预占，未知上游消耗由平台继续核对。用户提交的答案不会通过无限重试消耗资源。

管理员应至少配置两个独立可用服务商并分别测试；同一个上游账号的多个域名可能共享额度，不能提供真正独立的容灾。当前仅支持单实例 Node，调度中的并发计数保存在该实例内，不支持 PM2 cluster 或多副本共同调度。旧版单服务商配置会在启动时迁移，原有账号、学习记录和流水保留。

## 个人中心与用户 ID

登录后点击右上角名称或侧栏“个人中心”，进入 `/profile`。可复制固定的随机 8 位数字用户 ID、查看登录账号和注册时间、修改显示名称及密码。显示名称支持 1–40 个字符，登录账号保持不变。修改密码须提供当前密码，新密码为 8–128 位；成功后轮换当前会话和 CSRF，注销其他设备会话，当前设备保持登录。没有自助找回密码入口。

8 位 ID 由密码学随机数生成，数据库唯一约束和碰撞重试保证唯一；它不表示注册顺序，也不承担权限验证。内部仍使用原随机 UUID 关联学习记录、额度及会话。旧账号首次认证或管理查询时自动补齐公开 ID，已有学习数据保持关联，无需手工迁移。后台用户列表支持按 ID、登录账号或显示名称搜索。

### 免费资格、资源包与批次额度

后台固定入口 `/admin`：

- **用户与额度**：按账号、昵称或 8 位用户 ID 搜索。设置普通/免费模式、免费天数或永久资格、个人日预算；赠送或补偿额度，指定有效期，或按已发布商品版本发放。免费资格独立于余额，仍受封禁、频率、输入输出和预算限制，变更只影响新调用。
- **资源包与预算**：配置商品编码、人民币售价、基础/附赠额度、有效期、简介和排序。先存草稿，再发布不可变版本；下架不影响既有批次。发布提示同有效期商品的单位价格倒挂和重复购买单一小包的覆盖价格，不做所有组合的穷举定价证明。
- **定价测算**：输入上游原价、采购折扣及客户扣费额度，比较各档资源包的用户实际价格、模型毛利和保本费率。可保存独立测算方案，具体口径见下文。
- **调用与核对**：查看应扣、实扣、豁免、Token、批次结算、失败重试和采购成本。可核对未知用户费用、冲正已扣款，以及记录实际上游账单金额。冲正只执行一次，返回原批次；原批次已过期则进入过期记录。
- **服务与模型**：每个模型可选填折算人民币后的每百万输入/缓存/输出 Token 采购价。该价格用于预计成本，独立于用户费率；实际账单金额由管理员核对，不能用资源包售价推算真实采购成本。

每次发放形成独立权益批次，按“最近到期 → 最早发放 → 批次 ID”使用，永久权益排在最后。可跨批次预占和扣费，但用户只看到一笔逻辑结算，展开查看分摊。有效期在查询和预占时实时检查；到期中的预占可核销，释放部分不会重新延长有效期。已有余额懒迁移为永久历史批次，原预占按旧调用绑定，不重复发放；原流水通过“升级前流水”查看。

用户在 **AI 学习与历史 → 我的额度与流水** 查看有效可用、预占、七天内到期、净消费及每个批次的来源和有效期。该页同时展示当前公开 Token 费率和个人预算，历史调用按启动时的费率快照执行；用户接口不返回服务商采购价、密钥或资源包内部修改说明。

默认单次预算 **90 额度**、每用户近 24 小时预算 **1000 额度**、未知用量核对期 **24 小时**，可在后台调整。失败及免扣调用也计入反滥用预算；用户级预算可覆盖默认值。资源包售价只是商品配置，**本版未接入在线支付、自动购买或人民币退款**，后台按模板发放属于赠送，不生成付款记录。后续支付应基于订单商品快照发放权益，不能由前端传入可信售价或发放数量。

### 定价测算

管理员进入 **管理后台 → 定价测算**（`/admin?tab=pricing`），点击“编辑测算参数”。PC 使用居中弹窗，手机与触屏 iPad 使用底部 sheet。输入普通输入／缓存输入／输出的原价（**人民币元／百万 Token**）、采购倍率、客户费率（**额度／千 Token**）及一组典型用量；采购倍率 `0.15` 表示支付原价的 15%，不是减免 15%。可选填额外模型成本比例，模拟失败重试等开销。

页面自动读取资源包，可以比较已上架的已发布价格或全部草稿，按以下口径显示：

- 每额度价格＝资源包售价 ÷（基础额度＋赠送额度）；用户每百万 Token 单价＝每千 Token 扣费额度 × 1000 × 每额度价格。
- 采购成本＝原价 × 采购倍率；毛利＝用户收费－模型成本；毛利率＝毛利 ÷ 用户收费，同时显示用户价相对原价的比例、相对采购成本的倍数及保本额度。
- 可按样例比例、纯普通输入、纯输出及启用后的纯缓存输入查看整包用完的成本与毛利。缓存命中是总输入的子集，不重复收费；赠送额度计入分母，负毛利保留显示，零收入不计算毛利率。
- 单次消耗按正式账本精度向上取整到百万分之一额度，其他计算使用精确分数，展示时再舍入。整包次数按同等用量理论折算，不保证最后余量足够再调用一次。毛利不含服务器、税费、支付手续费等运营费用，不计额度过期收益；手填原价不自动代表官方报价。

提供截图人民币价格 `5／30`、采购倍率 `0.15` 与试算费率 `0.125／0.75` 的快捷示例，也可单独载入当前正式费率。试算允许最多六位小数，**保存测算不会修改正式费率、模型采购价、资源包或用户余额**；实际收费仍由“服务与模型”中的正式配置决定。当前正式费率仅接受每千 Token 1～1000 的整数额度，试算值不符合时页面会提示；本次不改变正式收费规则。

“更新测算结果”只更新本页；“保存测算方案”将当前方案保存在后端既有 `ai_config` 中，其他管理员可以继续查看，覆盖时检查版本冲突并记录审计。仅保留一份当前方案。该接口要求管理员权限和写入 CSRF 校验，普通用户、个人备份和公开数据不返回采购假设；测算不调用 AI。上线时更新前后端即可，无需执行 SQL 或增加环境变量。

## 学习数据与备份

AI 历史、个人生成题、管理配置和资源流水保存在数据库中，需要通过数据库备份保留；加密主密钥单独备份。个人 JSON 仍只备份学习状态，其中生成题相关记录仅能合并回仍拥有这些题目的原账号。JSON 导入不能创建 AI 生成题、恢复额度或修改调用账本，避免通过伪造题目绕过 AI 用途限制。

进度、笔记、收藏、作答、复习、计划和模拟记录统一保存在所选数据库。MySQL 模式使用 `MYSQL_DATABASE` 中的 `knowforge_*` 表；默认 SQLite 模式使用 **`runtime/study.sqlite`**。应用关闭后数据保留，`runtime/` 中的数据库文件已排除 Git。

公开注册后，每个账号从空白记录开始。升级前的共享记录不会自动归属任何注册用户；旧共享表不再通过学习接口访问。

同一套账号数据库下，用相同账号在不同设备登录可访问自己的进度和已提交记录。切换数据库不会自动复制账号或记录；需要保留某份学习状态时，可先登录原账号导出个人 JSON 备份，在目标库注册并登录账号后导入。

在“资料来源与数据”页面可以导出：

- **完整资料 JSON**：知识点、问答、答案、实验、用例与来源。
- **Markdown 学习手册**：适合离线阅读的完整学习内容。
- **个人 JSON 备份**：学习状态与已提交的练习记录，支持预览后合并导入。

**未提交的代码草稿保存在当前浏览器的 localStorage 中，不包含在个人 JSON 备份里。** 重要草稿请单独另存。直接复制 SQLite 文件前应先停止服务，避免遗漏尚未合并的 WAL 数据。

代码草稿按站点来源和账号 ID 隔离，同一浏览器切换账号也不会混用草稿。旧版未分账号的草稿不再自动读取；草稿不在设备间同步。

## Python 配套项目

[examples/python/workbench.py](examples/python/workbench.py) 是一个只依赖 Python 3.11+ 标准库的独立练习项目，串联本机样本站点、robots、分页采集、HTML 解析、SQLite 幂等存储与 REST API。

运行完整演示：

```bash
python3 examples/python/workbench.py demo
```

分别启动服务与采集器：

```bash
# 终端一：启动本机样本站点与 API
python3 examples/python/workbench.py serve --port 8765

# 终端二：采集样本页面并写入独立数据库
python3 examples/python/workbench.py crawl --base http://127.0.0.1:8765
```

示例端点：

- `GET /api/articles?page=1&limit=2`
- `GET /api/search?q=python`

配套项目默认使用 `runtime/python-demo.sqlite`，与个人学习库分离。搜索接口返回带来源的确定性检索结果，`answer` 为 `null`；接入真实大模型需要另行实现模型适配与评估。

## 技术栈与目录

| 层级 | 技术 |
| --- | --- |
| 页面与路由 | Vue 3、Vue Router、Vite |
| 编辑与展示 | CodeMirror 6、Prettier、Marked、DOMPurify、Highlight.js |
| 服务与存储 | Node.js、Express 5、MySQL / 内置 SQLite、Zod |

```text
knowforge/
├── client/                   Vue 页面、组件与浏览器代码运行器
├── server/                   API、判分、备份、MySQL / SQLite 与服务入口
├── shared/                   前后端共用的输出比较规则
├── data/
│   ├── content/              可维护的课程、示例、练习与来源
│   ├── catalog.json          生成的完整学习数据
│   └── original-handbook.txt 原始参考材料
├── examples/python/          独立 Python 全链路练习
├── scripts/                  数据生成与完整性检查
├── tests/                    API、示例、实验与 Python 集成测试
├── docs/                     完整手册、数据结构、覆盖说明与验收记录
├── runtime/                  本地数据库，忽略提交
├── dist/                     前端构建产物，忽略提交
├── nodemon.json              后端监听范围
└── vite.config.mjs           前端构建与开发配置
```

开发时 Vite 作为前端 Express 服务的中间件运行，HMR 使用前端端口；`server/frontend.mjs` 将 API 和 Worker 资源流式代理到后端，并保留浏览器 Host，使写入校验和 Python Worker CSP 保持同源。nodemon 仅监听 `server/`、`shared/` 和 `data/catalog.json`；前端改动由 Vite 处理，数据库、构建产物和 Vite 临时文件不会触发后端重启。

## 开发与扩展

### 添加或修改资料

1. 编辑 `data/content/` 中的结构化内容源；Python、爬虫、REST 和 AI 基础内容位于 `data/content/expansion/`。新增深度正文、运行代码、迁移题和算法位于 `data/content/v3/`；`entries.json` 保存元信息，`lessons/` 保存正文，`code/` 保存确定性实验。
2. 为知识点补充讲解、来源、示例、预期输出、练习与参考答案，并保留明确的输入输出契约。
3. 生成资料并检查数据关系：

```bash
npm run build:data
npm run check:data
```

`build:data` 会同时生成 `data/catalog.json` 与 `docs/完整学习手册.md`。请修改内容源，直接修改生成文件的结果会在下次生成时被覆盖。新增或调整内容 ID 前应考虑已有学习记录的关联。

### 验证

```bash
npm test
npm run build
```

测试涵盖 API 判分、持久化、备份合并、模拟作答、输出比较、课程示例、补全参考解、实验用例和 Python 配套项目。完整测试需要 `python3` 命令指向 Python 3.11+；测试使用独立数据库或临时目录。

MySQL 集成测试单独运行 `npm run test:mysql`，需通过环境变量提供测试库的 `MYSQL_*` 连接信息；每项测试创建并清理随机前缀表。Actions 手动打包时会自动运行隔离 MySQL 测试，不使用生产凭据。

贡献内容时，请同时说明示例适用范围和参考依据，为参考实现提供边界用例，并运行相关检查。UI、Worker 与平台兼容性还需要实际浏览器验证。

## 使用范围与资料说明

KnowForge 支持公开注册和个人学习记录隔离。账号为 3–32 位字母、数字、下划线或短横线，不区分大小写；密码为 8–128 位。登录会话有效期 7 天，退出会立即注销当前会话。当前没有邮箱验证或自助密码找回，请妥善保管密码。管理员由服务器命令指定。数据库请求在单个 Node 进程内串行处理，部署使用单实例，不启用 PM2 cluster 或多副本；AI 外部调用在数据库会话之外执行。代码在浏览器 Worker 中运行，支持取消和超时，但没有严格内存配额；学习运行器不承担防作弊在线评测职责，也不能直接执行 Vue SFC、DOM 或 Node.js 模块。

资料用于学习和练习，不代表腾讯或其他机构的官方题库、招聘流程或命中率承诺。涉及平台行为时，应以目标版本的官方文档和实际环境为准。

### Python 运行环境排查

前后端分域部署时，Python Worker 与 `/python-runtime/` 都由 API 域名提供。前端从 OSS 加载页面，再通过 API 的隔离运行器启动 Worker。首次加载较慢时可展开环境准备窗口里的“加载日志”，查看文件名、HTTP/MIME 错误和初始化阶段，并复制排查；等待过程中可以停止。进度条表示已就绪资源数量，初始化阶段不估造百分比。

1. 检查 `https://knowforge-api.ookew.com/python-runtime/manifest.json` 返回 JSON，不能返回站点首页；该清单使用 `Cache-Control: no-store`。
2. 按清单 `base` 检查 `pyodide.js`、`pyodide.asm.mjs`、`pyodide.asm.wasm`、`python_stdlib.zip` 和 `pyodide-lock.json` 都返回 200；WASM 类型必须是 `application/wasm`。
3. 运行资源使用版本路径与长期缓存，避免不同版本混用。资源缺失返回明确 404；错误会包含资源名、HTTP 状态或 MIME 原因。
4. 发布这次更新需要分别运行前端、后端两个部署 Actions。只更新 OSS 不能更新后端运行资源清单和 Worker；不要把 API 的资源路径转发成前端 SPA 页面。

框架概念与 API 示例参考 [Microsoft Agent Framework](https://learn.microsoft.com/en-us/agent-framework/overview/)、[LangGraph](https://docs.langchain.com/oss/python/langgraph/overview)、[OpenAI Agents SDK](https://developers.openai.com/api/docs/guides/agents/sdk) 等官方资料，核对日期为 2026-10-23。升级框架时仍需按目标版本复核示例。
