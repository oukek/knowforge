## 从具体问题认识动态规划进阶

背包问题用有限容量约束选择：物品有重量和价值，希望在容量内获得最大价值。0/1 背包每件最多选一次，完全背包允许同类物品重复选。两者题面相似，但压缩成一维数组后的循环方向不同。

容量为 4，只有一件重量 2、价值 3 的物品，0/1 背包答案应为 3；如果程序得到 6，就说明同一件物品被重复使用了。

## 循环方向其实决定读取哪一层状态

二维 0/1 状态可定义 dp[i][c] 为只考虑前 i 件物品、容量不超过 c 的最大价值。选第 i 件时读取上一层 dp[i-1][c-w]+v，不选读取 dp[i-1][c]。压缩为一维后必须从大容量向小容量更新，保证 c-w 仍保存上一层，而不是本轮已包含当前物品的新值。

完全背包允许重复使用当前物品，所以可以从小容量向大容量更新，读取本轮已经更新的 c-w。组合计数与排列计数又是另一层区别：外层枚举物品、内层递增金额通常按物品类型组织组合；外层枚举金额、内层枚举最后一项则会区分不同顺序。具体初始化仍取决于是否要求恰好装满。

字符串与区间 DP 同样需要依赖方向。编辑距离依赖左、上与左上，压缩时需保存被覆盖的旧对角值；区间 DP 常按区间长度递增，因为大区间依赖更短区间。循环不是为了让代码跑完，而是为了满足状态依赖的先后。

## 背包先区分每项能用几次

0/1 背包的每个物品最多使用一次，二维状态 dp[i][c] 表示前 i 项、预算不超过 c 的最大值。选当前物品时必须接 dp[i-1][c-w]。压成一维后预算逆序，让被读取的 dp[c-w] 仍属于上一轮。若正序，当前物品的结果可能立即再次被利用，语义就变成可重复使用。

## 一个物品即可看出循环方向

只有重量 2、价值 3 的一项，容量 4。正确 0/1 答案是 3。正序更新 c=2 得 3，之后 c=4 又从刚更新的 dp[2] 加 3 得 6，等于用两遍同一项。这个反例比大样例更能解释机制。完全背包恰恰允许重用，所以容量正序是有意的选择，不是普遍错误。

## 组合数量与排列数量不同

面额 [1,2] 凑 3，组合有 [1,1,1] 和 [1,2] 共两种；按顺序区分的排列还包括 [2,1] 共三种。面额外层、金额正序，每个组合在处理最后一种面额时计一次；若金额外层枚举最后一枚面额，顺序会被计入。dp[0]=1 代表空组合，不能用最小硬币数的 Infinity 初始化方法代替。

## 网格与字符串状态的差别

有障碍网格计数依赖上方和左方，障碍处必须清零。LCS 处理两个前缀：字符相等走对角+1，否则取上或左，子序列可不连续；最长公共子串在不等时清零，这是不同题。最长回文子序列处理区间：两端相等接内部+2，否则舍弃一端，单字符为 1。先写完整二维关系，再决定滚动缓存与遍历方向。

## 压缩必须保存将被覆盖的旧值

一维 LPS 从 i=n-1 递减，j=i+1 递增，dp[j] 更新前表示下一行，dp[j-1] 表示当前行，左下角需单独 diagonal 保存。每次先保存旧 dp[j]，算新值，再更新 diagonal。背诵“倒序可以压缩”不足以确定两个维度的顺序，必须指明每个读取值属于哪一轮。

## 训练顺序和正确性依据

先做 0/1 预算最大价值、等和分割，再做硬币最少枚数与组合数，最后做股票、LCS、回文子序列和状态压缩巡检。为每题写出状态、候选选择、基例、依赖顺序、最终答案与复杂度。对背包用子集枚举，对组合数按每种硬币使用次数枚举，对字符串枚举小串子序列；不同基线能暴露循环方向和覆盖旧状态的错误。大规模测试检查资源上界，但仍需你解释推导。

## 把机制放到一条完整路径中

```flow
背包状态压缩
明确使用次数｜每件一次还是可重复
写二维转移｜标出读取上一层或当前层
安排循环｜按依赖选择升序或降序
最小反例｜检查同一物品是否被误用
```

## 配套代码：动态规划进阶：背包循环、序列与区间依赖 · 手推后运行

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

先预测输出，再修改一处输入，检查你的状态与不变量解释是否成立。

```javascript
function pack(descending){const dp=Array(5).fill(0);if(descending){for(let c=4;c>=2;c--)dp[c]=Math.max(dp[c],dp[c-2]+3);}else{for(let c=2;c<=4;c++)dp[c]=Math.max(dp[c],dp[c-2]+3);}return dp;}
console.log(pack(true));
console.log(pack(false));
const coins=[1,2],dp=[1,0,0,0];for(const c of coins)for(let s=c;s<=3;s++)dp[s]+=dp[s-c];
console.log(dp[3]);
```

比较两段循环的容量方向，观察同一轮更新是否读取了刚写入的位置。逆序会保留上一轮状态，正序允许本轮结果再次参与，因此一个物品可能被用多次。先用单物品容量两倍的小反例验证，再扩展到多物品。

## 从示例走向实际使用

先写二维状态与转移，画出依赖箭头，再决定能否压缩。若只记“背包倒序”而不知道为什么，遇到完全背包或计数变体就容易套错。

用一件物品就能验证循环方向，使用最小反例比大规模随机数据更直观。再测试容量零、物品过重、恰好装满不可达和重复面值的题意。
