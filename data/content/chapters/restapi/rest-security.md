## 从具体问题认识API 安全

API 安全关注不可信输入如何影响数据、权限和系统资源。常见问题包括对象级越权、批量赋值、SQL 注入、SSRF 与不安全上传。它们不都能靠一个统一“过滤特殊字符”函数解决，因为每种风险发生在不同边界。

例如更改 URL 中的订单 ID 能看到别人的订单，是授权缺失；把用户输入拼进 SQL 改变查询结构，是注入。前者即使全部使用参数化查询也仍然存在。

## 按信任边界选择控制措施

数据库值使用绑定参数，动态列名与排序方向使用白名单。资源查询包含经过验证的用户或租户作用域，写入字段由允许列表构造。认证、结构校验和授权分别实施，避免某一层通过就跳过其他层。

服务端代用户请求 URL 时，需限制协议、目的地址、重定向与网络出口，防止访问内部服务。只检查字符串前缀无法处理 DNS、地址表示与跳转变化。上传则要限制大小、类型、文件名与存储位置，必要时隔离处理；用户提供的 MIME 或扩展名都不能独自证明内容安全。

资源耗尽也是安全问题。超大分页、复杂正则、无限并发和无界解压都可能消耗 CPU 或内存。限流、超时、队列容量和请求体限制应靠近入口生效。日志记录请求关联与错误类别，避免把凭证和敏感正文变成另一个泄露通道。

## 把机制放到一条完整路径中

```flow
API 信任边界
识别入口｜参数正文文件URL与凭证
限制解释｜结构白名单与参数化访问
校验权限｜对具体资源与操作授权
控制资源｜限额隔离超时并记录审计
```

## 配套代码：API 安全：越权、注入、SSRF 与上传：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

allowed_fields={'title','summary'}
request={'title':'A','is_admin':True}
unknown=set(request)-allowed_fields
show(sorted(unknown))
show(not unknown)
```

示例只验证未知字段检测，没有实现 SSRF、上传扫描或身份授权。安全边界应对应实际能力，并在服务器和网络出口执行；单个纯函数示例用于理解一项约束，不应被当作完整安全方案。

## 从示例走向实际使用

围绕实际接口建立威胁用例：替换资源 ID、提交不可写字段、超大输入、重定向到内部地址与伪装文件类型。验证拒绝发生在产生副作用之前。

课内未知字段检测只覆盖批量赋值边界的一部分，不能把它当成通用安全验证器。每类输入都应结合最终使用位置选择措施。
