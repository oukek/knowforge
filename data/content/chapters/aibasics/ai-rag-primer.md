## 从具体问题认识RAG 是什么

RAG 是检索增强生成：先从外部资料中找出与问题相关的内容，再让模型依据这些内容组织回答。它适合需要私有、更新频繁或可追溯知识的任务，但不会自动保证资料正确或回答有据。

例如用户问公司的报销期限，系统先找到适用部门与当前版本政策，再生成解释。模型参数不必为了每次政策更新重新训练，但资料更新与权限过滤必须可靠。

## 入库链与问答链分开理解

离线或后台入库链负责取得文档、解析结构、切分片段、保存元数据并建立索引。在线问答链负责理解查询、检索候选、过滤与重排、组织上下文、生成回答和验证引用。两条链任一环节出错，都可能表现为“回答不好”。

检索可以使用关键词、向量或混合方式，不等于必须先买向量数据库。切分需要保留标题、来源、版本和权限，避免片段脱离条件。重排帮助从候选中挑更相关材料，但无法从完全没有召回的文档中凭空找到答案。

生成阶段应明确只依据哪些证据回答，缺资料时如何说明。引用要指向具体支持内容，不只是附一个看起来相关的网页。RAG 与微调解决不同问题：检索提供运行时事实，微调主要改变行为与任务适配；两者可以组合，但不应互相替代。

## Retrieval-Augmented Generation 的意思

**RAG 的两条流水线分别负责准备资料和回答问题。** 准备阶段将文档解析、切分、建立可检索索引；回答阶段接收问题，筛选用户有权访问的相关片段，再把片段提供给模型组织回答。

例如公司政策更新后，重新处理对应文档及索引，之后的提问才能检索到新版本。模型不会因为一次阅读就永久记住这份政策；若没有找到可靠证据，应允许回答无法确认，而不是靠生成补全事实。

例如检索结果没有提到试用期能否休假，答案应说明证据不足，而不是根据相似公司政策推断。

RAG 是 Retrieval-Augmented Generation，检索增强生成：在生成之前或过程中找出相关外部信息，把证据放进模型可用上下文，再组织回答。它通常不修改模型参数，知识更新主要发生在文档与索引。不是把文档传过一次，模型就永久学会。

它适合有可检索知识、需要更新或追溯来源的任务。没有可靠资料时，RAG 不能凭空制造真相；精确库存与订单状态通常更适合结构化查询。检索文档仍需权限与时效控制。

## 离线与在线两条链路

离线：获取文档 → 解析清洗 → 分块 → embedding/关键词索引 → 元数据和版本入库。在线：理解查询 → 权限过滤 → 召回 → 融合/重排 → 选择证据 → 生成 → 主张与引用校验。两条链路分别观测，索引阶段丢失的信息很难靠生成补救。

| 环节 | 核心问题 | 常见坏例 |
|---|---|---|
| 分块 | 条件和结论能否一起看到 | 表头与数字拆开 |
| 召回 | 正确证据是否进入候选 | 产品编号匹配失败 |
| 上下文 | 预算内保留什么 | 关键条款被截断 |
| 生成 | 是否忠于证据 | 忽略“仅企业版” |

提高 top-k 不一定改善最终正确率，噪声和预算挤占也可能增加。

## 与搜索、微调、Agent 的关系

搜索可以直接返回文档列表；RAG 增加按证据组织答案。微调改参数行为，RAG 提供运行时事实，两者可组合。Agent 可决定是否检索和下一步行动，但普通 RAG 问答不一定需要 Agent 循环。

向量数据库是可选的检索基础设施，不等于 RAG 本身；小知识集可以先用简单可验证检索。关键是任务、证据和评估，不是堆工具数量。

## 怎样从最小系统走向可靠系统

先建立固定语料和问题集，包含有答案、无答案、冲突、权限和更新，分别记录召回与答案支持。逐步加入混合检索、重排和查询改写，并做消融比较；不要同时改十个变量后无法解释收益。

面试讲项目要说明语料规模与类型、分块依据、embedding 版本、权限、评估、延迟与坏例。没测过的指标如实说明，并给出补测方案，不编造“召回率 99%”。

## 把机制放到一条完整路径中

```flow
RAG 两条链
文档入库｜解析切分版本与权限元数据
查询检索｜获得相关候选并过滤重排
证据组织｜保留条件来源与冲突信息
有据生成｜回答并检查引用支持与缺口
```

## 配套代码：RAG 是什么：检索增强生成的两条流水线

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。



```javascript
const docs = [
  { id: "refund", version: 2, terms: ["退货", "订单"] },
  { id: "shipping", version: 1, terms: ["物流", "配送"] },
];
function retrieve(terms) {
  return docs
    .map((d) => ({
      ...d,
      score: d.terms.filter((t) => terms.includes(t)).length,
    }))
    .filter((d) => d.score > 0)
    .sort((a, b) => b.score - a.score)
    .map((d) => ({ id: d.id, version: d.version }));
}
console.log(retrieve(["订单", "退货"]));
console.log(retrieve(["天气"]));
```

这是词项重合教学检索，没有真实模型和向量库。无匹配返回空集；检索成功仍不代表证据支持全部答案。

## 从示例走向实际使用

先用十几篇允许使用的文档和人工标注问题建立最小系统，逐步检查答案文档是否入库、是否召回、是否进入上下文和是否被正确使用。

课内词项检索实验展示最小链路，不使用真实 embedding，也不代表完整 RAG 质量。它有助于先理解资料与回答之间的关系，再引入更复杂检索。
