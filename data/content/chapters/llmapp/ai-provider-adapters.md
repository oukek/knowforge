## 从具体问题认识多服务商协议适配

不同服务商即使声称兼容同一种 API，也可能在流事件、工具参数、错误码、使用量和输出限制上有差异。业务要的是稳定的任务语义，而不是所有响应长得相似。适配层的工作是把差异显式表达出来。

例如服务 A 在末尾返回 usage，服务 B 需要另查账单；如果统一成“没有 usage 就是零”，故障会直接变成计费错误。

## 协议映射不能抹掉能力差异

内部请求使用业务概念，如消息、工具、输出约束、时间预算和取消信号；每个适配器再映射到上游协议。能力矩阵声明哪些契约真正被支持，不满足的候选在发起请求前排除，避免静默删参数。

流处理先解码字节和协议帧，再按文本、工具参数、完成状态和计量事件归一。多个工具同时生成时按调用 ID 聚合；网络包、文本行和 JSON 对象边界没有必然对应关系。

错误分成用户输入、能力不支持、认证配置、配额限制、暂时故障和结果未知。只有符合策略的类别才重试或切换，并沿用任务总预算。原始错误保存脱敏诊断信息，不把密钥或整个请求头直接返回前端。

## 协议相似不等于语义一致

OpenAI 兼容端点、Responses 风格事件、Claude Messages 等可以有不同的消息结构、system 位置、工具参数、结束原因、用量字段与流式生命周期。同一模型经中转服务也可能缺字段。不能只替换 baseURL 就宣称适配完成，应按供应商与 API 版本建立适配器并做真实契约验证。

## 内部领域模型与能力矩阵

应用先定义与厂商无关的 Request：任务类型、消息块、工具定义、输出约束、预算和取消信号。Response 统一为文本块、工具提议、结束原因、用量与来源元数据；多模态和推理过程只保留有文档且获准的内容。Capability 声明支持的输入类型、工具并行、结构化输出与流式用量，不支持的能力在调用前拒绝或显式降级。

不要为了统一而丢弃语义。例如“token 达上限”“正常完成”“等待工具执行”必须分开；模型标识应包含供应商、端点与版本，不能只用一个短模型名做缓存和计费键。工具调用 ID 要稳定映射，工具结果必须能配回原始调用。

## 流不是逐行 JSON

网络 chunk 可能切断 UTF-8 字符、SSE 行和工具参数 JSON。先增量解码，再按协议拼事件；文本 delta 可逐步显示，工具参数必须按调用 ID 拼接到对应终止事件，再解析和校验 schema。不能收到半个参数就执行，也不能把某家结束标记写死为所有服务商约定。

下方示例用自定义规范化事件演示参数拼装，不是某家真实 SDK。真实 adapter 的 encode、decode、parseError、usageNormalizer 应有独立文件与固定夹具，并测试空 delta、多工具交错、缺 usage、未知事件、服务端流中错误和网络半断。

## 错误与用量如何归一

HTTP 状态、服务商错误码、Retry-After、请求 ID、已输出内容与副作用状态一起决定是否可重试。鉴权错误、额度耗尽与短期限流不能归为同一种 429。usage 缺失时记录 unknown 或估算来源，不能当作零消耗；缓存 token、输入输出 token 和推理 token 的口径也不能随意相加。

## 安全与可测试边界

密钥只在后端解密使用，端点通过管理员白名单和网络策略避免 SSRF；禁止前端自行提交任意 URL 让后端代请求。日志保留脱敏请求、模型版本、耗时、token 和错误分类，不记录 Authorization。契约测试使用录制并脱敏的响应与 mock，不必每次花钱跑真实模型；上线前再做受控验证。

## 面试中怎样展示工程能力

画出业务层、能力路由、adapter、传输层的边界，并展示一个从工具参数分片到已验证调用的时间线。追问通常落在兼容模式缺字段、模型切换后行为变化和流中失败，答案要说明哪些能力不承诺、哪些错误不重试，避免“统一 SDK 解决一切”的空话。

## 把机制放到一条完整路径中

```flow
供应商适配
检查能力｜确定候选满足任务契约
转换请求｜映射参数并传递预算取消
归一事件｜按身份聚合文本工具和计量
分类结果｜输出明确终态与可诊断错误
```

## 配套代码：多服务商协议适配：能力矩阵与流式事件契约

下面代码在课内JavaScript运行区执行；需要DOM、Node或平台SDK的真实集成，应按正文的运行边界另行验证。

使用本地 JavaScript 模型验证关键不变量；不调用真实数据库、模型或生产服务。实验简化之处与真实系统步骤见正文。

```javascript
const calls = new Map();
function accept(event) {
  if (event.type === 'args') calls.set(event.id,(calls.get(event.id)||'')+event.delta);
  if (event.type === 'end') return JSON.parse(calls.get(event.id));
}
accept({type:'args',id:'t1',delta:'{"city":'});
accept({type:'args',id:'t1',delta:'"广州"}'});
console.log(accept({type:'end',id:'t1'}));
console.log({complete:'stop',limit:'length',tool:'tool_required'}.tool);
```

本段程序用于把状态、条件和数据之间的关系写清；真实实现仍需上文介绍的资源、权限与失败协议。

## 从示例走向实际使用

建立每家服务的契约样本，覆盖正常、拒绝、流截断、工具交错、缺失 usage 和限流。替身验证解析与控制流，少量真实请求验证兼容性，业务集验证质量。
