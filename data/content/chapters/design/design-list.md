## 从具体问题认识系统设计

动态高度虚拟列表只为视口附近的数据创建节点，同时允许每条记录有不同高度。与固定行高不同，滚动距离不能简单除以一个常数得到行号，因为前面每条记录贡献的高度都不同。

例如三行高度为 40、60、50，第二行占据纵向位置 [40,100)，滚动偏移 80 落在第二行。理解这个映射，才能设计可见范围、占位和高度变化后的滚动修正。

## 累计高度、测量与阅读锚点

前缀高度记录前若干行的总高度，例子为 [0,40,100,150]。寻找某个滚动位置对应的行，就是在累计值中寻找包含它的区间，可用二分查找。前缀数组查询快，但某行高度变化后可能需要更新后面所有累计值；频繁动态更新时可评估树状数组等结构。

尚未渲染的行没有真实测量值，只能先用估计高度。进入视口后测量并替换估计，会改变总高度与后续位置。为了避免用户正在读的内容跳动，可以保存锚点记录 ID 及其相对视口偏移，再根据新高度恢复该锚点的位置。

图片、字体和折叠内容都可能在首次渲染后改变高度。测量更新应合并处理，避免读布局与写样式反复交错。节点复用还要按业务 ID 管理输入、选中和请求状态；列表索引随插入删除变化，不能作为所有持久状态的唯一身份。

## 把机制放到一条完整路径中

```flow
动态虚拟列表
估计高度｜为尚未测量的行建立累计位置
定位窗口｜按滚动偏移查找可见范围
渲染测量｜更新真实高度与缓冲区域
锚点补偿｜保持当前阅读内容的相对位置
```

## 配套代码：动态高度前缀和与定位

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

根据已知高度找包含目标偏移的项目；这是列表数据模型，不渲染真实页面。

```javascript
const heights=[40,60,50];
const prefix=[0];
for(const height of heights) prefix.push(prefix.at(-1)+height);
function locate(offset) { return heights.findIndex((height,i)=>offset>=prefix[i]&&offset<prefix[i+1]); }
console.log(prefix);
console.log(locate(80));
console.log(locate(100));
```

80 落在第二项的 [40,100)，100 正好进入第三项。真实大列表可二分查找并维护测量缓存；图片改高、插入和滚动锚点还要独立处理。

## 从示例走向实际使用

从固定高度版本开始验证窗口与占位，再加入动态测量和锚点补偿。测试前方插入记录、图片晚到、快速滚动与筛选切换，观察是否出现空白、跳动和错绑状态。

课内线性查找用于解释位置区间；大规模列表应按实际更新与查询频率选择索引结构。虚拟化只优化视图数量，数据分页和缓存上界仍需另外设计。
