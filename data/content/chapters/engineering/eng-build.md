## 从具体问题认识Vite、Webpack 与开发/生产差异

构建工具把开发时组织的源码转换成目标环境能够加载的产物。源码里可能有 TypeScript、Vue 单文件组件、样式预处理和模块引用，浏览器并不能原样理解所有这些格式。开发服务器负责提供快速反馈，生产构建负责生成可部署、可缓存的文件，两者目标不同。

因此“开发时能打开”并不保证生产部署正确。开发服务器可能替你转换模块、代理 API 并回退路由，静态服务器则只会按配置返回产物文件。

## 模块图、转换与产物生成

入口文件导入其他模块，其他模块继续导入依赖，形成模块图。工具需要解析引用、找到文件、转换语法，再决定如何输出。开发阶段可以按请求转换源模块，并缓存未变化的结果；生产阶段通常还要考虑打包、代码分割、压缩和资源文件名。

Vite 的设计强调利用浏览器模块能力改善开发反馈，Webpack 也通过模块图和缓存等机制完成构建。具体底层工具与默认行为会随大版本演进，不应永远记成某个固定工具组合。选型时应查看项目使用的版本，比较实际插件、兼容目标和构建结果。

环境变量、公共路径和代理是常见差异来源。编译期注入客户端的变量最终属于公开产物，不是秘密存储；开发代理不会自动随静态文件部署到生产。带 hash 的资源文件适合长期缓存，但入口 HTML 需要能及时指向新的文件，旧资源也应保留合理过渡期。

## 把机制放到一条完整路径中

```flow
源码到部署产物
模块解析｜从入口建立依赖关系
格式转换｜处理组件类型与样式
产物优化｜分割压缩并生成资源引用
部署验证｜检查路径缓存与 API 配置
```

## 配套代码：按请求转换与转换缓存的模型

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

模拟开发服务器只转换被请求模块，并缓存结果；不代表具体 Vite 版本底层实现。

```javascript
const cache=new Map(); let transforms=0;
function requestModule(id) {
  if (!cache.has(id)) { transforms++; cache.set(id,'compiled:'+id); }
  return cache.get(id);
}
console.log(requestModule('entry.js'));
requestModule('entry.js');
console.log(transforms);
requestModule('other.js');
console.log(transforms);
```

重复请求命中转换缓存，新模块才增加工作。真实模块图、依赖预处理和生产打包有更多步骤，不能用模型替代实际工具版本和产物测量。

## 从示例走向实际使用

本地验证生产构建时，使用接近部署环境的静态服务访问产物，检查刷新深层路由、API 域名、资源前缀和缓存策略。不要只运行开发服务器作为验收。

优化构建速度先测冷启动、热更新和完整构建各自耗时，识别慢插件或重复转换。一个指标变快，不代表其他指标也同时改善。
