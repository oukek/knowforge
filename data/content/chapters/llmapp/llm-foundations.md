## 从具体问题认识模型、推理、采样与应用系统边界

把模型接入应用前，需要知道一次推理的输入、计算与输出分别是什么。输入包括指令、用户内容和必要上下文，模型计算候选 token 的分数，解码策略选择后续内容。应用再把输出解释成回答、结构化结果或工具提议。

这条链中每一层都有独立错误：资料没传进去、模型理解偏差、输出被截断、解析器拒绝格式或业务校验失败。统称“模型不行”会让排查失去方向。

## 概率输出如何进入确定性业务

logits 是候选的未归一化分数，softmax 把它们转换成总和为一的概率分布。计算时常减去最大值改善数值稳定性，因为指数函数对大数容易溢出；这种平移不会改变归一化后的相对比例。概率描述模型对下一个片段的偏好，而不是业务事实正确率。

模型输出可以有变化，因此应用契约应围绕允许结果与验证条件设计。抽取任务检查字段和来源，代码任务运行测试，金额与权限交给确定性程序。不能期待一次自然语言提示替代数据库约束，也不能把所有随机变化都当系统故障。

部署与模型能力分开记录。模型版本、精度、提示、上下文、采样与工具都会影响结果，同一系列名称不足以复现一次任务。服务层还要处理并发、取消、限额和上游故障，模型本身不会替应用维护用户账本。

## 把机制放到一条完整路径中

```flow
推理进入应用
准备输入｜固定任务规则与事实上下文
模型计算｜产生候选分数与解码输出
结果归一｜识别文本工具拒绝与截断
业务验证｜检查事实权限结构并保存结果
```

## 配套代码：模型、推理、采样与应用系统边界：最小可验证示例

下面复用本课的确定性机制实验，只表达所讨论的局部关系，不等于真实宿主、数据库或模型服务。

使用 Python 标准库和固定样本验证关键机制。show() 把结果序列化成 JSON；可修改输入再运行。

```python
import json

def show(value):
    """按 JSON 打印结果，便于逐行预测和验证。"""
    print(json.dumps(value, ensure_ascii=False, separators=(',', ':')))

import math
logits=[0.0,1.0,2.0]
weights=[math.exp(x-max(logits)) for x in logits]
probabilities=[round(x/sum(weights),3) for x in weights]
show(probabilities)
show(round(sum(probabilities),3))
```

softmax 示例把三个教学 logits 转成概率分布，不是调用语言模型或训练 Transformer。概率高表示在当前分布下更可能生成，不表示该词对应事实一定正确；实际应用还需证据、校验与任务级评估。

## 从示例走向实际使用

先用确定性替身把输入校验、任务状态与结果验证跑通，再接真实模型比较质量。替身通过证明的是应用控制流，不是模型效果。

课内 softmax 实验帮助理解分数变分布。之后调试真实任务时，优先检查可观察输入输出与阶段记录，不推测不可见的内部推理过程。
